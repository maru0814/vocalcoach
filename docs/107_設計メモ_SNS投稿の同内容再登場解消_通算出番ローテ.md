# 107. 設計メモ — SNS投稿の同内容再登場の解消（通算出番ローテ）

- 作成: 2026-08-17 / 担当: グロースオペレーター
- 対象: `scripts/sns_autopost/themes.py` / `generate_and_post.py`
- 依頼: 「ツイートの内容が毎回違うようにしてくれ」（運用者）

## 1. 事象と根本原因

自動投稿の文面が短周期で同じ内容になっていた。原因は次の3つが重なったもの。

1. **選択indexが日付の通し番号だった**
   弾倉（TIPS 等）の選択が `day_index = 日付.toordinal()` の剰余だったため、
   「出番の間隔」と「弾数」が同期する型で毎回同じ弾に当たる。
   実例: contrarian は弾数3で、出番が月夜→木昼→水朝→土朝（3日おき）。
   3日おき mod 3 = 常に同じ index → **同じ文面が週に何度も出る**。
2. **診断導線（self_type / visual）のフックが固定1種だった**
   `template_post()` が固定文字列を返すため、週4回（self_type）出ても毎回同文。
   Gemini リライトも同じ下敷き・同じ指示なので似た文になる。
3. **弾数が週次出番に対して薄い**
   contrarian は週4出番に対し弾3本。ローテ方式を直しても1週間以内に一巡してしまう。

（識別: docs/103 の「パッチワーク禁止」に照らし、個別の弾追加だけで済ませず
選択機構そのものを直す。）

## 2. 対処（1PR・機構1変更＋弾薬補充）

### 2.1 選択機構: 「日付」→「その型の通算出番」（`themes.rotation_index`）

週次スケジュール（PILLARS / PILLARS_2ND / PILLARS_3RD）と日付・スロットから、
その型が **通算何回目の出番か** を決定論的に算出し、それを弾倉の index にする。

- 出番ごとに +1 で進む連番 → **弾倉を順番に一巡してから繰り返す**
  （同内容の再登場間隔が最大化される）。
- 状態ファイル・ログ参照なし。同じ日付・スロットなら dry-run と本番で同じ値
  （承認フローの再生成でもズレない）。
- スケジュール外の手動 `--pillar` や不正 slot は従来どおり日替わり
  （`toordinal()`）にフォールバック。
- 画像（infographic）も同じ index を使うため、本文と図解の内容は同期したまま。

### 2.2 弾薬補充（1週間で一巡しない弾数に）

| 型 | 週次出番 | 弾数（旧→新） | 一巡の周期 |
| --- | --- | --- | --- |
| tip | 5 | 8 → **12** | 約2.4週 |
| contrarian | 4 | 3 → **8** | 2週 |
| voice_type | 4 | 8（据え置き） | 2週 |
| self_type | 4 | 1 → **5**（フック変奏） | 1.25週 |
| visual | 2 | 1 → **3**（フック変奏） | 1.5週 |
| artist_analysis | 2 | 10（据え置き） | 5週 |

- 追加した弾は既存の品質規約に従う: 実名は ARTISTS_BY_ID の正本のみ・URLなし・
  リプ乞いなし・効果の誇張なし。図解パーサ（`infographic.build_data`）で
  成立することをテストで担保。
- Gemini 下敷きの self_type/visual マーキー実名（従来 rock/mysterious/dramatic 固定）
  も day_index でローテし、顔ぶれの固定化を解消。

## 3. テスト

`scripts/sns_autopost/tests/qa_rotation.py`（新規）:

- TC-RT01: rotation_index が出番ごとに +1 の連番
- TC-RT02: 弾数ぶんの連続出番で本文が全て異なる（一巡まで重複なし）
- TC-RT03: 旧バグ再現条件（同週の contrarian 4枠）が全て別内容
- TC-RT04: 全型で弾数 > 週次出番（1週間以内に同内容が再登場しない）
- TC-RT05: 診断導線フック変奏が実名・リプ案内・URLなしの規約を維持
- TC-RT06: 追加弾が図解データとして成立
- TC-RT07: スケジュール外・不正slotでも例外なくフォールバック

既存ハーネス（qa_artist_analysis / qa_oneoff_text / qa_infographic / qa_images）
は全PASSを確認。

## 4. 運用メモ

- スケジュール表（PILLARS 3表）を改定すると通算出番の数え方が変わり、
  ローテの位相がずれる（重複はしないが順番が変わる）。配分変更は従来どおり
  週次レポートの「1週1変更」ルールで。
- 弾を追加するときは各リストの**末尾に追加**（途中挿入は位相がずれるだけで
  害はないが、末尾追加が素直）。
- 効果確認: fetch_metrics の型別サマリで、同文再登場が消えたことと
  エンゲージの変化を次回週次レポートで確認する。
