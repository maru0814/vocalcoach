## 1. 何が問題か（実測）

ソラ先生に渡している「台本」（システムプロンプト＋状況注入）は、事故が起きるたびに
注意書きを1行ずつ足してきた結果、次の状態にある。

| 計測 | 現状 |
| --- | --- |
| 人格プロンプト（SYSTEM_PROMPT） | **6,931字・99行**。うち「〜しない/禁止」系の表現が **22箇所** |
| 状況注入（build_session_context ほか） | レッスン状況により数十行が毎ターン追加 |
| 会話品質検査の確定所見 | **21件全部が「冗長・長すぎ」**（docs/42 §2 の 2〜4文・120字ルール違反） |
| 質問への逃げ腰（過剰拒否） | 会話の **27%で萎え**、うち最大要因が過剰拒否38件 |

構造的な因果はこう見ている。

> 禁止の積層 → モデルが萎縮して**逃げ腰**になる（過剰拒否）
> ＋ 指示が多すぎて全部に従おうとして**長文化**（冗長）
> ＋ 指示同士の矛盾で挙動が**不安定**になる

正規表現ゲートを撤去しても、台本にルールを足し続ければ「継ぎ接ぎで壊れる構造」が
場所を変えて再現する（憲法 R4）。だから台本には**予算と削る仕組み**が要る。

## 2. 方針（5本柱）

### 柱1: 台本に「予算」を付ける
- 人格・原則パート（SYSTEM_PROMPT 相当）は **3,000字以内** を上限とする（現状の約4割）。
- 追記は **one-in-one-out**: 1行足すなら1行削る。予算超過のPRはレビューで差し戻す。
- 字数チェックはテストとして自動化する（形式の決定論チェックなので憲法の許容範囲）。

### 柱2: 禁止の列挙をやめ、少数の原則に書き直す
22箇所の「〜するな」を、次の3原則＋良い例/悪い例（few-shot）に集約する。

1. **事実は解析から、判断はあなた** — 数値・秒数・URLは渡された事実だけを使う
2. **不確かな時は、確かな範囲＋次の一歩** — 「分かりません」で終えず、分かる範囲を言い橋を架ける
   （橋渡し義務。導入実測で再録音要求 -71%・突き放し率 53%→32% の実績あり）
3. **2〜4文・120字・1ターン1問** — 長さは足すものではなく削るもの

「禁止文のまま残してよいのは安全に関わるものだけ」とする（健康レッドフラグ・歌詞の複製・URL捏造）。
禁止形は萎縮（過剰拒否）の主因と推定しており、原則形＋例示への書き換え自体が治療である。

### 柱3: ターンに関係ある指示だけ渡す（経路別の台本）
PR #303 で会話ターンと分析ターンの system テキストが分離された。これを活かし、

- 会話ターンに、録音講評用の注意書き（秒数の扱い・講評フォーマット等）を**載せない**
- 分析ターンに、雑談・共感の指示を**載せない**
- 状況注入（レッスン状況）は「今のターンの判断に使う事実」だけに絞る

「全部入り1枚の台本」をやめることが、予算内に収める最大の手段になる。

### 柱4: 全ての指示行に「来歴」を付ける（rule provenance）
- 台本の各指示は、docs/42 の節番号と、それを守っていることを確かめる soar_eval ケースIDに紐づける。
- **対応する検査ケースが無い指示行は「削除候補」**。四半期ごとに削除実験を行う:
  1行削って eval を回し、悪化しなければ削除確定、悪化したらその結果を来歴として記録して戻す。
- これにより「怖くて消せない行」を無くす。台本は増える一方、をやめる。

### 柱5: 触ったら測る（憲法 R8 と同じ運用）
- 台本に触れる PR は soar_eval の before/after（萎え率・平均字数・橋渡しなし否定率・多ターン）を貼る。
- ダイエットの成功指標:

| 指標 | 現状 | 目標 |
| --- | --- | --- |
| 返答の平均字数（雑談時） | 147字 | **80字以下**（docs/42 §2.1 の趣旨） |
| 萎え率 | 27% | **15%以下** |
| 質問を躱した率（dodged） | 15/143 | **半減** |
| 冗長所見（N4） | 確定所見の100% | **0件** |

## 4. やらないこと

- 事例が1件起きるたびに台本へ注意書きを足すこと（憲法違反。まず eval にケースを足す）
- 台本の書き換えを eval なしで本番に出すこと
- Web版だけ・skill版だけの片側改訂（docs/42 の単一ソース原則違反）
