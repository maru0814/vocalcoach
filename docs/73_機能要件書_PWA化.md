# PWA化 機能要件書

## 1. 概要
- **一言説明**: 現行 Web版（Next.js `frontend/`）を PWA（Progressive Web App）化し、ホーム画面に追加できる「アプリ体験」と、練習継続を促すプッシュ通知を提供する。
- **解決する課題**: ネイティブアプリはsolo運営に重すぎ、ストア手数料・審査で単位経済と開発速度を損なう（docs/72 意思決定メモ）。一方でボイトレは毎日習慣化してこそ上達につながる。ネイティブの利点（ホーム画面想起・プッシュによる習慣化・オフライン・録音導線）の大半を、Web版のコードのまま・審査ゼロ・手数料ゼロで取りに行く。

## 2. 想定ユーザー / ユースケース
- **ペルソナ**: スマホで練習するライトボイトレ層。「毎日ちょっと録って上達を確認したい」が続かない。
- **主要ユースケース**
  - UC-1: 気に入ったのでホーム画面に追加し、次回からアイコンから起動する。
  - UC-2: 練習リマインドのプッシュ通知を受け取り、その日の練習に戻る。
  - UC-3: 電波の弱い場所でもアプリ枠が開き、録音導線まで到達できる（解析はオンライン必須）。

## 3. スコープ
### 3.1 対象（やること）
- Web App Manifest（名称・アイコン・テーマ色・`display: standalone`・起動URL）
- インストール（ホーム画面追加）導線とインストール可能状態の担保
- Service Worker によるアプリシェルのキャッシュ（オフラインでUIが開く）
- Web Push 通知（購読許諾 → 練習リマインド配信）。VAPID鍵ベース。
- iOS Safari / Android Chrome 両対応（できる範囲。iOSのWeb Push制約は §8 参照）

### 3.2 対象外（やらないこと）
- ネイティブアプリ（App Store / Google Play）— docs/72 で Later 決定
- **録音・解析処理そのもののオフライン実行**（解析はサーバー必須。オフラインは「UIが開く」までで、解析実行はオンラインを要求する）
- バックグラウンド録音・OSレベルのマイク最高品質（ネイティブ固有。対象外）
- 高度なオフライン同期（録音のローカルキュー→後送信）— 本MVPでは扱わない
- プッシュ配信のセグメント配信・A/Bテスト・リッチ通知（画像/アクション）— MVP後

## 4. ユーザーストーリー
- US-01: ユーザーとして、気に入ったアプリをホーム画面に置きたい。なぜなら毎回ブラウザで開くのが面倒で忘れるから。
- US-02: ユーザーとして、練習リマインドの通知が欲しい。なぜなら習慣化できず続かないから。
- US-03: ユーザーとして、standalone表示（ブラウザUIなし）で全画面で使いたい。なぜならアプリらしく集中したいから。
- US-04: ユーザーとして、通知は自分の意思でON/OFFしたい。なぜなら勝手に許諾を求められたくないから。

## 5. 機能要件

### FR-01: Web App Manifest
- **概要**: `frontend/public/manifest.webmanifest`（または Next Metadata API）で manifest を提供し、`layout.tsx` から参照する。
- **詳細仕様**:
  - `name`="ソラ先生のボイトレ"（正式名は designer/ブランド `docs/55` に合わせる）、`short_name`（12文字以内）
  - `display`="standalone"、`start_url`="/?source=pwa"、`scope`="/"
  - `theme_color` / `background_color` はブランドカラー（`docs/61` デザインシステムv2 に準拠）
  - `icons`: 192x192 と 512x512（`purpose: any` と `purpose: maskable` の2系統）。既存 `frontend/src/app/icon.png` を基に生成
- **入出力**: 出力=有効な manifest JSON。Lighthouse PWA/Installability チェックを通過。
- **例外**: アイコン欠落時はインストール不可になるため、192/512/maskable の3枚を必須アセットとする。

### FR-02: インストール導線
- **概要**: インストール可能なブラウザで、ユーザーにホーム画面追加を促す控えめな導線を出す。
- **詳細仕様**:
  - Android/Chrome系: `beforeinstallprompt` を捕捉し、任意のタイミングで「ホーム画面に追加」ボタンから `prompt()` を呼ぶ（自動ポップアップはしない）
  - iOS/Safari: `beforeinstallprompt` 非対応のため、「共有→ホーム画面に追加」の手順を案内するヘルプ表示
  - 既にインストール済み（`display-mode: standalone`）の場合は導線を出さない
  - 導線の閉じる操作を記憶し、しつこく再表示しない（例: 7日間は再表示しない）
- **例外**: 非対応ブラウザでは導線を出さず、通常のWebとして機能を落とさない（プログレッシブ・エンハンスメント）。

### FR-03: Service Worker（アプリシェル・キャッシュ）
- **概要**: Service Worker を登録し、アプリシェル（トップ/コーチ画面の骨格・CSS・主要JS・ロゴ）をキャッシュしてオフラインでもUIが開くようにする。
- **詳細仕様**:
  - キャッシュ戦略: 静的アセット=Cache First、ページのナビゲーション=Network First（フォールバックでオフライン用シェル）
  - **解析API（録音アップロード・FB生成）はキャッシュしない**。オフライン時は「オフラインです。解析はネット接続が必要です」を明示
  - SW更新戦略: 新バージョン検知時に次回起動で反映（skipWaiting は controlled update で。ユーザー操作中の破壊的リロードはしない）
  - 実装は Next 13 App Router 互換の方式（例: `serwist`/`next-pwa` 等はアーキテクトが技術選定）
- **例外**: SW登録失敗時もアプリは通常のWebとして動作する（機能デグレしない）。

### FR-04: Web Push 通知（購読）
- **概要**: ユーザーが明示的にONにしたときだけ通知購読を作成し、サーバーに保存する。
- **詳細仕様**:
  - VAPID公開鍵で `PushManager.subscribe()`、購読情報（endpoint/keys）をバックエンドに保存（ユーザー単位）
  - **許諾は必ずユーザー操作起点**（設定画面のトグル等）。ページ読み込み直後の自動許諾要求は禁止
  - 設定画面（`frontend/src/app/settings`）に「練習リマインド通知」ON/OFFを追加
  - OFF時は購読を解除しサーバー側も無効化
- **入出力**: 入力=許諾操作。出力=購読レコード（DB保存）。
- **例外**: 許諾拒否/ブロック時は状態を保存し、以後トグルは「ブラウザ設定から許可してください」を案内。

### FR-05: Web Push 通知（配信）
- **概要**: バックエンドから購読者へ練習リマインドを配信する。
- **詳細仕様**:
  - バックエンド（FastAPI）に `web-push`（VAPID）送信処理と購読テーブル（Alembicマイグレーション）
  - 配信トリガー MVP: 「最後の録音から N 日（既定=3日）練習がないユーザーへ、1日1回まで」。cron/スケジューラで実行（既存の運用cron方式に合わせる）
  - 通知内容: タイトル「そろそろ声を出そう🎤」＋本文（固定文でMVP可）、クリックで `/coach` を開く
  - 配信失敗（410 Gone 等）時は購読を無効化してクリーンアップ
- **例外**: 送信レート・上限を設け暴発を防ぐ（1ユーザー1日1通まで）。

## 6. 非機能要件
- **性能**: SW導入で初回以降のアプリシェル表示を高速化。Lighthouse PWA スコア=Installable を満たす。
- **可用性**: SW/Push はプログレッシブ・エンハンスメント。非対応環境でも既存Web機能は100%維持。
- **セキュリティ**: VAPID秘密鍵はサーバー環境変数管理（`docs/34` の鍵管理方針に準ずる）。購読情報はユーザーに紐付け、他者に漏れない。
- **保守性**: 「固定費ほぼ¥0」哲学を維持（Web Push自体は無料。外部プッシュ課金サービスは使わない）。
- **UX**: 許諾要求は必ずユーザー操作起点。通知は1日1通上限で鬱陶しくしない。
- **プライバシー**: 通知購読は任意・いつでも解除可能。プライバシーポリシー（`frontend/src/app/legal`）に通知購読の記載を追加。

## 7. 受け入れ基準
- AC-01: Chrome(Android/PC)で本番URLを開くと、インストール（ホーム画面に追加）が可能で、追加後アイコンから standalone 起動できる。
- AC-02: Lighthouse の PWA / Installability チェックがすべてパスする（manifest・アイコン・SW登録・HTTPS）。
- AC-03: 機内モード（オフライン）でホーム画面アイコンから起動すると、アプリシェル（UI）が表示される（白画面やブラウザのオフラインエラーにならない）。
- AC-04: オフライン状態で録音解析を実行しようとすると「解析にはネット接続が必要」の明示メッセージが出る（無言の失敗をしない）。
- AC-05: 設定画面で通知をONにすると許諾ダイアログが出て、許可すると購読がサーバーに保存される。ページ読み込み直後に自動で許諾は要求されない。
- AC-06: 最後の録音から3日練習がないON購読ユーザーに、リマインド通知が1通届き、クリックで `/coach` が開く。同一ユーザーに1日2通以上は届かない。
- AC-07: iOS Safari では「共有→ホーム画面に追加」の案内が表示され、追加後 standalone 起動できる（Web Pushの可否は §8 の制約に従う）。
- AC-08: SW登録やPush非対応のブラウザでも、既存のWeb機能（録音・解析・FB）がすべて従来どおり動作する。

## 8. 前提・制約
- 前提: 本番はHTTPS（Caddy）で提供済み（docs/08）。PWA/Push はHTTPS必須のため前提を満たす。
- 制約: **iOS の Web Push は iOS 16.4+ かつ「ホーム画面に追加」したPWAのみ**動作。未追加のSafariタブでは通知不可。iOS向けは「追加を促す→追加後に通知許諾」の順序を守る。
- 制約: 録音品質・バックグラウンド録音はネイティブに劣る。これは docs/72 で許容済み（ネイティブは Later）。
- 前提: ブランド名・カラー・アイコンは `docs/55`（ブランドリニューアル）/ `docs/61`（デザインシステムv2）を正本とする。
- 制約: FB品質・解析ロジックは本要件で変更しない（`docs/42` 単一ソース不変）。
