## 1. eval の回し方（②）

### 1.1 正解付き録音を集める（運用者のみができる作業）
- 1練習=1ファイル。**録音した本人が正解を知っている**ものだけを使う（これが「正解付き」の意味）
- ラベル語彙: `llm.PRACTICE_KEYWORDS` の代表形（リップロール／サイレン／ハミング／エッジボイス等）または `歌`
- 目安: まず 1ラベルあたり2〜3本 × 5〜8種類 ＝ 15〜20ファイル。docs/92 §5.9 のサイレン2本も再利用できる
- 紛らわしいペア（サイレン vs リップロール、リップロール vs 巻き舌）を意図的に含める

### 1.2 マニフェストと実行
```csv
# manifest.csv（path はCSVからの相対パス可）
path,label
recordings/siren_01.wav,サイレン
recordings/liproll_01.wav,リップロール
recordings/song_01.wav,歌
```
```bash
cd backend
# 本番と同条件（現行モデル・DSPあり）の正答率:
python ../scripts/blind_listen_eval.py manifest.csv --runs 3 --out report.json
# モデル横断＋DSP効果の同時測定（①はやらない決定だが、測るだけは1コマンド）:
python ../scripts/blind_listen_eval.py manifest.csv --runs 3 \
    --models gemini-2.5-flash,gemini-3.5-flash --dsp both --out report.json
```
- コスト: 実行前に予定呼び出し数×¥0.5 の概算が表示される（20ファイル×3回×1モデル×DSPあり ≒ ¥30）
- 実API・実音源依存のため CI では回さない（従来どおり手動運用）

### 1.3 結果の読み方と反映先
- **name正答率 ≥90% のラベルだけ「名指し可」**（docs/104 §4。最終ラインは運用者が決める）。
  それ未満は現行どおり描写＋一言確認（docs/105 実装済み＝精度不足は「間違い」でなく「質問」になる）
- kind正答率（歌/練習の取り違え）が9割を切る場合は識別レイヤーの前提が崩れているので、
  名指し以前に docs/105 の見直しを起票する
- **失敗列**（listen_blind が2回とも失敗）はレイテンシ・形式崩れの兆候。モデル比較では正答率と併読する
- 結果は本書 §4 に追記して記録する（docs/92 と同じ運用）

## 2. しきい値較正（③）

`report.json` の `profiles[].profile.windows` に、録音ごとの1秒窓の生値
`{rate_hz, strength}` が入っている（しきい値でふるう**前**の値）。

1. ラベルを2群に分ける: **震え系**（リップロール・巻き舌・エッジボイス）と
   **非震え系**（サイレン・ハミング・歌・ロングトーン）
2. 群ごとの strength 分布（evalが表で出力）を見て、両群を分ける値を選ぶ
   （現行 0.35 は合成信号での暫定値。texture.py:20 の `STRENGTH_THRESHOLD` を更新）
3. 変更したら **APIを叩き直さず** `texture.modulation_profile` の再計算だけで
   describe 文の変化を確認できる（録音はローカルにあるため）
4. しきい値変更は hermetic テスト（`backend/tests/test_texture.py`）が通ることを確認して反映

## 3. ハーネス実証（合成スモーク・2026-08-14 実施）

合成3ファイル（サイレン相当スイープ／25Hz AM＝リップロール相当／ハミング相当）×
2モデル × DSPあり/なし × 1回 ＝ 12呼び出し（¥6）を実APIで実行し、動作を確認した。

- **正答率の根拠には使わない**（合成音源は人声ではないため。§1 の実録音evalが本番）
- ハーネスとしての確認事項: モデル切替・DSP切替・レイテンシ計測・失敗計上・レポート出力 すべて動作
- 較正データの妥当性: strength 生値は サイレン相当 0.13〜0.18 ／ リップロール相当 0.95〜0.96 と
  設計どおり明確に分離（現行しきい値 0.35 は合成信号上は妥当な位置）
- **観測事項（要注視）**: `gemini-3.5-flash` は4行フォーマットの遵守が不安定だった
  （PRACTICE が「practice」「リップ」等に崩れる・2/12 でパース失敗→リトライ）。
  レイテンシも 2.5-flash（1.9〜3.1s）より遅い尾（5.1〜5.8s）を確認。
  docs/92 §5.10 の「3.5-flash は尾が重い」と整合する。**モデル変更を検討する場合は
  実録音evalの正答率・失敗数・レイテンシの3点で判断する**（今回は①をやらない決定のため据え置き）

## 4. 実測記録（実録音）

### 第1号: 本番実事故の再現と較正（2026-08-14）

**事故**: 運用者がリップロール（サイレン音形・2.9秒）を本番アプリへ送信 →
ソラ先生が「サイレンの発声」と断定して講評（識別レイヤー docs/105 デプロイ後の初事故）。

**DSP計測の再現**（決定論・本番と同一経路 webm→wav 22050Hz）:
- 震え: 13.8Hz・strength 0.41・flutter_ratio 0.5（2窓中1窓。残り1窓は f0 漏れの境界ガードで計測除外）
- 音程移動: 19半音（86→264Hz）
- 注入された事実文: 「録音の一部（約5割）の区間で**のみ**毎秒約14回の振幅の規則的な震えを検出。
  **残りの区間はなめらか**。音程は…約19半音…移動している」（帯域注釈なし: 13.8Hz は旧注釈帯域 15〜45Hz の外）

**条件比較**（gemini-2.5-flash・各5回・同一録音）:
| 条件 | 判定 | 備考 |
| --- | --- | --- |
| A: 本番の事実文（当時） | サイレン 5/5・high | 事故を完全再現 |
| B: DSPなし（素の耳） | **リップロール 5/5・high** | モデルの聴覚は正しかった |
| C: A＋帯域注釈のみ追加 | サイレン 5/5・high | 注釈だけでは直らない |
| D: 矮小化表現を除去＋共存注記 | **リップロール 5/5・high** | 処方を確定 |
| 修正後コード（facts.assemble 経由） | **リップロール 5/5・high** | 本番同一経路で検証済み |

**結論**: 誤認の原因はDSPでもモデルの耳でもなく、**事実文の言い回し**（矮小化表現＋
共存注記の欠如）がモデルの正しい聴覚を上書きしていたこと。処方は docs/104 改訂その2。

**残る監視点**: 逆方向（冒頭だけきしむサイレン）の実録音が未検証。運用者のサイレン録音が
揃い次第、同じ条件比較で退行がないことを確認する（hermetic の文言テストは追加済み）。

### 第2号: 言い回し修正では一般化しない — 事実注入を既定OFFへ（2026-08-14）

**事故**: 第1号の修正デプロイ直後、運用者が別テイクのリップロール（14.9秒・サイレン音形・
上下スイープ）を送信 → 再び「サイレンの練習」と断定講評。

**DSP計測の再現**: 毎秒25.0回・strength 0.87・flutter_ratio 0.79（11窓が20〜29Hzで安定）＝
**教科書どおりのリップロールを完璧に計測**。音程移動 32半音（81→523Hz）。
事実文は帯域注釈＋共存注記つきの理想形だった。

**条件比較**（gemini-2.5-flash・各5回・同一録音）:
| 条件 | 判定 |
| --- | --- |
| 修正後の事実文を注入（第1号の処方） | サイレン 5/5・high（誤） |
| 注入なし（素の耳） | **リップロール 5/5・high（正）**「リップロールをしながら音程を上下させている」 |

**結論**: 言い回しの較正はテイク依存で一般化しない。実録音2本を通じ、素の聴覚は10/10正解、
事実注入だけが誤認を作った。注入導入の動機（8/13 サイレン誤認）も聴力でなくエラー握りつぶしが
原因だったと判明済み（docs/95 FR-05）で、**注入が助けた実例はゼロ**。
処方: `blind_listen_inject_facts`（config・既定OFF）でブラインドへの注入を停止。
計測・ログ（「質感計測: …」）と eval の `--dsp both` は維持し、今後の実録音evalで
注入あり条件が正答率で上回った場合のみ再ONを検討する（docs/104 改訂その3）。
