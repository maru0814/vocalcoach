# X投稿インフォグラフィック デザイン仕様

対象: X自動投稿に添付する「保存される情報図解」テンプレート。
現状の“タイトル1行＋グラデ表紙”を、お手本水準（タイトル＋色分け3ステップ＋まとめ帯）に引き上げる。
作成: UXデザイナー（2026-06-29）。コンテンツ源: `scripts/sns_autopost/themes.py` の `TIPS` / `CONTRARIAN`。

## 1. ユーザーゴール
- タイムラインで親指を止め、**画像1枚で手順が完結**して「保存」したくなる。
- ソラ先生＝専門家、と一目で伝わるブランド一貫性。
- 文字化けゼロ（日本語はコード描画。AIには描かせない）。

## 2. コンテンツ・マッピング（自動抽出）
`TIPS[i]` の文字列構造はすべて共通で、図解の各領域に1:1で対応する：

| TIPSの行 | 図解の領域 |
| --- | --- |
| 1行目「…人へ。」 | **タイトル**（悩みフック） |
| ①の前の段落 | **サブ見出し**（原則・結論の一言） |
| `①〜③` の各行 | **ステップブロック**（番号＋本文） |
| 最終段落 | **まとめ帯**（締め。キー句を黄色ハイライト） |

- パーサ規約: `①②③④` で始まる行をステップとして抽出（2〜4個可変）。先頭行=タイトル、最初の空行までの非番号段落=サブ見出し、番号行の後の段落=まとめ。
- `CONTRARIAN` は「誤解（タイトル）＋根拠（サブ）」型 → ステップ無しの**2ブロック簡易版**にフォールバック（§7）。

## 3. キャンバス / グリッド
- **比率: 16:9 横長（1600×900px、表示1200×675）**。理由: 3ステップ＋注釈を横に展開でき、Xフィードで16:9はトリミングされず全面表示。縦4:9表紙より情報密度が高い。
- 外周パディング 56px。8pxベースライングリッド。
- 縦スタック5領域（上→下）:

```
┌──────────────────────────────────────────────┐  56 padding
│  TITLE BAR            （H 96）                  │
│  SUBTITLE  - - - - - - - - - - - - - -         │  （H 56）
│  ┌ STEP 1 ───────────────────[illust/icon]┐    │
│  │ ❶  pill見出し / 本文                     │ ↓  │  3行
│  ├ STEP 2 ───────────────────[illust/icon]┤    │  各 H≈170
│  │ ❷  pill見出し / 本文                     │ ↓  │
│  ├ STEP 3 ───────────────────[illust/icon]┤    │
│  │ ❸  pill見出し / 本文                     │    │
│  └────────────────────────────────────────┘    │
│  ┌ まとめ帯（🎤 まとめ ＋ハイライト＋#tag）┐   │  （H 120）
│  └────────────────────────────────────────┘    │
└──────────────────────────────────────────────┘
```
- ステップ行の内部: 左から **番号バッジ(72px)→本文カラム(可変)→右イラスト枠(360px固定)**。行間に下向き矢印「↓」。
- 行高はステップ数で flex 等分（2個なら各行を高く、3個=既定、4個なら本文フォント-2px）。

## 4. デザイントークン
### カラー（ブランド軸＝紫→ピンクをステップに分配）
| 用途 | 値 |
| --- | --- |
| ブランド軸 | violet `#7c3aed` → purple `#8b5cf6` → pink `#ec4899` |
| Step1 | accent `#7c3aed` / 帯背景 `#f3efff` |
| Step2 | accent `#b14ad6`（軸の中点付近） / 帯背景 `#fbeefb` |
| Step3 | accent `#ec4899` / 帯背景 `#fdecf4` |
| 本文テキスト | slate `#334155` |
| サブ/注釈 | slate `#64748b` |
| まとめ帯背景 | `#f8fafc`（薄灰） |
| ハイライト（蛍光） | `#fde68a`（amber-200） |
| 背景 | ほぼ白 `#ffffff`＋上端に淡いブランドグラデ20% |

> お手本は青/橙/緑の信号色だが、本ブランドは紫→ピンク軸で**色相を振りすぎず**段階差をつける（権威性・統一感優先）。

### タイポ（Zen Maru Gothic / 丸ゴシック）
| 要素 | サイズ | 太さ |
| --- | --- | --- |
| タイトル | 52px | Bold |
| サブ見出し | 30px | Medium |
| ステップ番号 | 40px | Bold（白丸内） |
| pill見出し | 34px | Bold（色帯に白文字） |
| ステップ本文 | 28px | Regular |
| 注釈ラベル | 22px | Medium |
| まとめ本文 | 28px | Regular |
| ハッシュタグ | 24px | Medium（ブランド色） |

### 角丸 / 影
- ステップ帯・まとめ帯・pill: 角丸 20px。pill は 999px（完全ピル）。
- 影は控えめ（`0 6px 20px -8px rgba(124,58,237,.18)`）。番号バッジのみ軽い立体。

## 5. ステップごとの色運用ルール
1. 番号バッジ = step accent の塗り、白文字。
2. pill見出し = step accent 塗り、白文字。本文は step帯背景(淡色)の上に slate。
3. イラスト/アイコンの線・タグ枠 = step accent でトーンを合わせる。
4. 矢印「↓」= 次stepの accent（流れを予告）。

## 6. ソラ先生キャラクター（確定）
**方針（2026-06-29 確定）: AIキャラ「ソラ先生」を採用。絵柄=案B（アニメ系・紫→ピンクのグラデ髪＝ブランド色）。**

### 6.1 一貫性の担保（最重要）
AIは生成のたびに別人になるため、**毎投稿生成は禁止**（ソラ先生が毎回別人＝ブランド崩壊）。
- **参照画像1枚を基準**に、`gemini-2.5-flash-image`（Nano Banana＝キャラ一貫性編集）で「同じソラ先生のまま別ポーズ」を生成 → **固定アセット化**。検証済み（同一の顔・髪・衣装でポーズ差分が出ることを確認）。
- ポーズ確定セット（`assets/characters/sora/` に保存、追跡対象）:
  | キー | 用途 |
  | --- | --- |
  | `singing` | 既定/ヒーロー（歌う） |
  | `explain` | 説明・手を差し出す（tip本文側） |
  | `cheer` | 応援・グッ（まとめ帯） |
- **再生成はリブランド時のみ**。通常運用は静的アセットの貼り込み＝コスト¥0・失敗ゼロ・完全一貫。

### 6.2 配置
- 既定: カード右に1体（ヒーロー配置、白背景をノックアウトして合成）。
- お手本風に“ステップ毎”にしたい場合: 3ポーズを各行右に縮小配置（最大3体まで）。**生成は最初の1回だけ**なので per-step でも崩れない。
- 注釈ラベルは本文中の「」抜き出し or キーワードを最大2個。
- ❌ per-post でのAI人物生成（不整合・失敗・3倍コスト）は不採用。

### 6.3 アイコン併用（任意）
キャラを置かない簡易版や補助として、概念→ラインアイコン（`microphone / lungs / stairs-up / wave` 等）を step accent 着色で使ってよい。

## 7. テンプレ可変・状態網羅
- **ステップ2個**: 行を2分割で高く。**3個**: 既定。**4個**: 本文28→26px、行高圧縮。
- **CONTRARIAN（手順なし）**: タイトル（誤解）＋大きな「↑これ、半分ウソ」バッジ＋根拠ブロック1枚＋まとめ。ステップ帯は出さない。
- **診断導線（self_type/voice_type/visual）**: 図解ではなく従来の“表紙カード”（§現行）を使う（情報量が少ないため図解に不向き）。→ **図解テンプレは tip / contrarian 限定**、他はカード。
- **本文が長すぎ**: 各ステップ本文は最大2行で省略（`…`）。まとめは3行上限。
- **フォント未検出**: 既存同様クラッシュせず（ただし図解は文字必須のため、フォント無し時はカードにフォールバック）。

## 8. 実装技術の推奨
**HTML/CSS → PNG（Playwright / Headless Chromium）を強く推奨。**

| 方式 | 評価 |
| --- | --- |
| **HTML/CSS→PNG（Playwright）** | ✅ pill・flex・ハイライト・日本語折返し・@font-faceが全部容易。お手本レベルに最短。Docker に Chromium追加(~300MB)はcronツールなら許容。 |
| SVG→PNG（resvg/cairosvg） | △ レイアウト制御は可能だがテキスト折返しを自前計算。中量級。 |
| Pillow 手描き | ✕ pill/flex/折返し/ハイライトを全部座標計算。この密度では非現実的・保守不能。 |

- テンプレは単一HTML（`templates/infographic.html`）＋CSS。`{{title}} {{subtitle}} {{steps[]}} {{summary}} {{highlight}} {{hashtags}}` を差し込み、Playwrightで `1600×900` をスクショ→PNG。
- フォントは Zen Maru Gothic を `@font-face`（同梱 or Google Fonts）。Dockerに同梱しオフライン化。
- 既存 `images.py` は「診断カード（表紙）」担当として残し、**新規 `infographic.py`（tip/contrarian図解）を追加**。`build_image()` がピラーで振り分け。

## 9. アクセシビリティ / 可読性
- 本文と背景のコントラスト比 ≥ 4.5:1（slate#334155 on 淡色帯=OK）。pill白文字 on accentも≥4.5:1を満たす accent明度に調整。
- 最小フォント22px（注釈）以上。1行の最大文字数 ≈ 全角20字で折返し。
- 1画像=1トピック。詰め込みすぎない（ステップ最大4）。

## 10. 受け渡し
- **キャラ確定アセットは生成済み**（`/tmp/sora_{B_halfbody,pose_explain,pose_cheer}.png`）。実装時に `scripts/sns_autopost/assets/characters/sora/` へ `singing/explain/cheer.png` として配置する。
- Pillow合成プレビュー（`scratchpad/compose_preview.py` → `/tmp/sora_infographic_final.png`）で完成形を確認済み。これは方向確認用プロトタイプで、本番は §8 のHTML/CSS→PNG。
- 注意: アイコン/🎤等はフォントに無いので**SVG or webアイコン**で描く（絵文字をテキスト描画しない＝豆腐化する）。
- 次は **frontend-engineer**: `infographic.html`＋CSSテンプレを実装（このトークン/グリッドに準拠、キャラ`<img>`＋3ステップ＋まとめ帯）。
- 続いて **backend-engineer**: Playwrightレンダラ＋`themes.py`パーサ＋`build_image()`振り分け（tip/contrarian=図解 / 診断導線=カード）を統合。

# 追補: 診断導線レイアウト（type=diagnosis / voice_type・self_type・visual）

作成: UXデザイナー（2026-06-30）。背景: 診断導線ピラーが「カード（背景＋見出しだけ）」に回り、声タイプ図鑑が“表紙だけ・英語Dramaticが改行で割れる”残念画像になった（LINE実機で確認）。**tip/contrarianと同水準の図解に統一**する。

## D1. ゴール
- 1枚で「8つの声タイプの世界観」が伝わり、「自分はどれ？」と**診断したくなる**。
- 英語タイプ名（Rock/Dramatic等）は**改行で割らない**（CSSの単語折返しで担保。カードのCJK1文字折返しが原因だった）。

## D2. レイアウト（16:9・既存と共通の枠／キャラは専用カラム）
縦スタック:
1. **タイトル**（フック。gradient・最大2行・`word-break:keep-all`で英単語保持）
2. **サブ見出し**（点線・任意）
3. **8タイプ・ラインアップ（主役）**: 4列×2行のチップ。各チップ＝淡色オーブ＋絵文字＋**タイプ名(Latin, 改行禁止)**＋1行特徴。
   - `voice_type`（スポットライト型）: 該当1タイプのチップを**拡大＋枠強調(2px accent)**し、特徴文を大きく。残り7つは通常サイズ。
   - `self_type` / `visual`: 8つを均等サイズで見せる。
4. **CTA帯**: 「プロフィールのリンクから無料で診断🎤」（self_type=「直感でどれっぽい？」/ visual=「15秒歌うだけ・似た歌手まで」を併記）
5. キャラ（explainポーズ・既存 `.char-col` 固定440px。本文は絶対に重ねない）

```
┌────────────────────────────────────────┐
│ TITLE (gradient, ≤2行)                    │
│ subtitle ----                       [キャラ]│
│ ┌Rock┐┌Groovy┐┌Pop┐┌Myst┐               │
│ └────┘└─────┘└───┘└────┘   ← 8タイプ4×2  │
│ ┌Cryst┐┌Drama┐┌Whis┐┌Moody┐  (voice_type │
│ └─────┘└─────┘└────┘└─────┘   は1つ強調)  │
│ ┌ CTA帯: プロフィールから無料で診断🎤 ┐    │
│ └──────────────────────────────────┘    │
└────────────────────────────────────────┘
```

## D3. 8タイプの色運用（声の質感に対応した淡色）
チップは「淡色tint背景＋同系の濃色テキスト」。8色は声のムードに対応:
| タイプ | 絵文字 | アクセント | tint背景 |
| --- | --- | --- | --- |
| Rock | 🔥 | #e2553a | #fdeee9 |
| Groovy | 🎙 | #d98324 | #fbf0e0 |
| Pop | 🌤 | #2f9bd4 | #e6f3fb |
| Mysterious | 🌒 | #5b54c4 | #ecebf9 |
| Crystal | 💎 | #1f9e8e | #e2f5f1 |
| Dramatic | 🎭 | #d4477e | #fbe9f1 |
| Whisper | 🍃 | #4fa564 | #e9f4ec |
| Moody | 🌙 | #7c5cc4 | #efeafa |
- ブランド軸（紫→ピンク）はタイトル／CTA／キャラで効かせ、8チップは“図鑑”として多色でOK（多色は声の多様性の表現＝意味がある）。
- スポットライトのタイプは tint背景＋`2px solid accent` の枠で1つだけ強調。

## D4. タイプスケール（Zen Maru Gothic）
| 要素 | サイズ |
| --- | --- |
| タイトル | 50/700（既存と同じ） |
| サブ見出し | 28/500 |
| チップ: タイプ名 | 30/700（Latin・改行禁止） |
| チップ: 絵文字 | 34 |
| チップ: 特徴 | 22/400（1行省略） |
| スポットライト特徴 | 30/500 |
| CTA帯 | 30/700（白文字 on brand-gradient） |

## D5. 絵文字の扱い
- 8タイプ絵文字（🔥🎙等）は Chromium で表示するため、**Dockerに `fonts-noto-color-emoji` を追加**（未導入だと豆腐化）。
- フォールバック: 絵文字が出ない環境では、チップ左に accent色の丸ドットを代わりに置く（タイプ名は必ず出す）。

## D6. データ（themes.VOICE_TYPES から）
`infographic.py` に `parse_diagnosis(pillar, day_index)` を追加し、`{type:"diagnosis", title, subtitle, spotlight?:{name,emoji,desc,accent,bg}, types:[{name,emoji,trait,accent,bg,featured}], cta}` を返す。VOICE_TYPESの並びと色表(D3)を内蔵。

## D7. 受け渡し
- 次は **frontend-engineer**: `templates/infographic.html` に `type==="diagnosis"` のレンダラ（8チップ4×2＋スポットライト＋CTA帯）を追加。英語名は `white-space:nowrap`。
- 続いて **backend-engineer**: `infographic.py` に `parse_diagnosis` ＋ `generate()` の分岐、`build_image` の振り分けを「全ピラー→infographic」に変更（診断導線もカードでなく図解へ）。Dockerに emoji フォント追加。
