# 会話型FB 設計書

対象: [36_機能要件書_会話型FBリニューアル.md](36_機能要件書_会話型FBリニューアル.md) / [37_デザイン仕様_会話型FB.md](37_デザイン仕様_会話型FB.md)

## 1. システム構成

### 1.1 データフロー（リニューアル後）
```mermaid
flowchart LR
    A[録音/テキスト] --> B[coach.py endpoint]
    B --> C[analyzer 解析]
    C --> D[rule_engine ディスパッチ]
    D --> E[voice_coach.diagnose 内部判断]
    E --> F[llm.generate_coach_comment 会話文1つ]
    F --> G[ChatMessage type=text のみ]
    G --> H[Bubbles.tsx テキスト吹き出し]
```

### 1.2 設計の核
- **解析・診断は維持、出力整形だけ差し替える**。`analyzer` / `voice_coach` / `taxonomy` の診断は内部判断材料として残し、`feedback_builder` のカードpayload生成と `rule_engine` の多メッセージ展開を会話文1本に置き換える。
- LLMコメント生成の制約を、録音FBとチャットで**単一化**する（現状は二重定義で矛盾）。

## 2. アーキテクチャ判断

| 判断 | 選択 | 理由 / 代替案 |
| --- | --- | --- |
| カード型の扱い | **新規生成を止める。型定義・DBカラムは残す** | 破壊的マイグレーションを避け過去ログ互換を保つ。代替（型ごと削除）はリスク大で不採用 |
| LLM制約の統一 | `_VOICE_INSTR` を廃し、録音FBもチャット同様 2〜4文制約に寄せる | トーン分裂の根本原因を断つ。`SYSTEM_PROMPT` を単一の真実とする |
| スコア | 計算ロジックは残し**注入・表示のみ削除** | `voice_coach.diagnose` 等が内部でしきい値を使うため計算は必要。表示だけ消す |
| 苦手検知→提案 | 既存 `voice_coach.diagnose` + `build_llm_block` を流用 | 「主課題1つ＋★推奨1つ＋できない時だけ次へ」が既に実装済み。再発明しない |
| メッセージ数 | 録音FB＝原則 text 1（最大2） | 「過剰」の主因が4連発のため。チップ/カードを足さない |

## 3. API設計
**エンドポイントの形は変更しない**（`/coach/sessions/{id}/audio` 等）。変わるのは `ChatResponse.messages` の中身：

- Before: `[audio, feedback(card), text, practice(card), text(chips)]`（5件）
- After（練習提案なし）: `[audio, text]`（2件）
- After（練習提案あり）: `[audio, text(感想), text(練習法＋動画リンク)]`（3件・coachは2吹き出し）

`MessageOut.type` は `text` を主とする。`feedback`/`practice`/`judge`/`progress`/`diagnosis` は**新規には返さない**（スキーマからは消さず、後方互換のため受理可能なまま）。

## 4. DBスキーマ
- **変更なし**。`ChatMessage.type` / `payload` カラムは維持。
- マイグレーション追加なし。過去の旧型レコードはそのまま保持。

## 5. モジュール構成（変更点）

### 5.1 backend

| ファイル | 変更内容 |
| --- | --- |
| `coaching/rule_engine.py` | `_audio_diagnose` を「会話文1本（必要なら動画リンク内包）」に再構成。`feedback`/`practice` カードの append を削除。`_audio_practice_check`・`_audio_recheck` も判定カードを廃し会話文へ。`_VOICE_INSTR` を削除または2〜4文制約に書き換え |
| `coaching/llm.py` | `build_session_context` のスコア注入（音程/リズム/表現/総合の行）を削除。`generate_coach_comment` の指示を「2〜4文」に統一。捏造ガード（`_scrub_invented_seconds`/`_scrub_lyrics`）は維持 |
| `coaching/feedback_builder.py` | カードpayload生成関数（`build_feedback_payload`/`build_voice_axes`/`build_analysis_table` 等）を**呼ばなくする**。会話文の事実供給に必要な補助（`_note_name`/`vibrato_label` 等）は残す。関数自体の削除は段階的に |
| `coaching/rule_engine.py: answer_question` | スコア質問分岐を「点数はつけていません」方針の返答に変更 |
| `coaching/voice_coach.py` / `taxonomy.py` | **変更しない**（内部判断材料として維持） |

**練習提案の会話内リンク**: `task["practices"][0]["video"]` の URL を、カードではなく `generate_coach_comment` に渡す facts に含め、会話文末に1行リンクとして添える。確定的にリンクを出したい場合は、LLM出力後にコード側で1行追記する方式も可（LLMがURLを落とす事故防止）。

### 5.2 frontend

| ファイル | 変更内容 |
| --- | --- |
| `components/coach/Bubbles.tsx` | `MessageBubble` の `isCard` 分岐を、§37-5 のフォールバック描画に変更。新規 text は従来通り描画。旧 `FeedbackCard` 等は過去ログ専用の縮約テキスト表示に。`ActionChips` は本機能では必須としない（残置可否は実装時判断） |

## 6. 後方互換性（移行）
- 既存セッションを開くと、過去の旧カードレコードが混在する。`Bubbles.tsx` は type が旧カード型のとき §37-5 のフォールバック（淡色テキスト・点数非表示）でレンダリングする。
- backend が旧カード型を新規生成しなくなるだけで、保存済みデータ・スキーマは不変。ロールバック時も互換。

## 7. エラーハンドリング方針
- 解析失敗・無音・同一音源・原曲取得失敗の既存ガードは**全て維持**（text一言で返す。表は出さない）。
- LLMタイムアウト時のフォールバック文（`_llm_or`）は維持しつつ、テンプレ文も2〜4文・点数なしに揃える。

## 8. 性能・可用性
- カード生成（`feedback_builder` の重い組み立て）が減り、LLM呼び出し回数も録音あたり実質1回に収束 → レイテンシは現状以下。
- `llm_coach_wait_sec` の待ち上限はそのまま。

## 9. セキュリティ
- 変更なし。捏造防止ガード維持により、会話文化しても与えられていない数値・秒数・歌詞は出力されない。

## 10. テスト方針（QA連携）
- AC-01〜AC-07（要件書§7）をテストケース化。
- 重点: 録音1回でcoach textが1〜2件か / 出力に点数・◎○△×・指標表が出ないこと / 課題なし録音で練習提案が出ないこと / 旧カードを含む既存セッションが壊れず開けること。
- 回帰: 無音・非歌唱・同一音源・原曲取得失敗のガードが従来通り動くこと。

## 11. 実装順序（推奨）
1. backend `llm.py`: スコア注入削除＋コメント制約統一（トーンの土台）。
2. backend `rule_engine.py`: `_audio_diagnose` のカードappend削除→会話文1本化。`_VOICE_INSTR` 撤去。
3. backend: `_audio_practice_check`/`_audio_recheck` の判定カードを会話文化。`answer_question` のスコア分岐修正。
4. frontend `Bubbles.tsx`: 旧カードをフォールバック描画に。
5. `SKILL.md`: 会話型に書き換え（Web版トーンと同期）。
6. QA: 受け入れ基準で検証。
