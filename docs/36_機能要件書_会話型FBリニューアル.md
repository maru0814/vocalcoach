# 会話型FBリニューアル 機能要件書

## 1. 概要
- **一言**: 録音への歌唱フィードバックを、採点カードの一括表示から「人間のボーカルコーチとチャットしている」会話体験へ作り替える。
- **解決する課題**: 現状はユーザーが聞いた以上に過剰な情報（採点カード4連発・スコア・項目羅列）が返り、機械的で「採点された」感覚になる。聞かれた分だけ、話し言葉で返る体験にする。

### 背景（現状分析の要点）
- 録音1回で `rule_engine._audio_diagnose` が **4メッセージ**（feedbackカード＋LLM長文＋practiceカード＋チップ付き案内）を一度に返す。
- LLMコメントには `_VOICE_INSTR` で「チャットの短さ制限を外し5〜8文で解説せよ」と、チャット人格（2〜4文/120字）と**真逆**の指示が入っている。
- 一方、自由テキストへの返信経路（`llm.generate_reply`）は会話履歴を保持し短く人間的に返す。**マルチターン基盤は完成済み**。
- 苦手検知→練習1つ提案の仕組み（`voice_coach.diagnose` / `build_llm_block` の★推奨1つ）も**既存資産として存在**する。
- → 本リニューアルは「FB経路を既存のチャット人格に吸収し、カード生成系を撤去する」ことが本質。会話AIの新規開発は不要。

## 2. 想定ユーザー / ユースケース
- **ペルソナ**: 独学で歌が上手くなりたい人。専門用語に詳しくない。気軽に「今の歌どう？」と聞きたい。
- **主要ユースケース**:
  1. 録音を送り、「どうだった？」と気軽に感想を求める → 短い会話で返ってくる。
  2. 特定の発声（高音・ミックス・ロングトーン等）を苦手にしている → 会話の流れで練習法を1つ教えてもらう。
  3. 続けて質問する（「どこが？」「どうやって直す？」）→ 文脈を保ったまま会話が続く。

## 3. スコープ

### 3.1 対象（やること）
- 録音FB経路（`_audio_diagnose` / `_audio_practice_check` / `_audio_recheck`）の出力を、会話文（チャットと同一トーン・文量）に統一する。
- スコア・点数・採点カードの概念を**完全撤廃**（裏でも表示用には持たない）。
- 苦手な発声を検知したターンだけ、練習法を**1つ**自然に提案する。
- 参考動画は会話文中のリンクとして残す（カードにしない）。
- Web版チャットと Claude Code版（SKILL.md）でトーン・文量を揃える。

### 3.2 対象外（やらないこと）
- 音声解析エンジン（`analyzer` / `voice_lab` / `taxonomy` の診断ロジック）の作り直し。**解析・課題判定は内部判断材料として維持**する。
- スコア計算の閾値ロジック自体の削除（表示はやめるが、課題判定の内部材料としては残す）。
- 既存DBスキーマの破壊的変更（過去データのカラム削除・型移行は行わない）。
- 声タイプ診断（`/voice-type` ページ）の機能変更。これは独立機能として現状維持。
- 新しい音声分析観点（リズム・表現等）の追加。

## 4. ユーザーストーリー
- **US-01**: ユーザーとして、録音を送ったら長文や表ではなく、友達のコーチが返すような短い一言で感想がほしい。なぜなら一度に大量の情報を処理したくないから。
- **US-02**: ユーザーとして、自分が苦手そうな発声に対して「こういうやり方あるよ」と練習法を1つだけ教えてほしい。なぜなら複数並べられても何から手をつけるか分からないから。
- **US-03**: ユーザーとして、続けて質問したら前の話を覚えたまま会話を続けてほしい。なぜなら毎回最初から説明したくないから。
- **US-04**: ユーザーとして、点数で評価されたくない。なぜなら採点されると萎縮し、楽しく続けられないから。

## 5. 機能要件

### FR-01: 録音FBの会話文化
- **概要**: 録音受信時の応答を、原則テキスト1〜2吹き出しの会話文にする。
- **詳細仕様**:
  - 標準的な録音FBの返答は **2〜4文**（チャット経路と同一制約）。`_VOICE_INSTR` の「短さ制限を外す/5〜8文」指示は撤廃する。
  - 1回の録音に対し、`feedback`/`practice`/`judge`/`progress` カードを新規生成しない。
  - 解析結果（秒数・課題・声の状態）は会話文の根拠として使ってよい。例:「サビの高い音、地声で押し上げ気味かも。軽く前に当てると楽に届くよ」。
  - 点数・◎○△×・指標の数値羅列は出力に含めない。
- **入出力**: 入力＝録音解析結果（既存 `analysis` / `compare_data`）。出力＝coachのtextメッセージ（1〜2件）。
- **例外ケース**: 無音・非歌唱・同一音源は既存ガード（録り直し依頼）を維持。

### FR-02: 苦手検知時の練習法1つ提案
- **概要**: 明確な発声課題を検知したターンだけ、練習法を1つ会話で渡す。
- **詳細仕様**:
  - 課題検知は既存の `voice_coach.diagnose` を流用。検知された主課題（severity最上位）に対応する★推奨の練習を**1つだけ**会話文で説明する。
  - **毎ターン提案しない**。課題が検知されない録音・通常の質問では提案を出さない（「出さないのが普通」）。
  - 一度すすめた練習は会話が続く間そのまま続けるよう導く（既存の「練習をコロコロ変えない」方針を維持）。ユーザーが「できない/合わない」と言った時だけ次の候補へ1つ切り替える。
  - 練習法は手順を会話文で説明する。複数の練習を並べない。
- **例外ケース**: 大きな課題が無い良い録音では、提案を強制せず「良かったね」で完結してよい（無理に stretch_target を出さない）。

### FR-03: 参考動画の会話内リンク化
- **概要**: 練習を提案する際、参考動画はカードではなく会話文中のリンクで渡す。
- **詳細仕様**: 動画提示は練習提案に付随する場合のみ。「この動画わかりやすいよ→<URL>」のように1行で添える。`PracticeCard` の動画ボタンは廃止。

### FR-04: スコア・カードの撤廃
- **概要**: スコア概念とカードUIを表示経路から除去する。
- **詳細仕様**:
  - frontend: `Bubbles.tsx` の `FeedbackCard`/`PracticeCard`/`JudgeCard`/`ProgressCard`/`DiagnosisCard` を新規メッセージで使わない。`isCard` 分岐を除去または無効化。
  - backend: `llm.build_session_context` のスコア注入（音程/リズム/表現/総合）を削除し、LLMが点数を喋れないようにする。
  - `answer_question` のスコア質問分岐は「点数はつけていない」方針の返答に変更。
  - 過去メッセージに残る旧カード型は、最小限のプレーンテキストにフォールバック描画する（履歴を壊さない）。

### FR-05: Web版とskill版のトーン統一
- **概要**: SKILL.md のFB出力を会話型に書き換え、Web版 `SYSTEM_PROMPT` と同じ作法に揃える。
- **詳細仕様**: SKILL.md の「評価軸（4スコア）」「出力フォーマット（Phase B巨大テンプレ等）」を、短い会話・1課題1提案の作法に置き換える。診断ロジック・解析パイプライン記述は残す。

## 6. 非機能要件
- **UX**: 1往復の標準返答は2〜4文。箇条書き・見出し・点数を出力に含めない。チャットのテンポを優先。
- **保守性**: 会話トーンの規律はWeb版・skill版で単一の方針を参照する（重複定義を増やさない）。
- **事実忠実性**: 既存の反ハルシネーション・ガード（`_scrub_invented_seconds` / `_scrub_lyrics` / 歌詞推測禁止）を維持。会話文化で具体性を上げても、与えられていない数値・秒数・歌詞は作らない。
- **互換性**: 既存セッション・既存DBデータを破壊しない。
- **性能**: 録音FBの応答時間は現状（解析＋LLMコメント合計の待ち上限 `llm_coach_wait_sec`）を超えない。カード生成が減る分、むしろ軽くなる。

## 7. 受け入れ基準
- **AC-01**: 録音を1つ送ったとき、coachの返答が原則テキスト1〜2吹き出しに収まり、標準的な返答が2〜4文である。
- **AC-02**: いかなる経路でも、出力に点数（NN/100）・◎○△×・指標数値の表が現れない。
- **AC-03**: 明確な発声課題が検知された録音では、練習法が1つだけ自然な会話で提案される。課題が無い録音・通常質問では練習法が提案されない。
- **AC-04**: 連続したやりとりで、直前までの会話文脈（録音の解析事実・前の発言）を踏まえた返答が返る。
- **AC-05**: 参考動画はカードではなく会話文中のリンクとして提示される。
- **AC-06**: Web版チャットとskill版で、返答のトーン（話し言葉・敬体）と文量（2〜4文）が一致している。
- **AC-07**: 既存セッションを開いても、過去の旧カードメッセージでUIが壊れず表示される。

## 8. 前提・制約
- マルチターン会話基盤（`ChatSession`/`ChatMessage`/`_history_for_llm`）は実装済みで流用する。
- 苦手検知（`voice_coach.diagnose`）・処方候補（`prescriptions_for`）は既存資産を流用する。
- 解析の数値は内部判断にのみ使用し、表示では点数・表にしない（会話中の秒数・位置の具体指摘は可）。
- `docs/12_要件追補_事実忠実性_反ハルシネーション.md` の制約を引き継ぐ。

## 9. 未決事項 / 要確認
- （確定済み）数値: 点数・表は撤廃、会話中の秒数・位置の具体指摘は可。
- （確定済み）過去カード: DB破壊せず、旧カード型はテキストにフォールバック描画。
- （確定済み）動画: カード廃止、会話内リンクで残す。
- （要デザイナー）旧カードのフォールバック表示の具体的見た目。
- （要アーキテクト）`practice`/`judge`/`progress` メッセージ型を「廃止」するか「内部的にtextへ変換」するかの実装方式。
