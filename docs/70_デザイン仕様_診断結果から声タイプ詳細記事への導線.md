## 3-2. 【改訂版】診断結果ビューの構成（SCR-01・ログイン済み）

```
<section ref={resultRef}>（result && auth === "in"）   ← FR-04: 診断完了時ここへ自動スクロール
  白カード: shareRef[VoiceTypeBlock] + ShareButtons     ← 変更なし
  アンカー: 「↓ {nameJa}のプロフィールを読む」          ← 新規 FR-05
  ボタン列: もう一度診断 / レッスンを受ける →            ← 変更なし
  補足文言: 「声タイプは傾向の推定です...」               ← 変更なし
  ── ここから新規 ──
  記事ヘッダ: 「{nameJa}のプロフィール」見出し（id="profile"・中央、font-rounded text-xl font-black）
  <VoiceTypeProfileArticle profile />                    ← 詳細ページと共有する記事本体
    ├ 導入（lede）
    ├ 目次チップ（アンカーは同一ページ内 #id）
    ├ 本文セクション ×N（SECTION 01.. + ソラ先生ポーズ6種）
    └ 有名人ラインナップ
  締めCTA: 夜のステージ調ブロック（FR-06）              ← 新規・読了直後の転換点
  記事末尾リンク: 「この記事を単独ページで開く →」= /voice-type/{typeId}（FR-03、text-xs テキストリンク）
</section>
```

### FR-04: 自動スクロールの挙動
- 発火: `result` && `auth !== "checking"` になった時点で、結果セクション先頭へ `scrollIntoView({ block: "start" })`。
- モーション: 既定は `behavior: "smooth"`。`window.matchMedia("(prefers-reduced-motion: reduce)")` が真なら `"auto"`（即時）にする。
- 意図: 結果カードを画面上部に固定することで、その下の「↓ プロフィールを読む」アンカーが自然に視界へ入る。

### FR-05: 記事へのアンカー
- 配置: 白カードの直下、ボタン列の**上**。中央寄せ。
- 文言: `↓ {nameJa}のプロフィールを読む`（例: 「↓ ミステリアスタイプのプロフィールを読む」）
- トーン: `text-xs font-bold text-brand-600` の下線付きテキストリンク。ボタン化しない（「レッスンを受ける」の優先度を侵さない）。
- 動作: `href="#profile"` で記事見出しへ。見出し側は `scroll-mt-4` でヘッダに潜らせない。

### FR-06: 読了後の締めCTA（コピー確定）
記事の最後（有名人ラインナップの直後）。**夜のステージ調**（`bg-stage grain` + `StageDecor`）でページ冒頭のヒーローと呼応させ、白い記事カードの連続を断ち切って「読み物の終わり／行動の始まり」を視覚的に示す。

- チップ: `ここまで読んでくれたあなたへ`
- 見出し: `その声を、磨きにいこう`（font-rounded text-2xl font-black）
- 本文: `{nameJa}の武器も、苦手も、もう分かりました。あとは、実際に歌ってみるだけです。あなたが歌った一曲をソラ先生が聴いて、{nameJa}の良さがいちばん出た瞬間と、もう一歩だったところを、具体的な言葉でお返しします。`
- ボタン: `ソラ先生のレッスンを受ける →` → `/coach`（白背景・brand文字の主要ボタン。暗いステージ背景の上でコントラストを確保）
- アバター: **頭部アバター（`CoachAvatar` の pose 無し）を使う**。理由: 全身ポーズ6種（singing/explain/cheer/clap/thinking/bow）は記事本文が全て使い切っており、docs/61 §3-6「ポーズはページ内で一意」に抵触するため。ヘッダ・ヒーローと同じ頭部表現なら衝突しない。
- コピーの根拠: `/coach` の実体は「曲を選んで、歌って、フィードバックをもらおう」。CTA本文はこの範囲を超えず、上達保証・期間・料金を主張しない（docs/69 FR-06 制約・AC-11）。

- **共有コンポーネント**: `frontend/src/components/voice/VoiceTypeProfileArticle.tsx`（新規）。
  `/voice-type/[typeId]/page.tsx` から lede・目次・本文セクション・有名人グリッドの描画を抽出し、詳細ページと診断結果ビューの両方がこれを使う。hooksなし（サーバー/クライアント両用）。
- **診断結果ビュー側の読み込み**: `VOICE_PROFILES`（約300KB）は結果表示後に動的import。読み込み中は何も出さない（スケルトン不要。上に結果カードが表示済みのため体感遅延なし）。失敗時・準備中タイプは記事ブロックごと非表示。
- **シェア画像**: `shareRef` の範囲は従来どおり `VoiceTypeBlock` のみ。記事はその外＝写り込みなし（AC-07）。
- **目次アンカーの重複回避**: 診断ページに記事を埋め込んでもセクション `id` はページ内で一意（記事は1タイプ分しか出さないため衝突しない）。
- **未ログイン**: 変更なし（記事なし・登録CTAのみ）。

## 3. 画面ごとの仕様

### SCR-01: 声タイプ診断（結果表示・ログイン済み）

**現状の構造**（[frontend/src/app/voice-type/page.tsx:204-232](../frontend/src/app/voice-type/page.tsx)）:
```
<section>
  <div class="rounded-2xl bg-white/90 p-4 shadow-card">   ← 白カード
    <div ref={shareRef}>                                   ← シェア画像化される範囲
      <VoiceTypeBlock />                                    タイプ名・スコア・似たアーティスト
    </div>
    <div class="mt-3">
      <ShareButtons />                                      Xシェア／画像保存（shareRef範囲外）
    </div>
  </div>
  <div class="flex gap-2">                                  ← 白カードの外、ボタン列
    もう一度診断 / レッスンを受ける →
  </div>
  <p>声タイプは「傾向」の推定です...</p>
</section>
```

**追加要素**: 白カード内、`ShareButtons` の下に「詳細記事リンク」を1行追加する。`shareRef` の外側なので画像化の対象外＝AC設計の「シェア画像に写り込まない」を追加コードなしで満たす。

```
<div class="rounded-2xl bg-white/90 p-4 shadow-card">
  <div ref={shareRef}>
    <VoiceTypeBlock />
  </div>
  <div class="mt-3">
    <ShareButtons />
  </div>
  <div class="mt-3 text-center">                             ← 新規
    <Link href={`/voice-type/${result.voice_type.id}`}
          class="text-xs font-bold text-brand-600 underline decoration-brand-200
                 underline-offset-2 transition hover:text-brand-700">
      {result.voice_type.name}についてもっと詳しく →
    </Link>
  </div>
</div>
```

- **文言**: `{タイプ名}についてもっと詳しく →`
  - 例: 「Mysterious Voiceについてもっと詳しく →」（`vt.name` は `VOICE_TYPE_META` の英語名。既存 `VoiceTypeBlock` 内表示 `{vt.name}` と同じ値を使い回す）
- **視覚トーン**: 下線付きテキストリンクのみ。ボタン化（角丸pill・3D押下影）は使わない。「レッスンを受ける」（`bg-brand-600` の主要ボタン、影付き）・「もう一度診断」（白背景secondaryボタン）より明確に一段弱いトーンにする。
  - フォントサイズ: `text-xs`（ボタン列の `text-sm` より小さい）
  - 色: `text-brand-600`（下線 `decoration-brand-200` で控えめに）。太字だが背景色なし。
- **配置**: 白カード内、`ShareButtons` の直下。`mt-3 text-center` で中央寄せ、他要素と同じ余白リズム（`mt-3`）を踏襲。
- **アクション**: クリックで `/voice-type/{result.voice_type.id}` へ遷移（Next.js `<Link>`、新規タブなし＝通常のページ遷移。詳細記事から診断ページへ戻れる導線は既存の詳細記事ページ側に委ねる）。
- **状態**:
  - 表示: `result` があり `auth === "in"` のときのみ。かつ `result.voice_type.id` が `VOICE_TYPE_LIST` に存在する場合のみ（FR-01例外ケース）。存在しないidの場合はこの`<div>`ごと非表示。
  - loading / empty / error: 該当なし（結果表示後の静的リンクのため、このリンク自体に非同期処理はない）。
- **未ログイン時（SCR-01のぼかしカード表示）**: 変更なし。詳細記事リンクは追加しない（FR-02）。既存の「無料登録して結果を見る」CTAのみ維持。

## 5. デザイントークン
- フォント: `text-xs font-bold`（既存の補足文言 `text-[11px] text-slate-400` より一段強いが、ボタンの `text-sm font-bold` より弱い中間トーン）
- 色: `text-brand-600` / hover `text-brand-700` / `decoration-brand-200`（下線色を薄くしてリンクの主張を抑える）
- スペーシング: `mt-3`（既存の `ShareButtons` ラッパーと同じリズム）
- 角丸・影: なし（テキストリンクのため）

## 6. アクセシビリティ要件
- `<Link>` はネイティブ `<a>` としてレンダリングされるため、キーボードのTab移動・Enter遷移は標準対応。
- `focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-brand-400` を付与し、既存ボタン群と同じフォーカスリング表現に揃える。
- コントラスト比: `text-brand-600` on `bg-white/90` は既存の同系色ボタン文言と同水準（既存パターン踏襲のため新規検証不要）。
- リンクテキストに `{タイプ名}` を含めることで、スクリーンリーダー利用者にもリンク単体で遷移先が推測できる（「詳しく →」のみの曖昧なリンクテキストを避ける）。

## 実装メモ（frontend-engineer向け）
- 変更ファイルは `frontend/src/app/voice-type/page.tsx` の1箇所のみ（204-232行付近）。新規コンポーネント作成は不要。
- `result.voice_type.id` が `VOICE_TYPE_LIST`（`frontend/src/components/voice/voiceTypes.ts`）に含まれるかの存在チェックを追加すること（AC-05 / FR-01例外ケース）。
- `shareRef` の範囲を広げない（現状のまま `VoiceTypeBlock` のみを囲む）こと＝このリンクが誤ってシェア画像に写り込まないようにする最重要ポイント。
