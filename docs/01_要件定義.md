# 録音した歌へのフィードバック機能 要件定義書

## 1. 目的
- ユーザーが自分の歌声を録音またはアップロードし、ボーカルトレーナー視点のフィードバックを受け取れるWebアプリを提供する。
- 継続練習を支援するため、評価履歴を保存し、改善ポイントを可視化する。

## 2. 想定ユーザー
- 独学で歌を練習している初心者〜中級者
- ボーカルレッスン前後で客観的な確認をしたいユーザー

## 3. 提供価値
- 音程、リズム、発声の観点で簡易評価を取得できる
- 改善アドバイスを日本語テキストで受け取れる
- 過去の録音結果と比較して成長を確認できる

## 4. スコープ
### 4.1 MVP対象
- ユーザー登録・ログイン
- 音声ファイルアップロード（wav/mp3/m4a）
- 録音1件ごとの自動評価（スコア + コメント）
- 評価履歴一覧・詳細表示

### 4.2 MVP対象外
- リアルタイム採点
- 楽曲ごとの著作権管理
- 講師とのチャット機能
- 決済機能

## 5. 機能要件
### FR-01: 認証機能
- メールアドレスとパスワードで登録・ログインできること
- 認証済みユーザーのみ録音評価機能を利用できること

### FR-02: 録音データ管理
- ユーザーは音声ファイルをアップロードできること
- アップロードした音声にタイトル、メモを付与できること

### FR-03: 自動評価
- バックエンドで音声解析を行い、以下を算出すること
  - pitch_score（音程）
  - rhythm_score（リズム）
  - expression_score（表現）
  - total_score（総合）
- 解析結果に基づく日本語フィードバック文を生成すること

### FR-04: 履歴閲覧
- ユーザーは自分の評価履歴一覧を閲覧できること
- 1件の評価詳細（スコア内訳、コメント、作成日時）を確認できること

## 6. 非機能要件
### NFR-01: 性能
- 10MB以内の音声ファイルで、評価完了まで30秒以内を目標とする

### NFR-02: 可用性
- Docker環境でローカル開発・検証が可能であること

### NFR-03: セキュリティ
- パスワードはハッシュ化して保存すること
- 認可チェックにより他ユーザーのデータへアクセス不可とすること

### NFR-04: 保守性
- フロントエンドとバックエンドを明確に分離すること
- DBスキーマ変更はAlembicマイグレーションで管理すること

### NFR-05: エラー時のユーザー体験
- 認証エラー発生時は、ユーザーに理由を明示しログイン画面へ誘導すること
- 解析失敗や通信エラー時は、ユーザーが把握しやすいメッセージとともに再試行手段を提供すること
- 同一録音に対する自動評価の再試行回数は最大3回までとすること

## 7. 受け入れ基準
- ユーザーがログイン後、音声をアップロードして評価結果を閲覧できる
- 評価結果がDBに保存され、再アクセス時にも表示される
- 他ユーザーの録音履歴が見えない

## 8. 前提・制約
- 技術スタックは以下に固定する
  - Frontend: Next.js + TypeScript + Tailwind CSS
  - Backend: Python + FastAPI
  - DB: MySQL + SQLAlchemy + Alembic
- 設計書を `docs/` に作成した後に実装着手する
