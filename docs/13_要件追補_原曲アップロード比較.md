# 要件追補：原曲アップロード比較（音程の正確さ・リズムの主経路化）

## 1. 概要
- ユーザーが「お手本（原曲）の音源」をセッションにアップロードできるようにする。
- 以降その曲の録音は、原曲とDTWで整列し、**音程の正確さ（音を外していないか＝in-tune）** と
  **リズムの走り／モタり** を実測してフィードバックする。
- これにより、従来「原曲が無いと厳密に判定できない」としていた音程の正確さ・リズムを、
  **原曲がある場合は実測値を主経路（主成分）** として扱う。

## 2. 背景・課題
- 既存FBでは、録音単体だと「音程の安定度（揺れの少なさ＝ジッター）」しか出せず、
  「原曲のメロディに対して音を外していないか（正確さ）」は断定できなかった。
- 「安定度」と「正確さ」は別物。安定して外し続けても安定度は高く出てしまう。
- 精度向上の本丸として、原曲との照合で正確さ・リズムを実測する。

## 3. スコープ
### 3.1 対象（やること）
- 原曲音源のアップロード用エンドポイント／UI。
- DTWワーピングパスに沿った f0 比較による in-tune 実測（キー差は除外）。
- FBカード（実測値テーブル）への「原曲との一致（音程の正確さ）」行の追加。
- コーチ講評（自然文）で、原曲がある時は in-tune・リズムを実測値で語る。
- 音程スコアを、原曲がある時は in-tune 実測を主成分（7:3）に切替。

### 3.2 対象外（やらないこと）
- 歌詞・発音の原曲一致判定（発音は別機能 `pronunciation`）。
- 伴奏ありミックスからの高精度ボーカル抽出（軽量声分離のみ）。
- 原曲を大きく違うキー／オクターブで歌った場合の補正（同キー歌唱を前提）。

## 4. 機能要件
### FR-01: 原曲アップロード
- `POST /api/v1/coach/sessions/{id}/reference`（multipart `audio_file`）。
- 対応形式・サイズ上限は録音アップロードと同じ。`song_ref_path` に WAV 変換して保存。
- 受領後、コーチが確認メッセージを返す。`SessionDetail.has_reference=true` を返す。

### FR-02: 原曲との照合（in-tune／リズム実測）
- 曲の録音受信時、`song_ref_path` か `song_ref_url` があれば（フェーズ非依存で）常に比較。
- `alignment` に以下を付与：
  - `in_tune_score`（0-100）: 原曲メロディとの一致度。
  - `pitch_error_cents`（MAD・中央絶対偏差）: ビブラート等の外れ値に強い。
  - `off_pitch_ratio`: 明らかに別の音（>80cents）に外れている割合。
  - `mean_lag_sec` / `worst_segments`: リズムの走り／モタり（既存）。
- 全体の移調（キー差）は中央値で除去してから比較する。

### FR-03: フィードバック反映
- FBカードに「原曲との一致（音程の正確さ）= N点（ズレ平均 M cents）」を表示。
- 講評では、in-tune が低め（<65点）のとき音程ズレを最優先で具体的に触れる。
- 音程の「安定度（揺れ）」と「正確さ（外していないか）」を混同しない。

## 5. 非機能要件
- 追加のf0抽出（pyin×2）で解析時間が数秒増えるが、原曲ありセッション限定。
- 原曲が無い／対応が取れない場合は実測値を出さず、断定もしない（反ハルシネーション）。

## 6. 受け入れ基準
- AC-01: 原曲をアップロードすると `has_reference=true` になり、確認メッセージが返る。
- AC-02: 原曲セット後に曲の録音を送ると、FBカードに「原曲との一致」行が出る。
- AC-03: 明らかに音を外したテイクは in-tune スコアが下がり、正確なテイクは高く出る（単調性）。
- AC-04: 原曲が無いセッションでは「原曲を送れば正確に見られる」と案内し、正確さ・リズムを断定しない。
- AC-05: 講評で「安定度」と「正確さ」を取り違えない。

## 7. 前提・制約
- 原曲に合わせて**同じキー**で歌うこと（大幅な移調はchroma整列が崩れる）。
- 軽量声分離のため、強い伴奏ミックスでは精度が落ちうる。
