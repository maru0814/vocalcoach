# リリース告知メルマガ 機能要件書

- 文書番号: 88
- 作成日: 2026-08-01
- 作成: PdM
- 関連: docs/84〜87（ウェルカムメール）, docs/86（メール文面正本）, docs/17（LP）
- 発端: 運用者要望「新規リリースをメールで既存ユーザーに訴求したい」（2026-08-01）

## 1. 概要
- 新機能リリース等のお知らせメールを、**同意（オプトイン）した会員だけ**に一斉配信できるようにする。
- 解決する課題: リリースしても既存ユーザーに知らせる手段がWeb Push購読者向けしかなく、メールでしか届かない層に再訪のきっかけを作れない。

## 2. 想定ユーザー / ユースケース
- 受信者: 登録済み会員のうち、お知らせ受信に同意した人。
- 運用者: リリース時に告知文を用意し、コマンド1発で配信する丸山さん。
- 主要ユースケース: 新機能リリース → 運用者が件名・本文を用意してバッチ実行 → 同意済み会員に届く → メール内リンクからサービスに再訪。

## 3. スコープ
### 3.1 対象（やること）
- 新規登録時のオプトイン取得（チェックボックス）
- 既存会員が設定画面でオプトイン/オフを切り替えられるトグル
- メール内ワンクリック配信停止（ログイン不要）
- 一斉送信バッチ（運用者の手動実行・再実行安全）
- 特定電子メール法対応（同意・送信者表示・配信停止手段）

### 3.2 対象外（やらないこと）
- 配信管理画面・HTMLエディタ（文面はファイルで渡す）
- 開封率・クリック率の計測基盤（クリックは既存の src= パラメータ方式で日次レポートに乗せられる）
- セグメント配信・予約配信・A/Bテスト
- ステップメール（複数通のシナリオ配信）

## 4. ユーザーストーリー
- US-01: 会員として、興味のある新機能のお知らせだけ受け取りたい。要らなくなったら1クリックでやめたい。
- US-02: 運用者として、リリースのたびに法的リスクなく・無料枠内で・二重送信の心配なしに告知を送りたい。

## 5. 機能要件

### FR-01: オプトイン取得（新規登録）
- 登録フォームに「新機能・お知らせメールを受け取る」チェックボックスを置く。**既定はON**（プリチェック）。ただしラベルで内容を明示し、ワンタップで外せること。
- API `POST /auth/register` は `newsletter_opt_in: bool`（省略時 false）を受け、users に保存する。
- 例外: チェックを外して登録した場合、お知らせメールは一切送られない（ウェルカムメールは登録通知なので従来どおり送る）。

### FR-02: 配信対象
- `newsletter_opt_in = true` の実会員のみ（`@example.com` のテストアカウントは常に除外）。
- 同意のない既存会員には送らない（同意打診メールも送らない＝それ自体が広告宣伝メールと解釈されるリスクがあるため）。既存会員の同意は設定画面（FR-03）で取得する。

### FR-03: オプトイン変更（設定画面）
- 設定画面に「お知らせメール」トグルを追加。現在値の表示と ON/OFF 切替ができる。
- API: 認証済みユーザーが自分の opt_in を取得・更新できること。

### FR-04: ワンクリック配信停止（メール内・ログイン不要）
- お知らせメールのフッターに配信停止リンクを必ず入れる。
- リンクは推測不能なトークン付きURL。開くだけで opt_in=false になり、「配信停止しました」を表示する。ログイン不要。
- トークンが無効でもエラー画面で完結し、個人情報を漏らさない。

### FR-05: 一斉送信バッチ（手動・冪等）
- 運用者がVPS上で実行するCLI: 件名・本文（テキストファイル）・**campaign_key**（例: `release-2026-08-html-mail`）を渡す。
- **冪等性**: 送信済み（user_id × campaign_key）を記録し、再実行しても同じ人に二重送信しない。途中失敗→再実行で続きから送れる。
- DRY_RUN で対象者数と本文プレビューだけ確認できる。
- 1実行の送信上限は250通（Brevo無料枠300/日の安全マージン）。超過分は翌日の再実行で続きから（冪等性により自然に実現）。

### FR-06: 法的表示（特定電子メール法）
- フッターに: 送信者名義・連絡先メールアドレス・配信停止リンク。
- 件名に虚偽・誇大表現を使わない（docs/17 の誇大表現禁止と同じ規律）。

### FR-07: ログ
- バッチ実行ごとに 送信成功/失敗/スキップ（送信済み・停止済み）件数をログと標準出力に出す。

## 6. 非機能要件
- コスト: 月額0円（Brevo無料枠内。FR-05の上限で保証）
- セキュリティ: 配信停止トークンは暗号学的乱数（32byte以上）。URLに個人情報を含めない。
- 保守性: 送信処理はウェルカムメールと同じ `mail_service` を共用。文面の正本は docs/ に残す。
- 互換性: マイグレーションは既存ユーザーを opt_in=false で初期化（勝手に同意扱いしない）。

## 7. 受け入れ基準
- AC-01: チェックONで登録 → users に opt_in=true と配信停止トークンが保存される。
- AC-02: チェックOFF（またはAPI省略）で登録 → opt_in=false。バッチ対象にならない。
- AC-03: 設定画面トグルで ON→OFF / OFF→ON が反映される（API経由で検証可）。
- AC-04: 配信停止リンクを開くと opt_in=false になり、完了画面が出る。無効トークンでも500にならない。
- AC-05: バッチは opt_in=true の実会員だけに送り、同一 campaign_key の再実行で二重送信しない。
- AC-06: 1実行の送信は250通で打ち切られ、再実行で続きから送られる。
- AC-07: DRY_RUN では1通も送らず、対象者数が表示される。
- AC-08: メールフッターに送信者名義・連絡先・配信停止リンクがある。
- AC-09: メール未設定環境（MAIL_API_KEY なし）ではバッチが送信せずスキップ終了する。

## 8. 前提・制約
- 送信基盤は既存の Brevo（docs/85）。差出人 `MAIL_FROM_ADDRESS` も共用。
- 配信停止リンクは backend のAPIで受ける（フロントの新画面は作らない。APIが簡易HTMLを返す）。
- 告知文面はリリースごとにマーケターが作成し docs/ に残す（本要件はパイプのみ）。

## 9. 未決事項 / 要確認
- プリチェック（既定ON）の是非: 総務省ガイドライン上、内容が容易に認識できる表示なら有効と判断してプリチェックを採用。問題視する場合は既定OFFへ1行変更で対応可。
- 将来、配信数が増えたら Brevo のキャンペーン機能（管理画面配信・開封計測つき）への移行を検討。
