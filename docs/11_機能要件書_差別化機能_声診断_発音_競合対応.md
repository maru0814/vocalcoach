# 差別化機能（声診断・発音アドバイス・4軸FB）機能要件書

関連: `docs/05_機能要件書_チャットWebアプリ.md` / `docs/09_機能要件書_ユーザー主導フロー.md` / `docs/10_機能要件書_対話駆動フロー.md`（本書はこれらを前提に追記する）
対応実装: PR #1〜#4（main 反映済み）

## 1. 概要
- 競合 **Voick**（モバイルのボイトレアプリ）を踏まえ、自社「AIボーカルトレーナー ソラ先生」（チャットWebアプリ）の**差別化機能**を定義する。
- 解決する課題: Voickは「可視化・採点」中心。我々は**対話型LLMコーチ**＋**発音/歌い回しまで踏み込んだ講評**で差別化する。クローンはしない。
- 本書で正式化する機能: ①声診断カード ②発音アドバイス ③4軸バランスFB（秒数必須・必ず改善点） ④録音の曲/基礎練 自動判定 ⑤最新録音参照。

### 競合分析（Voick vs ソラ先生）
| Voickの機能 | 自社対応 | 方針 |
| --- | --- | --- |
| リアルタイム採点(6段階・ライブマイク) | 録音後解析 | Later（追わない） |
| セント単位ピッチ可視化 | 数値あり/グラフ無し | Next |
| 講師/原曲の声と比較 | DTW比較(任意)＋発音比較 | Now/Next |
| 声診断(音域/ロングトーン/ビブラート種別/音程精度) | **実装済**（FR-01） | Now ✅ |
| 録音保存/成長管理/過去比較 | セッション保存・改善判定 | Now ✅ |
| 楽譜＋歌詞の声区色分け | 無し | Later |
| レッスン集(50+) | 課題別基礎練 | Next |
| 無料/プレミアム | 無料のみ | Later |
| （Voickに無い）対話型LLMコーチ | **実装済** | 差別化 ✅ |
| （Voickに無い）発音・歌い回しの講評/原曲比較 | **実装済**（FR-02） | 差別化 ✅ |

### ロードマップ（CEO決定）
- **Now（実装済）**: 声診断カード／発音アドバイス／4軸バランスFB／自動判定／最新録音参照
- **Next**: ピッチ時系列グラフ／原曲アップロードでの発音・音程比較UX／基礎練レッスン拡充／進捗ダッシュボード
- **Later**: リアルタイム採点／楽譜＋声区色分け／オリジナルレッスン作成／プレミアム課金

## 2. 想定ユーザー / ユースケース
- ペルソナ: 独学でカラオケ上達を目指す初〜中級者。ゴールは「カラオケで上手に歌えること」。
- UC-1: 録音を送ると、声診断（音域・声質など）と4軸の講評（良い点＋改善点）が秒数つきで返る。
- UC-2: 「発音を見て」と頼むと、ソラ先生が実際に音声を聴いて発音・歌い回しを講評する（原曲があれば比較）。
- UC-3: 種類を選ばずに録音を送るだけで、曲か基礎練かを自動判定して適切に扱う。

## 3. スコープ
### 3.1 対象（やること）
- 既算出指標の声診断カード化（FR-01）。
- Gemini音声入力による発音アドバイス（FR-02）。
- 4軸バランスFB＋秒数必須＋必ず改善点（FR-03）。
- 録音の曲/基礎練 自動判定（FR-04）、最新録音参照（FR-05）。

### 3.2 対象外（やらないこと）
- リアルタイム採点・楽譜表示・声区色分け・オリジナルレッスン作成・課金（Later）。
- 解析・採点・弱点診断のLLM化（コスト・客観性のため不可。発音FBのみ音声をLLMに渡す）。
- 歌詞の自動採譜・正確な歌詞文字起こし（歌唱ASRは不正確なため断定しない）。

## 4. ユーザーストーリー
- US-01: ユーザーとして、自分の声の特徴（音域・声質・ロングトーン等）を一目で知りたい。上達の現在地を把握したいから。
- US-02: ユーザーとして、発音や歌い回しを原曲と比べて教えてほしい。カラオケで「っぽく」歌いたいから。
- US-03: ユーザーとして、良い点だけでなく必ず「次に直す点」を具体的に知りたい。練習につなげたいから。
- US-04: ユーザーとして、録音の種類をいちいち選びたくない。手間なく送りたいから。

## 5. 機能要件

### FR-01: 声診断カード
- 概要: 既に算出済みの指標を Voick 風の「声診断」カードに可視化する。
- 詳細仕様: 行＝{label, value, hint}。表示項目:
  - 声域（おおよそ／出せている音の範囲、音名）
  - 使っている声（地声／ミックス／裏声）
  - いちばん長い伸ばし（秒・音名）
  - 伸ばしの安定度（cents、30以下が目標）
  - 声の響き＝**整数次倍音**（豊か＝クリアで通る声／ほどよい／息まじり＝柔らかい声）
  - ビブラート（秒N回・深さcents、4〜7回が自然）
  - 音程の正確さ（cents、5以下プロ級/15以下上手）
- 入出力: 入力＝解析dict。出力＝`diagnosis` 型カード payload。曲の診断時に分析カードと並べて表示。
- 例外: 該当データが無い指標は「—」または非表示。

### FR-02: 発音アドバイス（Gemini音声入力）
- 概要: 最新の録音音声そのものを Gemini に聴かせ、発音（母音の口の開き・子音の立て方・滑舌・歌い回し）を講評する。
- 詳細仕様:
  - 起動: テキストに発音系キーワード（発音/滑舌/母音/子音/歌詞の言い 等）を含む、または「🗣 発音を見る」チップ押下。
  - 原曲（`song_ref_path`）があれば原曲音源も渡して**比較**。無ければ自分の発音単体FB＋「原曲を用意すれば比較できます」と案内。
  - 歌唱は歌詞を正確に聞き取れないことがあるため、**歌詞そのものは断定せず**発音の質に集中させる。
  - モデル: 音声対応の `gemini-2.5-flash`（`llm_audio_model`）。テキスト対話の `gemini-flash-lite-latest` とは別。
- 入出力: 入力＝最新録音wav（＋原曲wav任意）。出力＝コーチのテキスト返答。
- 例外: 録音が無ければ「まず録音を送って」。APIキー未設定/失敗時は丁寧なエラー文（ハルシネーションしない）。

### FR-03: 4軸バランスFB（秒数必須・必ず改善点）
- 概要: 単一課題に偏らず、発声・リズム・音感・表現の4観点でバランスよく講評する。
- 詳細仕様:
  - 4軸スコア＋良かった点＋気になる点（観点つき・各秒数つき、最大3件）を根拠に講評。
  - **良い点だけで終わらせず、必ず「もっと良くできる点」を最低1つ**、秒数や数値を添えて提示（弱点が無い録音でも `_stretch_hint` で具体提示）。
  - 音量の上下は表現（ダイナミクス）として尊重し欠点化しない。原曲が無いときはリズム/音程の正確さは断定しない。
  - **録音の長さを超える秒数（時刻）は言わない**（解析の秒数は録音長にクランプ済み）。
- 例外: LLM未設定/失敗時はルールベースのテンプレ文にフォールバック。

### FR-04: 録音の曲/基礎練 自動判定
- 概要: 送信種類トグルを廃止し、音声特徴（音数・音域）から曲/基礎練を自動判定（`classify_kind`）。
- 詳細仕様: 異なる音が3つ以下かつ音域4半音以下＝基礎練、それ以外＝曲。誤判定の害（「達成おめでとう」誤発火）を避けるため**曲寄りにバイアス**。フロントは常に `auto` 送信。

### FR-05: 最新録音参照
- 概要: 会話の根拠は常に「いちばん最後に送られた録音」を最優先で参照する。
- 詳細仕様: `last_analysis` カラム（migration `b2f1a7c9d3e4`）に毎回の録音解析を保存。LLM文脈は `last_analysis`→無ければ `baseline_analysis`。

### FR-06: 未登録トライアル動線（アハ→登録）
- 背景: docs/35 課題1・docs/48 論点1 の裁定。価値（声タイプ）を見せる前に登録を要求すると入口KPI（登録率・診断完了率）を最も毀損する。
- 概要: **未登録（未ログイン）でも声タイプ診断を1回完走できる**。結果は非開示（ぼかし）で提示し、**「結果を見る／シェアする／保存する」の瞬間に無料登録へ誘導**する。
- 詳細仕様:
  - `POST /api/v1/voice-type/analyze` は認証任意（未ログインでも実行可）。濫用対策として未登録はIP単位でレート制限（`rate_limit_max_audio`/`rate_limit_window_sec`）。
  - フロントは未ログイン時、結果カードを `blur` で隠し、登録CTA（`/login?next=/voice-type`）を重ねる。シェアボタン・レッスン導線はログイン後に開放。
  - 診断イベント（`voice_type_diagnoses`）はPIIを持たない（type_id・score・時刻のみ）。
- 入出力: 入力＝録音1本。出力＝`VoiceTypeResult`（未ログインはフロントで非開示表示）。
- 例外: 解析失敗（NO_VOICE/422 等）は既存どおり。401は返さない（匿名許可）。
- 実装: PR #107（`backend/app/deps.py` `get_current_user_optional` / `voice_type.py` / `voice-type/page.tsx`）。

## 6. 非機能要件
- 性能: 通常FB・対話は短文（max 400トークン）。発音FB（音声入力）は1往復・数十秒以内（`llm_audio_timeout_sec=60`）。
- コスト: 対話は無料枠の Flash-Lite。発音FBのみ Flash（音声対応）で割高なため**任意起動**（依頼時のみ）。
- 客観性: スコア・弱点診断・声診断の数値は決定論（LLMに数値を作らせない）。発音FBは音声を聴いた所見。
- 可用性: `GEMINI_API_KEY` 未設定・LLM障害時もルールベースで機能継続。
- 保守性: 解析(analyzer)／診断(taxonomy)／会話(llm)／進行(rule_engine)の責務分離を維持。

## 7. 受け入れ基準
- AC-01: 曲を送ると声診断カードが表示され、整数次倍音を含む各行が出る。
- AC-02: 「発音を見て」で、音声を聴いた発音講評が返る（原曲が無ければ提出を促す一文が付く）。
- AC-03: どの録音FBも、良い点に加えて「もっと良くできる点」を1つ以上、秒数や数値つきで含む。
- AC-04: 録音長を超える秒数（時刻）をコーチが言わない（12秒の録音で13秒等が出ない）。
- AC-05: 未登録でも声診断が1回完走でき、`analyze` が401を返さない。結果は非開示（ぼかし）＋登録CTAで提示され、登録後にフル結果とシェアが開放される（FR-06）。
- AC-05: 送信種類を選ばずに録音を送っても、曲/基礎練が自動判定され適切に処理される。
- AC-06: 新しい録音を送った後の質問が、最初の録音でなく最新録音を根拠に答える。
- AC-07: `GEMINI_API_KEY` 未設定でも、声診断・4軸FB・自動判定はルールベースで動作する（発音FBは「今は使えない」旨を返す）。

## 8. 前提・制約
- 既存基盤（`docs/05/07`、analyzer、taxonomy、llm、rule_engine）を流用。
- DB追加は `last_analysis`（JSON）のみ。**デプロイ時に `alembic upgrade head` が必要**。
- 発音FBは音声対応モデルを使うため、本番でも `GEMINI_API_KEY` と `llm_audio_model` 設定が前提。
