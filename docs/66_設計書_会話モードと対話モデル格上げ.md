# 会話モードと対話モデル格上げ 設計書

関連: `docs/42_FB品質基準_単一ソース.md`（§2.1 会話モード）/ `docs/65_設計書_提案済み練習の文脈注入.md` / `scripts/soar_eval/reports/REPORT_naturalness.md` / `REPORT_chatgpt_h2h.md`
実装先: `backend/app/core/config.py`, `backend/app/coaching/llm.py`（DB変更なし）

## 1. 背景（評価で確定した問題）
「話が噛み合う（ChatGPTレベル）」を満たせているかを、同一ユーザー発言・同一facts・同一反ハルシネーション制約の下で **ソラ先生(Gemini flash-lite) vs ChatGPT級(Claude)** の**ブラインド head-to-head** で検証したところ、**Claude級が18勝0敗**（噛み合いスコア 5.3 vs 8.3）。差は情報でなく**会話力**。内訳:
- **テンポ不一致**: 「うん」「へー」等の短い相槌に毎回100〜160字の講義（自然さ 4.8/10、120字超76%）。
- **押し付け**: 雑談・感情を必ず「録音送って/練習メニュー一緒に作りましょうか」へ引き戻す。
- **感情の汲み取り不足**: 「もうやめようかな」に即データ＋練習誘導、共感を飛ばす。

原因は2つ: ①**モデル格**（flash-lite は最安クラスで雑談・感情・テンポが弱い）②**プロンプト設計**（段階的エンゲージメントが"常に前進"に効きすぎ、雑談まで練習誘導になる）。

## 2. 打ち手（2施策）

### 施策1: 対話ターンのモデル格上げ（試行→既定では不採用・env オプションとして残置）
| 項目 | 内容 |
| --- | --- |
| 追加設定 | `config.llm_chat_model`（`_complete`/`_complete_with_tools` に `model` 引数を追加し会話パスから渡す） |
| 適用範囲 | 会話返答 `generate_reply` と会話コメント生成。分析ターン・レポート生成は従来のまま |
| **測定結果（2026-07-12）** | 2.5-flash で before/after: カジュアル/感情の噛み合い 4.8→**5.8（改善）**、多ターン 6.5→**5.2（悪化）**、自然さ 147字→40字、コスト**3倍**。ChatGPT級との blind head-to-head は 18–0→**17–1**（僅かに接近だが未到達） |
| **判断** | 多ターン悪化＋コスト増が見合わないため、**既定は flash-lite 据え置き**（`llm_chat_model = llm_model`）。プロンプト側（施策2 会話モード）だけ採用。必要時は env `LLM_CHAT_MODEL=gemini-2.5-flash` で格上げ可 |
| 副産物（恒久修正） | 格上げ試験で `_complete_with_tools` の thinking 無効化漏れによる**返答途中切れ**を発見・修正（thinking_budget=0 を追加）。flash-lite でも安全側 |

### 施策2: 会話モード（プロンプト＋決定論の事実注入）
docs/65 と同じ「照合可能な事実を注入する」パターンを踏襲。
- **(a) プロンプト（SSOT docs/42 §2.1 → SYSTEM_PROMPT → SKILL.md）**: 短い相槌・雑談・挨拶はコーチングに変換せず1〜2文で受ける／感情はまず共感／定型の連発禁止／明示的な練習依頼の時だけコーチングに入る。
- **(b) 決定論の会話モード検出（`llm._detect_conversation_mode`）**: 直前ユーザー発言が
  - 感情の吐露（`_EMOTION_RE`: 落ち込む/やめたい/緊張/最悪/才能ない 等）→ `"emotion"`（最優先）
  - 明示的コーチング依頼（`_EXPLICIT_REQUEST_RE`: 練習/どうすれば/教えて/コツ/見て 等）→ 対象外（None）
  - 相槌語（`_AIZUCHI`）または 記号除き12字未満の短文 → `"casual"`
  該当時、`_build_contents` が「# 会話モード: 講義に変換せず1〜2文で自然に受ける。練習・録音誘導を付けない（emotionはまず共感）」を文脈注入する（`build_session_context` は不変）。

## 3. アーキテクチャ判断
- **なぜ Gemini 2.5-flash で Claude でないか**: 新プロバイダ（Anthropic キー）導入・課金・運用を避け、既存 Gemini スタックの中で一段上げる MVP。head-to-head の「ChatGPT級」は到達目標の基準であり、まず 2.5-flash で噛み合いがどれだけ改善するかを同一ハーネスで測ってから、必要なら上位（2.5-pro / 他社）を検討。
- **なぜ会話モードを決定論注入でも行うか**: プロンプトだけでは flash 系が「常にコーチング」に流れやすい（docs/65 と同じ教訓）。短い/相槌/感情は決定論で判定できるので、事実として与える方が確実。
- **後方互換**: API・DB・スキーマ変更なし。全て env でロールバック可（`LLM_CHAT_MODEL`、会話モードは検出関数が None を返せば従来動作）。

## 4. テスト方針
- 単体（`backend/tests/test_proposed_practices.py` に追加）: 会話モード検出（相槌・感情・短文・明示依頼の除外・長文の除外）、注入行が最終プロンプトに入る、`llm_chat_model != llm_model`、`_complete` の model 引数。
- E2E: 自然さコーパス（`cases_naturalness.py`）＋ head-to-head を before/after 同一測定。合格の目安＝120字超率・「一緒に」率・自然さスコアの改善、head-to-head 勝率の改善。

## 5. 限界・残課題
- モデル格上げは**コスト増**。月次予算（`llm_monthly_budget_jpy`）への影響は運用で監視。
- 2.5-flash でも ChatGPT級に完全一致するとは限らない。到達度は head-to-head 再測で確認する。
