# コーチFBへのフィードバック＆改善ループ 設計書

## 1. 目的
ソラ先生（AI）の回答が間違っていたとき、**ユーザーがその場で指摘**でき、それを
**蓄積→運営がレビュー→プロダクト改善**へつなげる仕組みを作る。

## 2. 「学習に活かす」の正直な定義（誇張しない）
本機能は**リアルタイムの自動学習（LLMの即時ファインチューニング）ではない**。
Gemini を会話に使う構成では即時学習は行わない。実際に回るのは次のループ:

```
① ユーザーがコーチの返信に 👍 / 👎（＋「何が違った？」）を送る
② 文脈ごと（メッセージ本文・その時の解析サマリ・ユーザーのコメント）を蓄積
③ 運営が定期レビューし、誤りの種類に応じて改善:
   - 事実誤り/言い回し  → SYSTEM_PROMPT・ルールエンジンの指示を改善
   - 声診断(声区など)の誤り → 正しいラベルで較正データ(data/register/)へ → ハーネスで再較正
   - しきい値由来の誤り   → REGISTER_THRESHOLDS 等の数値を見直し
④ 改善をリリースし、再び①へ
```

将来的に、蓄積データは few-shot 例の選定や評価セット(eval)にも使える。

## 3. スコープ
### 3.1 やること（MVP）
- コーチの**テキスト返信**に 👍/👎。👎時は任意で理由カテゴリ＋自由コメント。
- 1メッセージ×1ユーザーにつき1件（再送は上書き）。
- 文脈スナップショット（返信本文・直近解析のサマリ）を一緒に保存。
- 運営用の**エクスポート/集計スクリプト**（CSV/JSON、👎優先・カテゴリ集計）。
### 3.2 やらないこと
- 自動ファインチューニング／オンライン学習。
- 管理画面UI（当面はスクリプトで足りる。一人会社）。
- 他ユーザーのFB閲覧。

## 4. データモデル（新規 `message_feedback`）
| カラム | 型 | 説明 |
| --- | --- | --- |
| id | int PK | |
| message_id | FK chat_messages | 対象のコーチ返信 |
| session_id | FK chat_sessions | |
| user_id | FK users | |
| rating | str(8) | "up" / "down" |
| reason | str(32) NULL | down時の分類: fact(事実誤り)/irrelevant(見当違い)/rude(失礼)/other |
| comment | text NULL | 「何が違った？」自由記述 |
| context | JSON NULL | {message_excerpt, analysis_summary} スナップショット |
| created_at | datetime | |

マイグレーション: head `b2f1a7c9d3e4` の次に追加。

## 5. API
- `POST /coach/sessions/{sid}/messages/{mid}/feedback`
  - body: `{ rating: "up"|"down", reason?: str, comment?: str }`
  - 認可: セッション所有者のみ。対象は role="coach" のメッセージのみ。
  - upsert（同一 user×message は1件、更新可）。
  - 返り: `{ ok: true }`
- 運営用は CLI（`tools/export_feedback.py`）でDBから出力。エンドポイントは作らない。

## 6. フロントUX
- コーチのテキスト吹き出しの下に小さく 👍 / 👎。
- 👎押下で、理由チップ（事実が違う／見当違い／その他）＋一行コメント欄を展開。
- 送信後「ありがとうございます。改善に役立てます🙏」を表示。送信済みは状態保持。
- 解析カード(feedback/diagnosis等)は対象外（まずはテキスト返信に限定）。

## 7. 受け入れ基準
- AC-1: 👍/👎が送れて `message_feedback` に保存される（context付き）。
- AC-2: 👎で理由・コメントを付けて送れる。再送で上書き（重複行が増えない）。
- AC-3: 他人のセッション/メッセージにはFBできない（404/403）。
- AC-4: `export_feedback.py` で👎・コメント・カテゴリ集計が出力できる。
- AC-5: 既存フローに影響なし（FB任意・未送信でも従来通り）。

## 8. 運用（改善ループの回し方）
- 週次/月次で `export_feedback.py` を実行 → 👎を分類。
- 多い誤りから順に Prompt/ルール/しきい値へ反映（docs/12・docs/15 と接続）。
- 声診断の誤りは、可能なら該当録音を `data/register/<正しい声区>/` に保存して再較正。
