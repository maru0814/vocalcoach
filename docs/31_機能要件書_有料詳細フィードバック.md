# 有料詳細フィードバック（単発課金） 機能要件書

> PdM作成。CEO意思決定（2026-06-12: 最初期マネタイズは個人向けアップセルを本命に小さく実装）を受けた最小要件。
> docs/20（黒字化プラン: freemium・Stripe・牽引後に課金）と整合。本機能はそのPhase 2を**単発課金で前倒し検証**するもの。サブスクはやらない。

## 1. 概要

- **一言説明**: 無料のスコア＋チャットFBの上位に、録音1本を深掘りした「詳細添削レポート」を**単発 ¥500** で販売する。
- **解決する課題**:
  - ユーザー側: 「点数は出たが、具体的に何をどう直せばいいか分からない」
  - 事業側: 支払い意思（Willingness to Pay）が存在するかの検証データがゼロ。金額より「払う人がいるか」を最初期に確かめる。

## 2. 想定ユーザー / ユースケース

- **ペルソナ**: 20〜40代のカラオケ・歌好き。声タイプ診断やFBを無料で試し「もっと具体的に直したい」と思った人。月に数百円なら趣味に払える。
- **主要ユースケース**:
  1. 無料FBでスコアを見たユーザーが、結果画面の「詳細添削を見る（¥500）」から購入し、その録音の詳細レポートを受け取る。
  2. 過去の録音履歴から1本選んで詳細添削を購入する。

## 3. スコープ

### 3.1 対象（やること）
- 録音1本に対する単発購入（¥500・買い切り・その録音に紐付く）
- Stripe Checkout による決済（カードのみ。サブスクなし）
- 詳細レポートの自動生成と表示（FR-03）
- 購入済みレポートの再閲覧（履歴から）

### 3.2 対象外（やらないこと）— MVP線引き
- サブスクリプション / 回数券 / 複数価格帯（検証後に docs/20 のプラン案で再検討）
- 人間（プロトレーナー）による添削
- 返金フローの自動化（問い合わせベースで手動対応）
- 領収書・インボイスの自動発行（Stripe標準のレシートメールのみ）
- Claude Code 版（skill）への課金導入

## 4. ユーザーストーリー

- **US-01**: 歌の練習をしているユーザーとして、自分の録音の「どこで・何が・なぜ」悪いのかを具体的に知りたい。なぜなら点数だけでは練習方法に落とせないから。
- **US-02**: 購入したユーザーとして、レポートをいつでも見返したい。なぜなら練習しながら何度も確認するから。
- **US-03**: 運営者として、購入率（無料FB→購入の転換率）を計測したい。なぜなら価格・訴求の改善判断に使うから。

## 5. 機能要件

### FR-01: 購入導線
- **概要**: 無料FB結果画面と録音履歴に「詳細添削を見る ¥500」ボタンを置く。
- **詳細仕様**:
  - 表示条件: 対象録音の自動評価（スコア算出）が完了していること。
  - 押下で Stripe Checkout Session を作成しリダイレクト。`metadata` に `user_id` と `recording_id` を必ず入れる。
  - 購入済みの録音ではボタンを「レポートを見る」に差し替える。
- **例外**: 未ログイン→ログインへ（`?next=` で復帰）。評価未完了→ボタン非表示。

### FR-02: 決済（Stripe Checkout）
- **概要**: 単発 ¥500 のカード決済。
- **詳細仕様**:
  - サーバ側エンドポイント `POST /api/v1/purchases/checkout`（body: `recording_id`）が Checkout Session を生成し URL を返す。
  - Webhook `POST /api/v1/purchases/webhook` で `checkout.session.completed` を受信し、`purchases` テーブルに記録（`user_id, recording_id, stripe_session_id, amount, status, created_at`）。署名検証必須。
  - 同一録音の二重購入はチェックアウト作成時に拒否（既購入なら409でレポートURLを返す）。
- **例外**: 決済キャンセル→元の結果画面へ戻す。Webhook遅延→レポート画面は「決済確認中（最大1分）」表示でポーリング。

### FR-03: 詳細レポート生成
- **概要**: 既存の解析結果（pitch/rhythm/expression スコアと解析データ）を入力に、LLMで詳細添削レポートを生成・保存する。
- **詳細仕様**: レポートは以下4セクション固定:
  1. **箇所別の指摘**（最大5箇所。「0:42〜0:48 サビ入りで音程が下にずれる」のように時間帯＋事象＋推定原因）
  2. **最優先の改善ポイント1つ**（あれもこれも言わない）
  3. **7日間練習メニュー**（1日10分・具体的な練習名と手順）
  4. **次回録音時のチェックポイント**（3つ以内）
  - 生成は購入確定（webhook受信）をトリガに非同期実行。生成結果はDBに保存し再生成しない。
  - docs/12（反ハルシネーション）に従い、解析データに根拠のない断定をしない。データが薄い箇所は「推定」と明示。
- **例外**: 生成失敗→自動リトライ2回→失敗なら「生成に失敗しました。返金対応します」表示＋運営に通知（ログ）。

### FR-04: レポート閲覧
- **概要**: 購入済みレポートを録音詳細から常時閲覧できる。
- **詳細仕様**: `GET /api/v1/purchases/{recording_id}/report`。本人のみ（認可必須）。

### FR-05: 計測
- **概要**: 転換率の計測に必要な最小イベントを記録する。
- **詳細仕様**: ①ボタン表示数 ②ボタン押下数 ③購入完了数 をログ（既存の分析手段で集計可能な形式）。目標値は置かない（まず実測）。

## 6. 非機能要件

- **性能**: レポート生成は購入後3分以内に閲覧可能（NFR-01相当）。
- **セキュリティ**: Stripe Webhook署名検証必須。レポートは本人以外アクセス不可。価格はサーバ側定義（クライアントから金額を受け取らない）。
- **コスト**: LLM生成は1購入1回（¥500に対し生成コスト数円〜十数円）。Stripe手数料3.6%込みで粗利約¥460/件。月額固定費の新規追加なし（docs/20 と整合）。
- **保守性**: 価格・文言は設定値で変更可能に（再デプロイなしが理想、env可）。

## 7. 受け入れ基準

- **AC-01**: 評価完了済みの録音の結果画面に ¥500 ボタンが表示され、未完了では表示されない。
- **AC-02**: テストカードで購入完了→3分以内に4セクション揃ったレポートが表示される。
- **AC-03**: 購入済み録音で再度購入操作をしても二重課金されない。
- **AC-04**: 他人の `recording_id` のレポートURLに直接アクセスすると 403/404。
- **AC-05**: Webhook署名が不正なリクエストは拒否される。
- **AC-06**: 決済キャンセル時、課金もレポート生成も発生しない。
- **AC-07**: 表示数・押下数・購入数が集計できる。

## 8. 前提・制約

- Stripe アカウント開設は人間（まる）が行う（本人確認が必要なため）。
- 特定商取引法に基づく表記ページが公開前に必要（販売者情報・価格・提供時期・返金方針）。LPに1ページ追加。
- 価格 ¥500 は検証用の初期値。変更はCEO判断（このdocの改訂で管理）。

## 9. 未決事項 / 要確認

- **Q1**: 法人格がない場合の特商法表記の記載内容（個人名公開の扱い）→ まる確認。
- **Q2**: レポートのトーン: ソラ先生人格で統一する（vocal-trainer skill の品質基準に従う）想定で良いか。
- **Q3**: 初週は「購入ボタンだけ出して計測」(fake door) を先に行うか、最初からフル実装か。→ 推奨: 流入がまだ少ないため fake door はスキップしフル実装（どうせ件数が少なく、偽ボタンは信頼を損なう）。
