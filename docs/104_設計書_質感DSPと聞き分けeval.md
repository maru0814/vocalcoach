# 質感DSPと聞き分けeval 設計書

対応要件: docs/95（FR-01/FR-06 の精度強化）。関連: docs/92 §5.9（換声点DSPの前例）, docs/96 会話モデル再定義「事実はDSP、判断はモデル」

## 0. 原則（この設計の憲法）
- **DSPは名前を判定しない**。「毎秒約24回の規則的な振幅の震えを検出」のような**測定事実の記述だけ**をブラインド聴取（第1段）に渡す。
- 名前（サイレン/リップロール/巻き舌…）を決めるのはモデル。測定事実は**消去法の物差し**。
- どこまで名前を断定してよいかの線引きは **eval の正答率で決める**（感覚で決めない）。それまでは docs/95 FR-06 の「描写で語る／一言確認」が既定。

## 1. 背景
サイレンをリップロールと誤認した実事故（2026-08-13）。両者は音程軌道がほぼ同じで、違いは「唇の振動による振幅の震え（毎秒20〜30回）」という質感にある。ただし**震え＝リップロールではない**：巻き舌（ほぼ同帯域）・エッジボイス（20〜80Hz）・がなり（不規則）・ビブラート（5〜8Hz）・マイクノイズでも振幅変動は起きる。だからDSPは帯域と規則性を**数字で記述**するに留め、解釈はモデルに委ねる。

## 2. システム構成
```
録音wav → texture.modulation_profile()（新設・librosa）
             ↓ {mod_rate_hz, mod_strength, ...}
          texture.describe()  → 記述文（名前を含まない日本語1〜2文）
             ↓
          llm.listen_blind(user_wav, acoustic_facts=記述文)  ← 第1段
```
- 会話文脈（宿題・課題・履歴・コメント）は従来どおり一切渡さない（docs/95 AC-01 は不変）。**録音自体から機械計測した事実**は文脈ではなく証拠であり、注入してよい。

## 3. モジュール設計
### backend/app/audio/texture.py（新設）
- `modulation_profile(wav_path, sr=16000) -> dict | None`
  - 5ms ホップの RMS エンベロープ → 平均除去 → 自己相関。
  - 4〜80Hz のラグ範囲でピーク探索: `mod_rate_hz`（支配的な震えの速さ）, `mod_strength`（自己相関ピーク値 0..1＝規則性の強さ）。
  - 1秒未満・無音は None。
- `describe(profile) -> str | None` — 名前を含まない記述文を返す:
  - strength ≥ 0.35 かつ 15〜45Hz: 「振幅の規則的な震えを毎秒約N回検出（唇・舌の震えやエッジボイスに典型的な帯域）」
  - strength ≥ 0.35 かつ 4〜9Hz: 「毎秒約N回のゆったりした音量の揺れ（ビブラート帯域）」
  - strength ≥ 0.35 かつ 45Hz超: 「毎秒約N回の細かいパルス状の震え（フライ/ラフネスに典型的な帯域）」
  - それ以外: 「規則的な振幅の震えは検出されない（なめらかな発声）」
  - しきい値 0.35 は合成信号テストで暫定校正。eval で見直す（§5）。

### backend/app/coaching/llm.py（変更）
- `listen_blind(user_wav, acoustic_facts: str | None = None)` に拡張。
- プロンプトに追記（facts がある時のみ）:
  「# この録音自体からの機械計測（参考）\n{facts}\n※名前を断定する材料ではなく、候補を絞る物差しとして使う（例: 震えが無ければリップロール・巻き舌・フライではない可能性が高い）」

### backend/app/api/v1/endpoints/coach.py（変更）
- ブラインド実行前に `texture.modulation_profile(wav_path)` → `describe()`（try/except・失敗は None＝従来どおり）。

## 4. eval（scripts/blind_listen_eval.py 新設）
- **目的**: 練習種別ごとの聞き分け正答率を実測し、「名指ししてよい練習」の線引きを数字で決める。
- **入力**: マニフェストCSV（`path,label`。label は正解の練習名 or `歌`）。正解付き録音は #288/docs/92 の資産＋今後の追加録音（運用者が録って足す）。
- **実行**: 実APIで `listen_blind` を各ファイルに N 回（既定3回）呼び、(a) kind 正答率 (b) 練習名正答率 (c) DSP事実の有無での差、を表とJSONで出力。
- **運用ルール（docs/95 FR-06 に接続）**: 正答率 ≥90% の練習は名指し可、それ未満は描写・確認どまり——という線引きの根拠データにする（しきい値自体は結果を見て運用者が決定）。
- **コスト**: 1ファイル×3回 ≒ ¥1.5。20ファイルで ¥30 程度。

## 5. テスト方針
- **hermetic（CI）**: 合成信号で texture を検証（APIキー不要）。
  - 25Hz AM を掛けたトーン → rate 20〜30 / strength 高
  - 純粋なスイープ（サイレン相当） → strength 低 →「震えは検出されない」
  - 6Hz AM（ビブラート相当） → ビブラート帯域の記述
  - `listen_blind` のプロンプト捕捉: facts 注入時も宿題・課題語が入らない（AC-01 維持）＋「断定する材料ではなく」の注意書きが入る
- **実測（手動・eval）**: §4 のスクリプト。CI では回さない（API・音源依存）。

## 6. 決定とトレードオフ
- 自己相関ベース（FFT変調スペクトルでなく）: 実装が短く外れ値に強い。周波数分解能は粗いが「帯域の区別」には十分。
- しきい値は暫定値で出荷し、evalの実測で校正する（過剰工学の回避）。
- 音程軌道の記述（連続グリッサンド等）は今回は追加しない: 既存 kind_hint（classify_kind）と重複するため。evalで不足が示されたら追加。
