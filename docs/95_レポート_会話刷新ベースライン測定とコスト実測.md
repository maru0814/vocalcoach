# 95. レポート — 会話レイヤー刷新のベースライン測定とコスト実測

- 実施日: 2026-08-09（qa-engineer）
- 目的: docs/94 §2 R8 の運用宿題。①刷新後の会話品質ベースラインを soar_eval で確定し、
  今後の変更の before/after 比較の基準点を作る。②チャット1ターンの実コストを実測する。
- 関連: docs/93（会話レイヤー刷新）/ docs/94（会話憲法）/ docs/64（eval設計）

## 1. 測定方法

- コーパス: `cases_multiturn` の全24会話・90ターン（video-accept-repair /
  smalltalk-numbers の新回帰ケースを含む）。**before/after とも同一バンク**。
- before: PR #301 時点のコード（旧パイプライン＝正規表現ゲートあり・chat=3.5-flash-lite）
- after: 現行 main（PR #303 マージ後＝意図理解モデル化・chat=3.5-flash）
- 判定: `mech_metrics.py`（決定論の機械計測。ラン間比較で最も信頼できる手法・README準拠）
- 成果物: `reports/mt_rebuild_before.json` / `mt_rebuild_after.json` / `mech_rebuild.json`

## 2. 機械計測の結果（before → after）

| 指標 | before | after | 評価 |
| --- | --- | --- | --- |
| 再録音要求 | 1/90（1%） | **0/90（0%）** | ✓ 改善 |
| 動画オファー | 7/90（8%） | 5/90（6%） | ✓ オファー済み正規表現の撤去後も**連発ゼロ**（下記） |

| 橋渡しなし否定 | 2/90（2%） | 1/90（1%） | ✓ 改善 |

## 3. 謝罪増（1%→10%）の精査 — 品質向上の反映であり劣化ではない

謝罪10件の内訳:
- **6件は video-accept-repair ケース**（ユーザーが「リップロールやん」「いや動画が。」と
  2度抗議する設計）。同じ場面で before はほぼ謝らず提案を言い張っていた。
  **抗議に謝って別の実在動画を再検索する＝修復行動が新たにできるようになった**結果の増加。
- 2件は contradict（偽前提）ケース。謝りつつも「チャットの記録にはまだ練習名が無い」と
  **事実で踏みとどまり、偽前提への追従はゼロ**（docs/65 の注入が新パイプラインでも機能）。
- 残り2件は「分かりにくくてごめんなさい」等の軽微なもの。
過剰謝罪（docs/42「混乱させてすみませんの多用禁止」）とは性質が異なると判断。
ただし今後のランで基準の10%を超えて増えるなら docs/42 側で扱う。

## 4. 定性確認（after の video-accept-repair 抜粋）

「よろ」→ 承諾と理解し、エッジボイスの実在動画（YouTube実検索）を即提示。
「リップロールやん」→ 訂正と理解して謝罪＋別の実在動画を再検索。
「いや動画が。」→ さらに修復。**スクショで起きた4連鎖の噛み合わなさは全て解消。**

## 5. コスト実測（チャット1ターン）

代表8ターン（相槌・質問・動画依頼・感情・雑談・曲名提示・声区質問）を実測:

| 項目 | 実測値 |
| --- | --- |
| 入力トークン/ターン | 平均 7,779（最大 13,111＝ツール往復ターン） |
| 出力トークン/ターン | 平均 79（最大 104） |
| 思考トークン | **0**（3.5-flash に tb=0 が効いている・docs/92 §2-2 の実測どおり） |
| APIコール/ターン | 平均 1.2回（ツールを呼ぶターンのみ2回） |

単価（2026-08 時点・サードパーティ集計値。公式改定に注意）: 入力 $1.50/M・出力 $9.00/M
（キャッシュ入力 $0.15/M）。

- **1ターン ≈ $0.012（約1.9円）**（入力 $0.0117 ＋ 出力 $0.0007。キャッシュ未考慮の上限値）
- 1,000ターン ≈ $12.4（約1,900円）
- 入力の大半（約6千tok）は毎ターン同一の system＋レッスン状況。**コンテキストキャッシュが
  効けば入力単価は1/10**（$0.15/M）になるため、実請求はこの試算を下回る可能性が高い。
  請求実績と乖離があればキャッシュヒットを usage_metadata の cached_content_token_count で確認する。

旧チャット（flash-lite: $0.10/M in・$0.40/M out 級）比でおよそ **15倍/ターン**だが、
絶対額は1ターン2円弱。運用者決定（2026-08-07「予算より品質」）の範囲内。

## 6. 今後の運用（このベースラインの使い方）

1. 会話体験に触れるPRは、同一バンクで after ランを取り
   `mech_metrics --before reports/mt_rebuild_after.json --after <新ラン>` で比較する
   （今回の after が以後の「before」になる）。
2. 監視すべき値: 謝罪率（>10%で docs/42 検討）・動画オファー連発（>0で即対応）・
   橋渡しなし否定（>2%で docs/42 橋渡し義務の再確認）。
3. コストは月次で請求実績を確認（目安: 1,000ターンあたり ≈$12。大きく上振れたら
   キャッシュヒット率とツール往復回数を疑う）。
