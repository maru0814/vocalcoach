# バイラル強化 設計書（声タイプ診断のシェアループ強化）

> アーキテクト作成。声タイプ診断の「勝手に広がる輪」を太くするための3機能の設計。
> 既存構造（`backend/app` FastAPI + SQLite/Alembic、`frontend/src` Next.js App Router）を尊重。MVP原則で過剰設計を避ける。

## 0. スコープ
| # | 機能 | 目的 | 主担当 |
| --- | --- | --- | --- |
| 1 | シェア文最適化＋「比べてシェア」導線 | k値（1人が連れてくる数）を上げる | frontend |
| 2 | 社会的証明（累計診断数＋タイプ分布） | 「みんなやってる」で参加を後押し | backend+frontend |
| 3 | 結果OG（スコア入りカード） | Xカードを“自分の結果”にしてクリック率↑ | frontend |

## 1. システム構成
```
[診断API] /api/v1/voice-type/analyze
   └─ 成功時に診断イベントを1行記録（#2）
[統計API] /api/v1/voice-type/stats (公開GET, 認証不要)
   └─ 累計件数・タイプ別分布を集計して返す（#2）
[共有導線] 結果カード ShareButtons（#1, #3）
   └─ X共有URL = /voice-type/share/{id}?s={score}
[共有ランディング] /voice-type/share/[id]（#3）
   └─ generateMetadata: og:title にスコア / 本文にスコア＋分布
[社会的証明UI] <VoiceTypeStats/>（#2）
   └─ LP・/voice-type・共有ランディングに設置（client fetch）
```

## 2. アーキテクチャ判断（トレードオフ）
- **#2 のデータ保持**：イベントログ方式（1診断=1行 `voice_type_diagnoses`）を採用。
  - 理由：累計・タイプ分布・「今週」など時間窓集計が後から柔軟。低トラフィックなので行数増は無視可。
  - 代替案：集計カウンタ表（type_id, count）。更新は軽いが時間窓に弱い → 却下。将来肥大化したら定期prune or 日次ロールアップで対応（拡張ポイント）。
- **#2 統計の鮮度**：毎回クエリ（COUNT/GROUP BY）。低コストなのでキャッシュ無し。将来負荷が出たらアプリ内メモリ60sキャッシュを追加（拡張ポイント）。
- **#3 動的OG画像は“今は作らない”（重要判断）**：
  - スコアは **og:title / og:description** に載せる（Xはカードに画像＋タイトルを並べて表示するため、スコアはカード上に見える）。
  - 完全な「画像内にスコアを焼き込む動的OG（next/og）」は、CJKフォント埋め込み・standaloneコンテナでの実行・ビルド肥大という**本番リスクが利得に見合わない**ため見送り。
  - 既存の**タイプ別OG画像（キャラ＋タイプ名入り）**は十分に“自分の結果”を表現できている。
  - 将来やるなら：`/api/og` Route Handler + `next/og`（英字オーバーレイのみでCJK回避：タイプ名は英語・スコアは数字）。隔離環境でビルド検証してから（フォローアップ）。

## 3. API設計
### 3.1 既存変更：`POST /api/v1/voice-type/analyze`
- 変更点：分類成功後、診断イベントを1行 INSERT（best-effort。失敗しても診断レスポンスは返す）。
- レスポンス不変（後方互換）。

### 3.2 新規：`GET /api/v1/voice-type/stats`（公開・認証不要）
- レスポンス:
```json
{
  "total": 1234,
  "distribution": [
    {"id":"crystal","name":"Crystal Voice","count":210,"pct":17.0}, ...
  ],
  "top": {"id":"crystal","name":"Crystal Voice","count":210}
}
```
- 認証なし（集計のみ・PIIなし）。レート制限は付けない（COUNT 1〜2発の軽量クエリ）。
- 分布は全タイプ（0件も0で返す）。`pct` は total>0 のとき百分率。

## 4. DBスキーマ
新規テーブル `voice_type_diagnoses`（イベントログ）:
| カラム | 型 | 備考 |
| --- | --- | --- |
| id | int PK autoincrement | |
| type_id | str(20) | rock/groovy/.../moody |
| score | int nullable | 総合スコア |
| created_at | datetime | default utcnow, **index**（時間窓集計用） |

- マイグレーション：Alembic新規リビジョン（`alembic upgrade head` はコンテナ起動時に自動実行）。down_revision は現行head。
- 既存データへの影響なし（新規表のみ）。

## 5. モジュール構成
- `backend/app/models/voice_type.py` … `VoiceTypeDiagnosis` モデル（Base継承）。`alembic/env.py` の import に追加。
- `backend/alembic/versions/xxxx_add_voice_type_diagnoses.py` … 新規表マイグレーション。
- `backend/app/api/v1/endpoints/voice_type.py`
  - analyze内で記録（try/except、commitはbest-effort）。
  - `GET /stats` ハンドラ追加。`voice_coach` の id→name マップを利用。
- `backend/app/coaching/voice_coach.py` … `id→name` ヘルパー（`VOICE_TYPE_NAMES`）を追加（任意。なければendpointで構築）。
- `frontend/src/components/voice/VoiceTypeStats.tsx`（client）… `/stats` を取得し「これまで N人が診断／今いちばん多いのは◯◯」を表示。total<20は非表示（新規の見栄え対策）。
- `frontend/src/lib/api.ts` … `getVoiceTypeStats()`。
- `frontend/src/components/voice/VoiceTypeResult.tsx`（ShareButtons）… #1 文面＋#3 共有URLに `?s=score`。
- `frontend/src/app/voice-type/share/[id]/page.tsx` … #3 searchParamsでscore受け取り→og:title/desc＋本文表示＋`<VoiceTypeStats/>`。
- 設置：LP（`/`）・`/voice-type`・共有ランディングに `<VoiceTypeStats/>`。

## 6. エラーハンドリング方針
- 診断イベント記録は **best-effort**：例外は握りつぶしログのみ（診断本体を絶対に止めない）。
- `/stats` 失敗時：フロントは `<VoiceTypeStats/>` を**非表示**（無ければ出さないだけ。致命でない）。
- 既存挙動・レスポンス互換を維持。

## 7. 性能・可用性
- INSERT 1行／診断（無視可）。`/stats` は COUNT+GROUP BY（インデックス無しでも小規模なら問題なし。created_atにindex）。
- 将来：`/stats` に 60s メモリキャッシュ、イベントの日次ロールアップ。

## 8. セキュリティ
- `/stats` は集計のみ・PIIなし → 公開で問題なし。
- 書き込みは認証必須の analyze 経路のみ（既存のレート制限が効く）。

## 9. テスト方針
- backend：temp SQLiteで `alembic upgrade head` が通る／analyzeでイベント記録／`/stats` の集計値が正しい。
- frontend：build green、`<VoiceTypeStats/>` がtotal<20で非表示・以上で表示、共有URLに `?s=` が付く、共有ランディングのog:titleにスコア。
- 本番：マイグレ自動適用→/stats 200→診断後にtotal増加→OGにスコア。

## 10. 後方互換性 / 移行
- 新規表のみ・既存APIレスポンス不変 → 後方互換。
- ロールバック：down migrationで表削除（データ消えるが集計のみ）。

## 11. 追補（2026-07-22）：#3 動的OG画像を実装する（§2の見送り判断を更新）
運用者から「共有ランディングのOGP画像が診断結果の一枚絵になっていない」との指摘を受け、§2で見送った動的OG画像を実装する。見送り理由だった3リスクは以下で潰す。

| §2で挙げたリスク | 対処 |
| --- | --- |
| CJKフォント埋め込みでビルド肥大 | Noto Sans JP（OFL）を**必要グリフのみサブセット**（かな全集合＋使用漢字＋ASCII、数十KB）。再生成スクリプト `frontend/scripts/subset_og_font.py` を同梱し、文言変更時に再実行 |
| standaloneコンテナでのedge実行 | Next.js self-host は edge runtime の Route Handler をサポート。`next build` とローカル実行で事前検証してからデプロイ |
| 失敗時にカードが壊れる | ルート内で例外を catch し、**既存の静的OG `/voice-types/og/{id}.jpg` へ302フォールバック**。最悪でも従来と同じ画像が出る |

### 設計
- ルート: `GET /api/og/voice-type/[id]?s={score}`（edge runtime, `next/server` の `ImageResponse`）
  - `id` は8タイプのみ許可、`s` は `/^\d{1,3}$/`（従来の `parseScore` と同一制約）。不正なら静的OGへフォールバック
  - 1200×630 PNG。背景=既存 `public/voice-types/og/{id}.jpg`、下部に結果カード帯（タイプ名・絵文字・`総合◯点`・説明文・「ソラ先生 声タイプ診断」バッジ・無料診断CTA）
  - 背景jpg・サブセットフォントは `new URL(..., import.meta.url)` でビルド時バンドル（実行時の外部fetch依存なし。絵文字のみ twemoji CDN、失敗しても文字は出る）
- `frontend/src/app/voice-type/share/[id]/page.tsx` の `generateMetadata`: og/twitter images を `/api/og/voice-type/{id}?s={score}` に変更（スコア無し時はクエリ省略）
- 旧静的OG `public/voice-types/og/*.jpg` は**削除しない**（既存ツイートのカードキャッシュ参照先＋フォールバック先として温存）
- フォント: `frontend/src/assets/og/`（サブセットttf＋OFL.txt＋README）。スコアはURLごとにXがカードをキャッシュするため、キャッシュ汚染なし

### テスト記録（2026-07-22 ローカルdev・QA実施済み）
| ID | 観点 | 手順 | 期待結果 | 結果 |
| --- | --- | --- | --- | --- |
| TC-OG-01 | 正常系 | 8タイプ×`?s=82` を GET | 200 / image/png / 1200×630 | ✅ 全8タイプ |
| TC-OG-02 | 正常系 | `s` 無しで GET | 200・スコア枠なしの一枚絵 | ✅ 目視確認 |
| TC-OG-03 | 境界値 | `s=0/100/999/1000/-1/08` | 正規表現外（1000/-1）はスコア非表示で200 | ✅ 全200 |
| TC-OG-04 | 異常系 | 不正id（`zzz`・パストラバーサル） | 404 | ✅ |
| TC-OG-05 | 正常系 | シェアLPの `og:image`/`twitter:image` | `/api/og/voice-type/{id}?s=` を指す（s無し時はクエリ省略） | ✅ |
| TC-OG-06 | 回帰 | 旧静的OG `/voice-types/og/{id}.jpg` | 200のまま温存（旧ツイート・フォールバック用） | ✅ |
| TC-OG-07 | 品質 | 日本語描画 | 豆腐なし・絵文字表示（twemoji） | ✅ スクショ確認 |
| TC-OG-08 | 性能 | 生成時間 | X クローラのタイムアウト内（実測 0.45s） | ✅ |

- 補足: 本番ビルドでは `ImageResponse` が `cache-control: public, immutable, max-age=31536000` を付与（devは no-store）。デプロイ後に本番URLで [X Card Validator](https://cards-dev.twitter.com/validator) 相当（ツイート下書きプレビュー）で確認すること。
- 残課題: 絵文字は twemoji CDN 依存（VPSの外向きHTTPS必須）。CDN不達時は catch で静的OGへ302するため、カード自体は壊れない。

### 追加（2026-07-22）：診断LP `/lp/shindan` のOGPを「8タイプ全員集合」の一枚絵に
- 運用者確認の結果：シェアURL用の動的スコア入りOGP（上記）は**残置**しつつ、診断LP `/lp/shindan` のOGP（従来は汎用 `/brand/og-default.png`）を **8タイプ全員集合グリッドの静的一枚絵 `/brand/og-shindan.jpg`**（1200×630, 約343KB）に差し替え。
- 画像は一時的な ImageResponse ルート（8タイプのモチーフ絵＋タイプ名＋見出し「あなたの声、何タイプ？」を合成）で生成し、静的JPGとして `frontend/public/brand/` に保存。一時ルートはコミットしない。文言・タイプ改定時は同じ手順で再生成する。
