## 決定2: 実現手段の裁定
### 選択肢
- **A: Capacitor**（既存 Next.js Web版を WebView シェルで包む。iOS/Android 両対応。コード共有ほぼ100%）
- **B: TWA / Bubblewrap**（PWA を Android アプリ化。Android のみ。iOS 不可）
- **C: React Native / Expo / Flutter で別開発**（ネイティブUI。二重開発）

### 決定: **A（Capacitor）**。配信は **Android 先行**、iOS はプロジェクト同梱・提出はオーナーの Apple Developer 契約後。

### 理由（判断軸との対応）
1. **ユーザー本質価値**: アプリの価値は「ホーム画面から1タップで録音→FB」。Capacitor は既存の録音UI・コーチ画面・課金導線をそのまま提供でき、体験の同一性が保たれる。マイクは WebView の getUserMedia がそのまま動く（Android WebView / iOS WKWebView 14.3+）。
2. **MVP原則**: C は二重開発で最も遠い。B は iOS に永遠に届かない。A は「既存Webを包む」最小構成でストア配信に到達する。Web側の改善が即アプリに反映される（リモートURL方式）ため、ストア再審査なしで機能改善を出し続けられる＝「即デプロイ」の強みを維持。
3. **一人で運営可能か**: A はネイティブ層が「シェル＋権限宣言」だけに縮む。OS追随はシェルの Capacitor バージョンアップのみ。C の二重開発却下理由（docs/72 ③）はそのまま有効。
4. **収益化**: ストア手数料 15〜30% の問題は、**アプリ内では既存 Stripe のWeb課金導線をそのまま出す（外部ブラウザ誘導はしない・アプリ内WebViewでの自社決済）**戦略には規約リスクがあるため、**アプリ内では課金導線を露出せず「Webで契約→アプリで利用」型（reader app 型）を基本**とする。詳細は要件（pdm）で確定。

### 技術方針の骨子（architect への指示）
- Capacitor プロジェクトを `native/` に新設。`server.url = https://sora-vocal-ai.duckdns.org`（ビルド時に環境変数で差し替え可能に）を指すリモートURL方式。フロントの二重ビルド・static export はしない。
- Android を先行（Google Play $25 一括。審査が軽く、WebView 方式に寛容）。iOS プロジェクトも同梱するが、提出は Apple Developer Program（$99/年）契約後。Apple 審査ガイドライン 4.2（最小機能性）のリスクは iOS 提出時に評価する。
- マイク権限（RECORD_AUDIO / NSMicrophoneUsageDescription）等の権限宣言をネイティブ層で行う。
- ビルドは GitHub Actions で AAB（Play 提出用）と APK（直配布・実機確認用）を自動生成。ローカルに Android SDK を要求しない。

## 決定3: 「リリースまで」の定義
オーナーの「止めずにリリースまで」を、会社が自力で完了できる最大範囲として次のとおり定義する:
1. リポジトリにネイティブアプリ一式（`native/`）とCIビルドが入り、**署名済みAPK/AABが生成できる状態**
2. QAテスト計画・リリースランブック（ストア提出手順書）完備
3. PR 作成・レビュー可能な状態で提出
4. **ストアの公開ボタンだけがオーナー作業**（Google Play デベロッパー登録 $25・Apple $99/年 はオーナー名義の支払いが必要で、会社は代行できない）。ランブックに沿えば当日中に提出可能な状態で引き渡す。

## リスクの飲み方（docs/72 の懸念への回答）
- **solo負荷**: リモートURL方式によりアプリ更新頻度を最小化（シェルの更新は権限・OS対応時のみ）。
- **手数料30%**: アプリ内で課金導線を出さない構成で回避（要件で確定）。
- **固定費**: Google $25（一括）のみで開始。Apple $99/年 は iOS 提出判断時にオーナーへ提示。
- **duckdns ドメイン**: 無料DNSのままストア公開は信頼性リスク（ドメイン失効=アプリ全滅）。独自ドメイン移行を Later 課題としてランブックに明記。
