# ネイティブアプリ化 機能要件書

- 作成日: 2026-07-21
- 作成: PdM
- 上流: docs/77_意思決定メモ_ネイティブアプリ化.md（CEO裁定: Capacitor リモートURL方式・Android先行・アプリ内課金導線なし）
- 関連: docs/73〜76（PWA化。本件の土台）、docs/31/33（有料プラン）

## 1. 概要
- 既存Web版（https://sora-vocal-ai.duckdns.org）を Capacitor シェルで包み、Google Play で配信できる Android アプリ（および提出準備済みの iOS プロジェクト）を作る。
- 解決する課題: ホーム画面追加（PWA）では届かない「ストアで検索して入れる」ユーザー層への到達と、オーナー要望「ネイティブアプリとしてのリリース」の実現。

## 2. 想定ユーザー / ユースケース
- ペルソナ: 既存Web版と同一（歌が上手くなりたい10〜30代。docs/01）。
- UC-01: ストアからインストール → アプリを開く → そのまま録音してソラ先生のFBを受ける。
- UC-02: 既存Webユーザーがアプリを入れ、同じアカウントでログインして履歴を引き継ぐ（同一ドメインのWebそのままなので自動成立）。

## 3. スコープ
### 3.1 対象（やること）
- `native/` に Capacitor プロジェクト新設（Android + iOS。リモートURL方式）
- マイク録音がアプリ内で動く（権限宣言＋WebView権限ブリッジ）
- アプリ用アイコン・スプラッシュ（既存ブランド資産の流用）
- 起動失敗（オフライン）時のリトライ画面
- 外部リンク（X共有・note等）はシステムブラウザで開く
- アプリ経由の利用を識別する起動パラメータ（`?source=app`）
- アプリ内では有料プラン購入導線を非表示（reader app 型・FR-05）
- GitHub Actions による APK（直配布/実機確認用）・AAB（Play提出用）の自動ビルドと署名
- ストア提出に必要なメタデータ一式の雛形（説明文・プライバシー申告の下書き）

### 3.2 対象外（やらないこと）
- ネイティブUIの新規開発（画面はすべて既存Web）
- アプリ内課金（Play Billing / StoreKit）実装
- プッシュ通知のネイティブ実装（FCM/APNs）。Android は WebView 内の既存 Web Push が動く範囲でよい。iOS のプッシュは Later
- オフラインでの録音・解析（オンライン前提は Web版と同じ）
- iOS の App Store 提出作業（プロジェクト同梱まで。提出は Apple Developer 契約後）
- 独自ドメイン移行（ランブックに Later として記載）

## 4. ユーザーストーリー
- US-01: スマホユーザーとして、Google Play から「ソラ先生」を入れて1タップで録音レッスンを始めたい。ブラウザのURL入力やホーム画面追加の手順は面倒だから。
- US-02: 既存ユーザーとして、アプリでも同じアカウント・同じ履歴を使いたい。
- US-03: オーナーとして、Web側の改善がストア再審査なしでアプリに反映されてほしい。solo運営だから。

## 5. 機能要件
### FR-01: Capacitor シェル（リモートURL方式）
- `native/` に Capacitor 7 系プロジェクトを作成。appId: `com.vocalcoach.sora`、appName: 「ソラ先生 - AIボーカルトレーナー」。
- `server.url` は本番URL（既定 `https://sora-vocal-ai.duckdns.org`）。ビルド時に環境変数 `CAP_SERVER_URL` で差し替え可能（ステージング検証用）。
- 起動URLにクエリ `?source=app` を付与（アプリ経由の計測・UI分岐用。PWA の `?source=pwa` と同型）。
- 例外: `server.url` のホスト以外への遷移は WebView 内で開かず、システムブラウザで開く。

### FR-02: マイク録音
- Android: `RECORD_AUDIO` / `MODIFY_AUDIO_SETTINGS` を宣言し、WebView の getUserMedia 権限要求をネイティブ権限にブリッジする（Capacitor 標準動作）。初回録音時にOS権限ダイアログが出て、許可後に既存の録音UIが動作する。
- iOS: `NSMicrophoneUsageDescription` を Info.plist に宣言（文言: 「歌声を録音してAIが添削するために使用します」）。
- 例外: 権限拒否時は既存Web版の getUserMedia エラーハンドリングに委ねる（新規ネイティブUIは作らない）。

### FR-03: 起動失敗時のフォールバック
- ネットワーク不通等で `server.url` の読み込みに失敗した場合、同梱のローカルエラーページ（日本語・「再試行」ボタン付き）を表示する。再試行でアプリの起動URLへ再遷移する。

### FR-04: アイコン・スプラッシュ
- 既存 `frontend/public/icons/`（icon-512 等）を流用してアプリアイコン・アダプティブアイコン・スプラッシュを生成。背景色は manifest と同じ `#0b1020`。

### FR-05: アプリ内の課金導線の扱い（reader app 型）
- アプリ（`source=app`）で表示中は、有料プラン購入・アップグレードへの導線（料金ページへのリンク/ボタン）を非表示にする。Google Play「アプリ内でのデジタル商品販売は Play Billing 必須」規約への抵触を避けるため。
- 課金済みユーザーの機能利用はそのまま（Webで契約→アプリで利用）。
- 実装は frontend 側の条件分岐（起動クエリ `source=app` を localStorage に保持して判定）。分岐点の具体箇所は設計（docs/79）で確定。

### FR-06: CI ビルド
- GitHub Actions ワークフロー `native-android.yml`: push（`native/` 配下変更時）および手動起動で、(a) debug APK を常に生成、(b) 署名シークレット（keystore）が設定されていれば release AAB + APK を署名付きで生成し、Artifacts に添付する。
- 署名鍵はリポジトリに含めない。GitHub Secrets（`ANDROID_KEYSTORE_BASE64` 等）で注入。

### FR-07: バージョン管理
- versionName は `native/package.json` の version と一致させ、versionCode は単調増加の整数で管理する。リリースごとの更新手順をランブックに記載。

## 6. 非機能要件
- 性能: シェルの追加起動オーバーヘッドは体感1秒以内（WebView起動＋リモート読み込みは回線依存でWeb版と同等）。
- 可用性: アプリの可用性は Web本番と同一（リモートURL方式のため）。本番停止＝アプリ停止である旨をランブックに明記。
- セキュリティ: cleartext 通信禁止（https のみ）。署名鍵・ストア認証情報はリポジトリ外（GitHub Secrets / オーナー保管）。
- 保守性: ネイティブ層の変更は「権限・Capacitor更新・アイコン」のみに限定。プロダクト機能の変更で `native/` を触らないこと。
- UX: 全画面 WebView。セーフエリア（ノッチ）は既存PWAの viewport 設定に従う。

## 7. 受け入れ基準
- AC-01: CI が生成した debug APK を Android 実機に入れ、起動すると本番の `/coach?source=app` が全画面で表示される。
- AC-02: アプリ内で録音ボタンを押すと OS のマイク権限ダイアログが表示され、許可後に録音→FB取得まで完走する。
- AC-03: 機内モードで起動すると日本語のエラーページと「再試行」が表示され、回線復帰後の再試行で正常起動する。
- AC-04: アプリ内表示では有料プラン購入導線が表示されない。ブラウザ（source なし）では従来どおり表示される。
- AC-05: X共有などの外部リンクがシステムブラウザで開く。
- AC-06: 署名シークレット設定済みの CI 実行で、Play Console にそのままアップロード可能な署名済み AAB が Artifacts に出力される。
- AC-07: `native/ios` が Xcode で開けるプロジェクトとして同梱され、マイク権限文言が Info.plist に含まれる。
- AC-08: リポジトリ内に署名鍵・パスワード・ストア認証情報が含まれない。

## 8. 前提・制約
- 本番ドメインは現状 duckdns（無料DNS）。ストア公開後のドメイン変更はアプリ更新（再審査）を要するため、独自ドメイン移行は早期に判断すべき（Later、docs/81 に記載）。
- Google Play デベロッパー登録（$25）・Apple Developer Program（$99/年）はオーナー名義。会社は提出直前まで準備する。
- iOS は WKWebView の制約で Web Push が動かない（通知は Later）。また Apple 審査 4.2（最小機能性）で「Webラッパー」指摘のリスクがあり、iOS 提出時に対策を再評価する（docs/77）。

## 9. 未決事項 / 要確認
- Play ストアの掲載名・スクリーンショット素材はマーケターがランブック内で雛形を用意（最終文言はオーナー確認でよい）。
- versionCode の初期値は 1。
