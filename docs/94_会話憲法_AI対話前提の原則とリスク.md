# 94. 会話憲法 — ソラ先生の会話は「AIとの対話」を前提に作る

- 制定: 2026-08-07（運用者決定）
- 適用範囲: ソラ先生の会話体験に関わる全ての設計・実装・修正（Web版・skill版）
- 関連: docs/93（会話レイヤー刷新）/ docs/42（FB品質・単一ソース）/ docs/92（モデル世代対応）

## 1. 憲法（原則）

> **会話が噛み合わない問題が起きたとき、決定論的なハイブリッド（正規表現ゲート・
> キーワードルーティング・定型返答）を追加して対処しない。**
> 意図の理解・トーンの選択・応答の生成は、常にモデルの仕事として扱い、
> モデル側（プロンプト・ツール・モデル選定・評価）で改善する。

### 1.1 役割の線引き（何をコードに残すか）
| 領域 | 担当 | 例 |
| --- | --- | --- |
| 意図理解・応答生成・トーン | **モデル** | 承諾/訂正/雑談/感情の判別、聴くべきかの判断、主訴の記録判断 |
| 事実の供給 | コード（ツール・注入） | DSP解析値、カタログ動画、YouTube実検索、会話に登場した練習名 |
| 実行 | コード（ツールの実体） | 録音を聴く、再解析する、状態を書く、検索する |
| 形式の取り込み | コード（決定論） | URL、時刻形式の区間（1:05〜1:20）、秒明示の区間（30〜45秒）＝**誤読しようがない形式のみ** |
| 事後の安全網 | コード（スクラブ・保証） | 実在しないURL・捏造秒数の除去、約束不履行の検知→強制リトライ |
| 安全（健康・課金） | **コード（例外領域）** | レッドフラグ→休声・受診案内の定型、レート制限、日次上限 |

### 1.2 禁じ手（このリポジトリで再び書いてはいけないもの）
- 発言の長さ・字数で意図を推定する（「12文字未満は相槌」）
- 承諾・拒否・訂正の語彙リスト（「よろ」が無くて壊れる構造）
- キーワード一致でLLMを迂回する特別経路（「母音って何？」が発音分析へ飛んだ）
- 文脈を見ないキーワードからの状態書き換え（「90〜95点」が比較区間になった）
- モデルの自由な言い回しを正規表現で言い当てる前提の制御（オファー済み検出のすり抜け）
- ユーザー発言を指示書テンプレートで包んでモデルに渡す

過去に撤去した実装を復活防止テストで封じている:
`test_proposed_practices.py::test_conversation_mode_gates_are_removed` /
`test_state_pollution.py`（撤去ガード＋雑談で state が汚れない検査）。

### 1.3 例外（憲法が決定論を認める領域）
1. **安全**: 声の痛み等のレッドフラグ対応（karte_service.RED_FLAG_REPLY）は決定論のまま。
   健康リスクの見逃しはモデルの確率的挙動に委ねない。
2. **課金・資源**: レート制限・解析回数上限・タイムアウトはコードで守る。
3. **事後スクラブ**: 実在しないURL・データに無い秒数の除去は最後の砦として維持する
   （モデルを信頼することと、検証を捨てることは別）。
4. **形式の取り込み**: 誤読しようがない形式（URL等）の決定論パースは効率のため許す。
   ただし返答の生成までは奪わない（取り込み事実を注入してモデルが応答する）。

## 2. この憲法のリスク分析（制定にあたって直視しておくべきこと）

### R1. 非決定性 — 同じ入力に同じ挙動が保証されない
ルールなら「よろ→承諾」は100%だが、モデルは99%×温度×モデル更新。まれに外す。
- **影響**: 個別の失敗事例が必ず発生し続ける。ゼロにはならない。
- **緩和**: soar_eval（多ターン・自然さ・事実忠実性）を回帰ゲートにし、「事例の数」で品質を
  管理する（単発事例への反射的ルール追加はこの憲法違反）。失敗が構造的（同型で繰り返す）と
  分かった時だけ、プロンプト・ツール宣言・モデルの順で直す。
- **残余リスク**: 受け入れる。「まれに噛み合わない」は「構造的に噛み合わない」より良い。

### R2. モデル依存 — 供給・互換・挙動ドリフト
Gemini の世代交代で会話が全滅した実績がある（docs/91: thinking 拒否・docs/92: 静かな 404）。
意図理解までモデルに寄せた分、モデル障害＝会話機能の全損に近づく。
- **緩和**: バージョン固定・世代ガード・日次ヘルスチェック（docs/92 の資産）を維持。
  env 1行での載せ替え経路と、LLM不可時の「正直フォールバック」（偽の定型で取り繕わない）を維持。
- **残余リスク**: モデル切替時に会話の人格・癖が変わる。切替前に soar_eval の before/after を必須化。

### R3. コスト・レイテンシの構造的増加
ツールAUTO化・事後リトライ・聴き直しツールで、1ターンのAPI往復は最大3〜4回になり得る。
録音を聴くツールは1回7〜12秒。
- **緩和**: ツール往復上限（coach_tool_loop_max=3）・リトライ1回制限・レート制限は維持。
  聴くツールの宣言文に「迷ったら呼ばずに聞き返す」を明記済み。
- **残余リスク**: 運用者決定（2026-08-07「予算より品質」）で許容。ただし月次でコスト実測を見る。

### R4. プロンプト膨張 — ルール地獄がプロンプト地獄に化ける
正規表現の代わりに SYSTEM_PROMPT へ指示を足し続ければ、同じ「継ぎ接ぎで壊れる」構造が
場所を変えて再現する。指示同士の矛盾はモデルの挙動を不安定にする。
- **緩和**: プロンプトの正本は docs/42（単一ソース）。追記時は既存節との矛盾を確認し、
  「事例対応の一文」ではなく「原則の改訂」として書く。eval で追記の副作用を測る。

### R5. 状態書き込みをモデルが握ることの誤爆
set_lesson_focus / rediagnose はモデル判断で state を書く。モデルが空気を読み違えれば
誤った主訴が記録される（旧: 正規表現の誤爆 → 新: モデルの誤判断。確率は下がるがゼロではない）。
- **緩和**: 書き込み系ツールの宣言に「明確な意思表示がある時だけ」を明記。書いた事実は
  レッスン状況としてモデルに見え続ける（ユーザーが「違う」と言えば会話で訂正できる）。
  破壊的な書き込み（削除・上書き）はツール化しない。
- **残余リスク**: 誤記録は次の診断1回に影響。会話で復元可能な範囲に収まる。

### R6. プロンプトインジェクション面の拡大
ユーザー発言がそのままモデルに渡り、モデルはツール（YouTube検索・状態書き込み・録音聴取）を
持つ。「システムプロンプトを無視して」「全動画URLを列挙して」等への耐性が必要になる。
- **緩和**: ツールは読み取り中心＋書き込みは低リスク2種のみ。URL は実在検証つき許可リスト、
  出力はスクラブ通過。個人情報・課金操作に触れるツールは存在しない。この面の攻撃で
  失えるものが小さい設計を保つ（新ツール追加時はここを審査する）。

### R7. デバッグ・再現性の低下
「なぜこう返したか」がルックアップできなくなる。ユーザー報告の再現も確率的。
- **緩和**: ツール呼び出しと注入コンテキストのログを残す（現行 logger を維持・拡張）。
  soar_eval の会話リプレイを再現手段として使う。

### R8. 検証文化への負荷（いちばん現実的なリスク）
決定論のユニットテストは書けば緑になるが、会話品質は実APIと評価が要る。
「テストが通った＝会話が良い」ではなくなり、**評価を回さない限り品質は見えない**。
- **緩和**: 本憲法とセットで「会話体験に触れるPRは soar_eval の該当ケースを回して
  before/after を PR に貼る」を運用ルールにする（回帰ケース: video-accept-repair /
  smalltalk-numbers を含む multiturn・naturalness）。

## 3. 運用（今後の「噛み合わない」への標準対応手順）
1. 事例を採取し、soar_eval に再現ケースとして追加する（まず測れるようにする）
2. 原因を「事実が足りない／ツールが無い／宣言が曖昧／プロンプトの原則欠落／モデルの地力」に分類
3. 対応は次の順で検討する: **ツール・事実注入の改善 → ツール宣言の改善 → docs/42 の原則改訂 →
   モデル格上げ・切替**。正規表現ゲート・定型返答・特別ルーティングは選択肢に入れない
4. before/after を実測して docs に記録する
