# レポート: 分析ターン pro vs flash 品質比較（ゼロベースFB）

- 日付: 2026-06-29
- 目的: ゼロベースFB（docs/43）の分析ターンを `gemini-2.5-pro` と `gemini-2.5-flash` で実走比較し、品質差・コスト・速度を見える化する。
- 方法: 同一の合成音声＋同一 Evidence Pack＋同一 `ANALYSIS_SYSTEM_PROMPT` で各モデルを実API呼び出し（`thinking=512 / max=2048 / temp=0.4`）。2ケース。
  - ケース1: 安定・原曲なし（一般講評）
  - ケース2: 高音が地声で揺れる＋原曲比較あり（ミックス/支えの課題が見えるはず）

## 1. 定量比較（実測）

| 指標 | flash | pro |
| --- | --- | --- |
| 完走（finish=STOP） | ✅ 両ケース | ✅ 両ケース |
| レイテンシ | **4.8〜5.8秒** | 12.2〜14.9秒（約2.5〜3倍） |
| thinkingトークン | ~500（一定） | 489〜**867**（難ケースで増やす） |
| 出力トークン | 244〜254 | 253〜298 |
| 接地（録音長超の秒・捏造秒） | なし | なし |
| 当日の503（一過性） | 2〜4回リトライ要 | 1回で成功（※午前は503多発） |
| **実コスト/回**（各モデル単価※） | **¥0.43〜0.46** | **¥2.0〜2.4** |

※単価目安: flash = in $0.30 / out(thinking含む) $10... → 実際は flash in $0.30・out $2.50、pro in $1.25・out $10 per 1M、¥155/$。pro はflashの約**4〜5倍**。
- ¥2000上限での月間可能回数の目安: **flash ≒ 約4,000回 / pro ≒ 約800回**。

## 2. 定性比較（実際の出力から）

### ケース1（安定・原曲なし）
- **flash**: 「2〜6秒のE4の音も、揺れが**22cents**と安定」と**実測値をそのまま引用**。処方は「フのロングトーン摩擦音（アッポッジョ）」。正確だがやや教科書的。
- **pro**: 「2秒あたりのE4、**2500Hzという響きの成分**がしっかり→**前に飛んでいる証拠**」と、flashが触れなかった**centroid（明るさ）まで評価に使い**、機構の説明が一段深い。口調も「〜だね/〜だよ」と**温かく自然**。

### ケース2（高音揺れ・原曲比較あり）
- **flash**: 「**リズムは原曲とほぼ一致**」を根拠に褒め、「3〜7秒の高音で揺れ＝**締めすぎ**→息の支え」と診断、フ摩擦音を処方。簡潔で的確。
- **pro**: 同じく3〜7秒の高音→「息の支えが不安定で**喉に力**」と、closure=pressed の事実と**因果をつなげて**説明。難ケースで**thinkingを867まで増やして**深く推論。口調はより寄り添う。

### 共通の傾向（重要）
- どちらも証拠の最重要シグナル（register_high: user=地声 / ref=ミックス＝高音をミックスへ）より、**「土台＝息の支え」を先に選んだ**。これは優先順位ルーブリック（声基礎 > ミックス）に**合致**しており誤りではないが、「原曲はミックスで運んでいる」を明示する踏み込みは両者とも弱め。
- 接地は両者良好（録音長を超える秒・捏造秒なし。「10秒キープ」は練習尺で時刻ではない＝正しく非対象）。

## 3. 品質差の要約

| 観点 | 差 |
| --- | --- |
| 診断の正しさ | ほぼ互角（同じ結論に到達） |
| 証拠の活用の広さ | **pro 優位**（centroid等まで使う） |
| 機構説明の深さ | **pro やや優位**（因果をより丁寧に） |
| 口調・自然さ・寄り添い | **pro 優位**（温かい話し言葉） |
| 数値の明示的引用 | flash がやや律儀（22cents等） |
| 簡潔さ（短文FBとして） | ほぼ互角（pro がやや長い時あり） |
| 速度 | **flash 圧勝**（2.5〜3倍速） |
| コスト | **flash 圧勝**（約1/4〜1/5） |

## 4. 結論・推奨
- **既定は flash で十分**。本プロダクトの成果物は「短い会話FB」で、診断の正しさ・接地は互角。pro の優位（証拠活用の広さ・機構の深さ・口調の温かさ）は**質的には認められるが、短文FBでの体感差は中程度**。一方で pro は**速度2.5〜3倍遅く・コスト4〜5倍**。
- **pro を使う価値があるケース**:
  - 有料（プレミアム）ユーザー向けの「より丁寧な講評」差別化機能として。
  - 品質クレームが出た／長尺・複雑曲で診断の深さが要る場合。
- **運用**: 既定 flash、必要時のみ `LLM_ANALYSIS_MODEL=gemini-2.5-pro` ＋ `LLM_ANALYSIS_EST_JPY_PER_CALL` を実コスト（≒¥2.4）に合わせる。¥2000上限はそのまま効く（pro時は早めに上限到達＝想定どおりの安全弁）。
- **改善の余地（モデル非依存）**: 「原曲はミックスで運んでいる」のような原曲比較の核心を、もっと前面に出すようプロンプトに一言足すと、両モデルとも踏み込みが増える可能性（次の調整候補）。
  → **2026-07-17 反映済み**: docs/42 §4 に「核心差分の明示」ルールを追加し、Web版（`llm.py` の ANALYSIS_SYSTEM_PROMPT / SYSTEM_PROMPT）と skill（`cover-analysis.md`）へ展開。実API検証で、主診断（支え）を保ったまま「原曲はミックス寄り（音響からの推定）」の1文が出ること、および声区比較行が無い時に捏造しないこと（例文の鸚鵡返し対策＝発動条件の明示）を確認。
