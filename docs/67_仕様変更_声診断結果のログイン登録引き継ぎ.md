# 声診断結果のログイン/登録後引き継ぎ 仕様変更書

関連: `docs/11_機能要件書_差別化機能_声診断_発音_競合対応.md`（FR-06 未登録トライアル動線、AC-05）
種別: 既存機能の仕様変更（バグ修正に近い実装漏れの解消）

## 1. 概要
- `docs/11` FR-06/AC-05 は「未登録でも声タイプ診断が1回完走でき、結果は非開示（ぼかし）で提示し、登録の瞬間にフル結果が開放される」ことを既に要件化している。
- しかし現行実装では、未登録ユーザーが「無料登録して結果を見る」（`/login?next=/voice-type`）を押すとページ遷移で `frontend/src/app/voice-type/page.tsx` がアンマウントされ、診断結果（`useState<VoiceTypeResult | null>`, L23）が完全に失われる。ログイン/登録成功後に `/voice-type` へ戻っても初期状態で再マウントされるだけで、結果が復元されない。
- 本書は、AC-05の意図どおり「登録完了後にフル結果が実際に見える」状態にするための実装仕様を定める。

## 2. 想定ユーザー / ユースケース
- US-01（既存 docs/11 US-01の続き）: 未登録ユーザーとして、声診断結果を見るために登録した直後、やり直しなしで自分の結果（フル版）を見たい。

## 3. スコープ
### 3.1 対象（やること）
- 未登録時に取得した診断結果を、ログイン/登録のページ遷移をまたいで引き継ぎ、登録・ログイン完了後に自動でフル結果を表示する。

### 3.2 対象外（やらないこと）
- 診断結果をユーザーアカウントの恒久的な履歴として保存し、マイページ等で後日再閲覧できるようにすること（history機能）。既存の `VoiceTypeDiagnosis` テーブルは匿名集計専用のままとし、`user_id` 紐付けの新テーブル・APIは今回作らない。
  - 理由: `docs/11` の要件はあくまで「登録直後にフル結果を見せる」ことであり、恒久保存の要件はまだ無い。スコープを広げると設計・実装コストが増え、今回の不具合解消が遅れる。恒久保存が必要になった場合は別途PdMで要件化する。
- 録音した音声Blobそのものの引き継ぎ（再解析用途）。引き継ぐのは解析済みの `VoiceTypeResult`（JSON）のみ。

## 4. 機能要件

### FR-01: 診断結果のブリッジ保存
- 概要: 診断結果取得時（`analyzeVoiceType()` 成功時）、結果を `sessionStorage`（キー例: `voiceTypeResultBridge`）にも保存する。
- 詳細仕様:
  - 保存内容: `VoiceTypeResult` 一式 ＋ 保存時刻（有効期限判定用）。
  - 有効期限: 30分。期限切れの場合は無視して破棄する（他人の古い結果が誤って復元されるのを防ぐ）。
  - ログイン成功・診断結果を正常表示できた時点でブリッジは削除する（使い回し防止）。

### FR-02: ログイン/登録画面での引き継ぎ
- 概要: `/login?next=/voice-type` 遷移時、ブリッジの有無に関わらず通常通りログイン/登録を行う。ブリッジの保存・読み出し自体は `voice-type/page.tsx` 側の責務とし、`login/page.tsx` の変更は不要（sessionStorageはページを跨いでもドメイン内で保持されるため）。

### FR-03: 復元と自動フル表示
- 概要: `/voice-type` マウント時、`result` が空かつ有効なブリッジが存在する場合、ブリッジから `result` state を復元する。
- 詳細仕様:
  - 復元は認証チェック（`auth` state）と独立して行ってよいが、フル結果表示条件（`result && auth === "in"`）は既存ロジックのまま維持する。
  - 復元後、ログイン済みであれば自動的にフル結果ブロック（L204以降）が表示される。
  - 復元してもログインしていない場合（例: ユーザーが登録せず戻ってきた）は、従来通りぼかし表示＋登録CTAを表示する。

### FR-04: タブ・端末をまたぐ場合の扱い
- 概要: `sessionStorage` はタブ・ブラウザ再起動をまたがない。別タブや別端末で登録した場合は引き継がれない（従来通り診断のやり直しが必要）。
- 詳細仕様: 本仕様変更ではこのケースを対象外とし、ユーザーには特別な導線・エラー表示は出さない（現状の「未登録・結果なし」と同じ画面に自然に戻る）。

## 5. 非機能要件
- セキュリティ: `sessionStorage` に保存する `VoiceTypeResult` にPIIは含まれない（既存の匿名集計イベントと同様、type_id・score・診断値のみ）。
- 保守性: ブリッジのキー名・TTLは定数化し、`voice-type/page.tsx` 内に集約する。

## 6. 受け入れ基準
- AC-01: 未登録で声診断を完走 → 「無料登録して結果を見る」から登録 → 登録完了後 `/voice-type` に戻った時点で、再診断なしにフル結果（ぼかし解除・シェアボタン含む）が表示される。
- AC-02: 上記と同じ流れをログイン（既存アカウント）でも確認できる。
- AC-03: 診断から31分以上経過してから登録した場合、結果は復元されず、通常の「診断結果なし」画面になる（やり直しを促す）。
- AC-04: 一度フル結果が表示された後にページをリロードしても、ブリッジは既に消費済みのため再度別ユーザーの結果として復元されない（同一セッション内で再診断すれば新しい結果に更新される）。
- AC-05（既存 docs/11 AC-05の再確認）: `analyze` は引き続き未登録でも401を返さない。

## 7. 前提・制約
- `voice-type/page.tsx` は現状 `result` を `useState` のみで管理しており、`sessionStorage` との同期はこの仕様変更で新規に追加する。
- 対象は `frontend/` のみ。バックエンド変更は不要（`analyze` エンドポイントの挙動は変えない）。

## 8. 未決事項 / 要確認
- 恒久的な診断履歴（マイページでの再閲覧）を将来やるかは別途CEO/PdMで判断する（docs/35課題1の延長として検討候補）。
