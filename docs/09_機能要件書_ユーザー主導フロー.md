# ユーザー主導コーチングフロー 機能要件書

> PdM作成。`docs/05`（チャットWebアプリ）のコーチングループを、ユーザーが自分のペースで
> 行き来できる「繰り返しの輪」に拡張する。

## 1. 概要
- 現状フローは A→B→C→D→E の一方向（システム駆動）。
- 学習は本来ノンリニア。「もう一度基礎練したい」「すぐ曲を録り直したい」「別の課題に変えたい」など、
  進みたい方向は人によって違う。
- 本機能では **各ステップの結果のあとに"次にやること"をユーザーが選べる** ようにする。

## 2. 想定ユーザー / ユースケース
- UC-01: 基礎練に自信がない → **もう一度 基礎練** をやり直す
- UC-02: 基礎練は十分 → **すぐ曲を録り直して** 改善を確認する
- UC-03: この課題は一旦置く → **別の課題に変える**
- UC-04: 満足した → **今日はここまで** で終える

## 3. スコープ
### 3.1 対象
- 送る録音の種類（基礎練 / 曲）をユーザーが選べる（FR-01）
- 結果カードの下に行動チップを出す（FR-02）
- フェーズ表示を「ループ」として見せる（FR-03）
### 3.2 対象外
- 任意ステップへの自由ジャンプ（例: いきなり再録音だけ）は提示チップの範囲に限定
- 複数課題の並行管理（1セッション1アクティブ課題は維持）

## 4. ユーザーストーリー
- US-01: ユーザーとして、結果のあとに次の行動を自分で選びたい。人によって進みたい方向が違うから。
- US-02: ユーザーとして、基礎練と曲の録音を好きな順で送りたい。システムに決められたくないから。
- US-03: ユーザーとして、同じ課題をしつこく練習したい時に、何度でも基礎練に戻りたい。

## 5. 機能要件

### FR-01: 送る録音の種類選択
- コンポーザーに「基礎練 / 曲」のトグルを設け、音声送信時に種類（kind）を明示送信する。
- 既定値は現在フェーズから自動選択（C/D=基礎練、それ以外=曲）。ユーザーは任意に変更可。
- `kind=practice` は練習確認（Phase D 相当）、`kind=song` は課題発見/改善判定（B/E 相当）として扱う。

### FR-02: 次にやることチップ
- フィードバック/判定/改善カードの下に、行動チップを表示する：
  - `🎙 もう一度 基礎練` → 基礎練の録音待ち（Phase C）
  - `🎵 曲を録り直す` → 曲の録音待ち・改善判定（Phase E）
  - `🔁 別の課題に変える` → 次は別の課題を診断（Phase B、現課題を除外）
  - `✅ 今日はここまで` → 終了（DONE）
- チップ押下は専用アクションとして処理し、コーチが次の案内メッセージを返す。
- システムは提案するが、遷移の決定権はユーザーにある。

### FR-03: フェーズ表示のループ化
- ステッパーを「準備（曲指定・課題発見）」＋「練習ループ（基礎練 → 練習確認 → 再録音 →）」の
  2ブロックで表現し、後半が繰り返しであることを ↻ アイコン等で示す。

## 6. 非機能要件
- 既存の自動診断・スコア・基礎練処方ロジックは変更しない（遷移の起点だけユーザーに開放）。
- チップ操作のレスポンスは1秒以内（解析を伴わないため）。

## 7. 受け入れ基準
- AC-01: 任意の結果カードの下に4種の行動チップが表示される。
- AC-02: `もう一度 基礎練` を押すと Phase C になり、基礎練の録音を促される。
- AC-03: `曲を録り直す` を押すと Phase E になり、曲の録音で初回との改善判定が出る。
- AC-04: `別の課題に変える` を押して曲を送ると、直前と異なる課題が提示される。
- AC-05: `今日はここまで` を押すと終了メッセージが出て DONE になる。
- AC-06: コンポーザーで種類を「基礎練/曲」に切り替えて送ると、その種類として判定される。
- AC-07: フェーズ表示が練習ループ（C-D-E）を繰り返しとして示す。

## 8. 前提・制約
- 1セッション1アクティブ課題（current_task）を維持。除外用に avoid_task を保持。

## 9. 未決事項
- Q1: チップを毎回出すか、結果の種類により出し分けるか → MVPは常時4種。
- Q2: 「別の課題」が尽きた場合の挙動 → 「弱点が減ったので今日は終了でもOK」を提示（DONEへ）。
