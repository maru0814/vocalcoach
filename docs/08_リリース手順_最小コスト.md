# 最小コスト To C リリース手順書

> CEO/アーキテクト作成。「AIボーカルトレーナー ソラ先生」を、激安VPS1台で最小コスト公開する手順。
> 構成: **VPS 1台 + Docker Compose（Caddy + frontend + backend）+ SQLite**。原曲のYouTube取得は既定OFF（録音単体FB）。

## 0. 方針とコスト

| 項目 | 内容 | 月額目安 |
| --- | --- | --- |
| サーバー | 激安VPS 1台（2vCPU / 2GB RAM 目安） | 〜1,000円 |
| ドメイン | 任意（無ければIP直でも可） | 〜150円（年1,500円） |
| HTTPS | Caddy が Let's Encrypt で自動取得 | 無料 |
| DB | SQLite（VPS内ボリューム） | 無料 |
| 解析 | librosa（CPU）。レート制限あり | 無料（VPS内） |

- **なぜVPS1台か**: 解析がCPU重め＆イメージが大きく、無料サーバーレスでは動かしにくい。1台に集約が最小コスト・最小運用。
- **推奨スペック**: 2GB RAM 以上（librosa解析にメモリが要る）。小規模テストなら1〜2 vCPUで十分。

## 1. 事前準備（ローカル / 管理）

1. VPSを契約（例: Hetzner / さくらのVPS / ConoHa / DigitalOcean）。Ubuntu 22.04+ を選択。
2. （ドメインを使う場合）DNSの A レコードを **VPSのIP** に向ける。
3. SSHでVPSにログインできるようにする。

## 2. VPSセットアップ

```bash
# Docker と Compose plugin を導入
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER   # 反映のため一度ログインし直す

# リポジトリを配置
git clone <このリポジトリのURL> app && cd app
```

## 3. 本番設定（.env）

```bash
cd docker
cp .env.prod.example .env
# 値を編集
#   DOMAIN=あなたのドメイン（例: sora-vocal.com）。ドメイン無しなら後述の注記参照
#   JWT_SECRET=$(openssl rand -hex 32) の結果を貼る
#   ENABLE_YOUTUBE_REFERENCE=false（推奨）
nano .env
```

## 4. 起動

```bash
cd docker
docker compose -f docker-compose.prod.yml --env-file .env up -d --build
```

- 初回は frontend のビルド（数分）+ backend の依存導入（librosa等）に時間がかかる。
- 起動後、`https://<DOMAIN>` で LP が表示されれば成功。
- ヘルスチェック: `curl https://<DOMAIN>/healthz` → `{"status":"ok"}`

### ドメインを使わない場合
- Caddy の自動HTTPSはドメイン必須。ドメイン無しで試すだけなら、`Caddyfile` を `:80 { ... }` に変えてHTTP公開（本番非推奨）するか、無料の試用ドメイン/サブドメインを使う。

## 5. 動作確認（リリースチェックリスト）

- [ ] LP（`/`）が表示され、ソラ先生のアバター・アニメデモが動く
- [ ] 新規登録 → ログインできる（Cookieが付く）
- [ ] レッスン開始 → **録音だけ**送ってFB（スコア・課題・基礎練）が返る
- [ ] レッスン名のリネームができる
- [ ] 他人のセッションにアクセスできない（403/404）
- [ ] 連続で大量に音声を送ると 429（レート制限）になる

## 6. 運用

- **ログ**: `docker compose -f docker-compose.prod.yml logs -f backend`
- **更新デプロイ**: `git pull && docker compose -f docker-compose.prod.yml --env-file .env up -d --build`
- **バックアップ**: SQLite と音声は `app_data` ボリューム（`/var/lib/docker/volumes/...app_data/_data`）。定期的に `/data/app.db` をコピー。
- **ディスク**: 音声ファイルが溜まる。`/data/uploads` を定期削除するcron推奨（例: 30日より古いものを削除）。

## 7. リスクと割り切り（To Cテスト前提）

| リスク | 内容 | 対応 |
| --- | --- | --- |
| 原曲取得(yt-dlp) | YouTube規約/IPブロック/著作権 | **既定OFF**。録音単体でFBするので公開時は無効が安全。比較が欲しい時だけ限定的に検討 |
| 解析のCPU負荷 | 同時アクセスでCPU飽和 | レート制限（既定: 60秒に8回/人）+ WEB_CONCURRENCY を小さく。様子を見て増強 |
| 音声の保存 | プライバシー | 本人のみ参照。溜まったら削除。プライバシーポリシーの掲示を推奨 |
| FB品質 | ルールベースのため文章は定型的 | 反応を見て、必要ならLLM併用（コスト増）を別途検討 |

## 8. 公開後すぐにやること（マーケ連携）

- 計測: アクセス解析（無料のCloudflare Web Analytics 等）を1行入れる
- 入口: X / note で告知（マーケター成果物のローンチプランに従う）
- 目標例: 7日で登録N人・録音送信N件・「課題→基礎練→再録音」完走率を観察

## 9. コスト最適化メモ

- まずは1台で十分。ユーザーが増えてCPUが厳しくなったら、解析だけを別ワーカー/キュー化（設計書 docs/07 の拡張）に進む。
- 画像が大きいので、VPSのディスクは最低25GB以上を推奨。
