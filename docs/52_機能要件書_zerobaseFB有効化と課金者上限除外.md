# zero-base FB 有効化と課金者の月次上限除外 機能要件書

関連: docs/43（zero-base FB 設計・実装済/フラグOFF）, docs/31（有料プラン）, docs/42（FB品質正本）。CEO決定: zero-base FB を GO（有料粗利98%・下振れは月¥2,000上限で限定。プレミアム¥800/月・手取り約¥771）。

## 1. 概要
- **一言**: 生音声を"聴いて"推論するFB（zero-base FB, docs/43）を本番で有効化する。ただし**お金を払っている有料ユーザーは月次コスト上限の対象外**にして、無料枠が予算を食っても課金者が格下げされないようにする。
- **解決する課題**: (1) ルールベース解析だけでは拾えない声の質感を"聴いて"講評し、上達体験と有料転換を強める。(2) 既存の月次上限¥2,000は無料・有料共通のため、無料ユーザーの利用で予算が尽きると**有料ユーザーまでルールベースFBに格下げ**され課金の約束を破る——これを防ぐ。

## 2. 想定ユーザー / ユースケース
- **無料ユーザー**: 月10回の解析枠内で zero-base FB の"驚き"を体験 → 有料転換の動機になる。
- **有料ユーザー（プレミアム¥800/月）**: 無制限解析。**いつ解析しても** zero-base FB が返る（月中に予算上限へ到達しても格下げされない）。

## 3. スコープ
### 3.1 対象（やること）
- zero-base FB の本番有効化（`enable_zero_base_fb`）。
- 有料ユーザーを月次コスト上限（`llm_monthly_budget_jpy`=¥2,000）の**判定対象から除外**（呼び出しは行う）。原価の**記録は継続**（監視のため）。
- 無料ユーザーは従来どおり上限の対象（到達後はルールベースFBへフォールバック）。
- 原価監視: 週次レポートに「AI原価・粗利・cap到達率」を出せるよう、当月概算コストと zero-base 呼び出し回数を参照可能にする。

### 3.2 対象外（やらないこと）
- zero-base FB のプロンプト・出力仕様の変更（docs/43 のまま）。FB品質正本 docs/42 も不変。
- 無料ユーザーへの zero-base 提供回数の追加ゲート（今回は「無料10回枠の中で提供／上限到達でルールベース」で足りる。将来必要なら別途）。
- 価格改定・Stripe 設定変更（¥800 の実値と docs/31・docs/20 の¥500記述の乖離是正は別タスク）。
- 週次レポートの文面生成そのもの（growth-operator 側の運用タスク）。

## 4. ユーザーストーリー
- US-01: 有料ユーザーとして、月末に解析しても"聴いてくれる"FBが必ず返ってほしい。なぜなら無制限を謳う対価を払っているから。
- US-02: 無料ユーザーとして、無料枠の中で"聴いてくれる"FBを体験したい。なぜなら有料に上げる価値を知りたいから。
- US-03: 運営者（CEO/growth-operator）として、AI原価と粗利を週次で把握したい。なぜなら黒字を崩さず投資判断するため。

## 5. 機能要件
### FR-01: zero-base FB の有効化
- **概要**: 録音FB経路で zero-base FB（`llm.generate_feedback`）を既定で使う。
- **詳細仕様**: `settings.enable_zero_base_fb=True` を既定にする（env で無効化も可）。`llm_enabled`（Geminiキー有）が前提。失敗・タイムアウト時は既存どおりルールベースFBへフォールバック（会話は止めない）。
- **例外**: `llm_enabled=false` の環境では従来どおりルールベースFBのみ。

### FR-02: 有料ユーザーの月次上限除外
- **概要**: 有料ユーザーは `llm_monthly_budget_jpy` の到達可否に関わらず zero-base FB を呼ぶ。
- **詳細仕様**:
  - 判定は `settings.billing_enabled and billing_service.is_premium(db, session.user_id)`。
  - 有料ユーザー: `would_exceed` の結果に関わらず zero-base を呼ぶ。成功時は `llm_budget.record()` で**原価を記録**（監視のため。ブロックはしない）。
  - 無料ユーザー: 従来どおり `would_exceed` が True なら `notify_budget_reached_once()` してルールベースへ。
- **入出力**: 入力＝録音＋セッションのユーザー。出力＝zero-base FB or ルールベースFB。
- **例外**: `billing_enabled=false`（課金未運用の環境）では全員「無料扱い」＝上限対象（安全側）。

### FR-03: 原価・粗利の可視化フック
- **概要**: 週次レポートが参照できる形で、当月の zero-base 概算コストと呼び出し回数を保持する。
- **詳細仕様**: `llm_budget` の台帳に「当月概算コスト(¥)」に加え「当月 zero-base 呼び出し回数」を持たせ、`month_spend_jpy()` と同様に読み出せるようにする（回数はコスト÷単価でも近似可＝最小実装可）。cap到達フラグも参照できること。

## 6. 非機能要件
- **性能**: zero-base は入力音声＋推論で重い（タイムアウト90秒, docs/43）。既存の非同期・フォールバックを維持し、UI応答は止めない。
- **可用性**: Gemini 503 等はルールベースへフォールバック。
- **コスト**: 有料は上限対象外だが、単価¥0.44/回・粗利98%のため無制限でも赤字化しない（1有料が赤字化するには月1,000回超が必要＝非現実的）。無料は月¥2,000上限で全体の下振れを限定。
- **保守性**: 有効/除外は設定と1関数判定に閉じる。即ロールバック可（`ENABLE_ZERO_BASE_FB=false`）。

## 7. 受け入れ基準
- AC-01: `enable_zero_base_fb=True`・`llm_enabled=True` で録音を送ると、zero-base FB 経路（`generate_feedback`）が呼ばれる（失敗時のみルールベース）。
- AC-02: 当月概算コストが上限¥2,000に達した状態で、**有料ユーザー**が録音を送ると zero-base FB が返る（ルールベースに格下げされない）。
- AC-03: 同じ上限到達状態で、**無料ユーザー**が録音を送るとルールベースFBにフォールバックする（従来どおり）。
- AC-04: `billing_enabled=false` の環境では、上限到達時に全員ルールベースへ（有料判定に依存して誤って呼ばない）。
- AC-05: zero-base 成功呼び出しは有料・無料とも `llm_budget` に原価が記録される（監視のため）。
- AC-06: 既存の会話型FB契約（点数・カードを出さない, docs/39）を壊さない。

## 8. 前提・制約
- プレミアム実価格は **¥800/月**（手取り約¥771）。docs/31・docs/20 の¥500記述は未追従（別タスクで是正）。
- zero-base の仕様・プロンプトは docs/43 準拠。FB品質は docs/42 が正本。
- `session.user_id` で課金判定できること（ChatSession はユーザーに紐づく）。

## 9. 未決事項 / 要確認
- Q1: 無料ユーザーへ zero-base を「無料枠10回すべて」提供するか、「最初のN回だけ」に絞るか。→ 本要件は**10回すべて提供＋上限¥2,000で全体を保護**（MVP・転換最大化）。低転換で cap を頻繁に叩くなら将来ゲート追加。
- Q2: 有料が上限対象外になると全体コストが¥2,000を超え得る。→ 有料の増加分は粗利98%で必ず賄えるため許容。監視は FR-03 の週次で行う。
