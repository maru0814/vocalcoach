## 0. 全体像（オーナーがやること3つだけ）
1. **Google Play デベロッパー登録**（$25・一回きり・30分）

## 1. Google Play デベロッパー登録（初回のみ）
1. https://play.google.com/console で Google アカウントを使い「個人」で登録（$25、クレカ払い）
2. 本人確認（身分証）を済ませる。承認まで最大48時間かかることがあるので**最初にやる**
3. 特商法対応で開発者情報（メール・住所の一部）がストアに公開される点は Web版の特商法ページと同じ屋号・連絡先で揃える

## 2. 署名鍵の生成と GitHub Secrets 設定（初回のみ）
手元のPC（Java があればどこでも / なければ VPS 上でも可）で:
```bash
keytool -genkeypair -v \
  -keystore release.keystore \
  -alias sora-release \
  -keyalg RSA -keysize 2048 -validity 10000 \
  -dname "CN=Vocal Coach, O=Vocal Coach Inc., C=JP"
# 聞かれた storepass / keypass は必ずパスワードマネージャに保存
base64 -w0 release.keystore > release.keystore.b64
```
GitHub リポジトリ → Settings → Secrets and variables → Actions に4つ登録:
| Secret 名 | 値 |
| --- | --- |
| `ANDROID_KEYSTORE_BASE64` | release.keystore.b64 の中身 |
| `ANDROID_KEYSTORE_PASSWORD` | storepass |
| `ANDROID_KEY_ALIAS` | `sora-release` |
| `ANDROID_KEY_PASSWORD` | keypass |

⚠️ **release.keystore は絶対に失くさない・リポジトリに入れない**（AC-08）。失くすと同じアプリとして更新できなくなる。パスワードマネージャ＋オフラインバックアップの二重保管。

## 3. ビルド（CI）
1. GitHub → Actions → **Native Android** → Run workflow（main ブランチ）
2. 完了後、Artifacts から取得:
   - `app-debug-apk`: 実機確認用（docs/80 TC-17〜22 をここで実施）
   - `app-release`: **app-release.aab（Play 提出用）** と app-release.apk
3. 実機テスト（docs/80 環境C）が全部パスしたら提出へ

## 4. Play Console 提出手順
1. 「アプリを作成」→ 名前「ソラ先生 - AIボーカルトレーナー」/ 日本語 / アプリ / 無料
2. **アプリのセットアップ**（申告類は §5.3 の下書きをそのまま使う）
3. 「製品版」→「新しいリリースを作成」→ app-release.aab をアップロード
   - 署名は「Google Play アプリ署名」に加入（アップロード鍵=今回の鍵）
4. ストア掲載情報（§5）を入力、スクリーンショットを添付
   - スクショは実機 or エミュレータで `/coach` 画面・FB画面・声診断画面の3枚以上（1080×1920推奨）
5. 「審査に送信」。初回審査は数日〜2週間

## 6. リリース後の運用
- **アプリ障害の一次切り分けは Web 本番の死活確認**（リモートURL方式のため。docs/79 8章）
- アプリ更新が必要になるのは: 権限追加 / Capacitor メジャー更新 / 接続先ドメイン変更 のみ。更新時は `native/android/app/build.gradle` の versionCode を必ず +1
- 告知: リリース確定後、X で「Playストアに出ました」投稿を growth-operator の週次枠に載せる（`sns-strategist` の出稿前レビューを通す）

## 7. iOS（Later・条件つき）
- 必要: Apple Developer Program **$99/年**（オーナー判断待ち・docs/77 決定2）
- リスク: 審査ガイドライン 4.2（最小機能性）で「Webラッパー」と判断される可能性。提出時はプッシュ通知のネイティブ実装など「アプリならでは」の要素追加を再評価する
- プロジェクトは `native/ios/` に同梱済み（マイク権限文言も設定済み）。提出時は macOS + Xcode で `npx cap open ios` → Archive

## 8. Later: 独自ドメイン移行の注意（重要）
- 現在の接続先は duckdns（無料DNS）。**ドメインが失効するとアプリが全滅**する（Web と違い、ユーザーの手元に古い接続先が残り続ける）
- 独自ドメイン移行時は: `CAP_SERVER_URL` を新ドメインにして再ビルド → versionCode +1 でストア更新 → 旧ドメインは最低6ヶ月リダイレクト維持
- ストア公開の前に独自ドメイン取得を済ませるのが理想（年1,500円程度）。オーナーに推奨する
