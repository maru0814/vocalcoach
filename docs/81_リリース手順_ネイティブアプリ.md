# ネイティブアプリ リリース手順（ランブック）

- 作成日: 2026-07-21
- 作成: マーケター（掲載情報）＋ SRE視点（署名・CI手順）
- 上流: docs/77（CEO裁定）/ docs/78（要件）/ docs/79（設計）/ docs/80（テスト計画）
- ゴール: オーナーがこの手順書どおりに進めれば、当日中に Google Play へ提出できる状態

## 0. 全体像（両ストア・オーナーがやること）
**Google Play（§1〜4）**:
1. デベロッパー登録（$25・一回きり・30分）
2. 署名鍵を作って GitHub Secrets に入れる（15分）
3. CI が作った AAB を Play Console にアップロードして提出（1時間）

**App Store（§7）**:
4. Apple Developer Program 登録（$99/年）
5. 証明書・プロファイル・APIキーを作って GitHub Secrets に入れる（Mac 不要・§7.2〜7.4 のコマンドどおり）
6. CI（Native iOS）を実行 → TestFlight で実機確認 → App Store Connect から審査提出

コード・ビルド・掲載文の下書きは会社側（本リポジトリ）で準備済み。

## 1. Google Play デベロッパー登録（初回のみ）
1. https://play.google.com/console で Google アカウントを使い「個人」で登録（$25、クレカ払い）
2. 本人確認（身分証）を済ませる。承認まで最大48時間かかることがあるので**最初にやる**
3. 特商法対応で開発者情報（メール・住所の一部）がストアに公開される点は Web版の特商法ページと同じ屋号・連絡先で揃える

## 2. 署名鍵の生成と GitHub Secrets 設定（初回のみ）
手元のPC（Java があればどこでも / なければ VPS 上でも可）で:
```bash
keytool -genkeypair -v \
  -keystore release.keystore \
  -alias sora-release \
  -keyalg RSA -keysize 2048 -validity 10000 \
  -dname "CN=Vocal Coach, O=Vocal Coach Inc., C=JP"
# 聞かれた storepass / keypass は必ずパスワードマネージャに保存
base64 -w0 release.keystore > release.keystore.b64
```
GitHub リポジトリ → Settings → Secrets and variables → Actions に4つ登録:
| Secret 名 | 値 |
| --- | --- |
| `ANDROID_KEYSTORE_BASE64` | release.keystore.b64 の中身 |
| `ANDROID_KEYSTORE_PASSWORD` | storepass |
| `ANDROID_KEY_ALIAS` | `sora-release` |
| `ANDROID_KEY_PASSWORD` | keypass |

⚠️ **release.keystore は絶対に失くさない・リポジトリに入れない**（AC-08）。失くすと同じアプリとして更新できなくなる。パスワードマネージャ＋オフラインバックアップの二重保管。

## 3. ビルド（CI）
1. GitHub → Actions → **Native Android** → Run workflow（main ブランチ）
2. 完了後、Artifacts から取得:
   - `app-debug-apk`: 実機確認用（docs/80 TC-17〜22 をここで実施）
   - `app-release`: **app-release.aab（Play 提出用）** と app-release.apk
3. 実機テスト（docs/80 環境C）が全部パスしたら提出へ

## 4. Play Console 提出手順
1. 「アプリを作成」→ 名前「ソラ先生 - AIボーカルトレーナー」/ 日本語 / アプリ / 無料
2. **アプリのセットアップ**（申告類は §5.3 の下書きをそのまま使う）
3. 「製品版」→「新しいリリースを作成」→ app-release.aab をアップロード
   - 署名は「Google Play アプリ署名」に加入（アップロード鍵=今回の鍵）
4. ストア掲載情報（§5）を入力、スクリーンショットを添付
   - スクショは実機 or エミュレータで `/coach` 画面・FB画面・声診断画面の3枚以上（1080×1920推奨）
5. 「審査に送信」。初回審査は数日〜2週間

## 6. リリース後の運用
- **アプリ障害の一次切り分けは Web 本番の死活確認**（リモートURL方式のため。docs/79 8章）
- アプリ更新が必要になるのは: 権限追加 / Capacitor メジャー更新 / 接続先ドメイン変更 のみ。更新時は `native/android/app/build.gradle` の versionCode を必ず +1
- 告知: リリース確定後、X で「Playストアに出ました」投稿を growth-operator の週次枠に載せる（`sns-strategist` の出稿前レビューを通す）

## 7. iOS（App Store）提出手順 — Mac が無くても完結する
docs/77 追補（オーナー指示「両ストア」）により、iOS も CI で署名〜TestFlight まで自動化済み。オーナー作業は以下。

### 7.1 Apple Developer Program 登録（初回のみ・$99/年）
1. https://developer.apple.com/programs/ で Apple ID を使い「個人」で登録（審査に数日かかることあり。**最初にやる**）
2. 登録後、https://developer.apple.com/account で **Team ID**（10桁英数）を控える

### 7.2 証明書・プロファイルの作成（初回のみ・Mac不要）
どのLinux/WSLでも可（VPSでもOK）:
```bash
# 1) 秘密鍵とCSRを生成
openssl genrsa -out ios_dist.key 2048
openssl req -new -key ios_dist.key -out ios_dist.csr \
  -subj "/emailAddress=yumaruyama0814@gmail.com/CN=Vocal Coach Distribution/C=JP"
```
2. https://developer.apple.com/account/resources/certificates → 「+」→ **Apple Distribution** → 上の `ios_dist.csr` をアップロード → `distribution.cer` をダウンロード
3. p12 に変換:
```bash
openssl x509 -inform DER -in distribution.cer -out distribution.pem
openssl pkcs12 -export -inkey ios_dist.key -in distribution.pem \
  -out ios_dist.p12 -passout pass:<強いパスワード>
base64 -w0 ios_dist.p12 > ios_dist.p12.b64
```
4. Identifiers → 「+」→ App ID `com.vocalcoach.sora`（Capabilities は既定のまま）
5. Profiles → 「+」→ **App Store Connect** 配布 → App ID と証明書を選択 → 名前 `SoraAppStore` → `.mobileprovision` をダウンロード → `base64 -w0` で文字列化

### 7.3 App Store Connect API キー（TestFlight 自動アップロード用・初回のみ）
1. https://appstoreconnect.apple.com → ユーザとアクセス → 統合 → App Store Connect API → 「+」で **App Manager** 権限のキーを発行
2. **Key ID** / **Issuer ID** を控え、`.p8` ファイルをダウンロード（一度しか落とせない）→ `base64 -w0` で文字列化

### 7.4 GitHub Secrets 登録（初回のみ）
| Secret 名 | 値 |
| --- | --- |
| `IOS_CERT_P12_BASE64` | ios_dist.p12.b64 の中身 |
| `IOS_CERT_PASSWORD` | p12 のパスワード |
| `IOS_PROVISIONING_PROFILE_BASE64` | .mobileprovision の base64 |
| `IOS_TEAM_ID` | Team ID（10桁） |
| `ASC_API_KEY_ID` / `ASC_API_ISSUER_ID` | 7.3 で控えた値 |
| `ASC_API_KEY_P8_BASE64` | .p8 の base64 |

⚠️ `ios_dist.key` / `ios_dist.p12` / `.p8` はパスワードマネージャ＋オフラインの二重保管。リポジトリに入れない（AC-08）。

### 7.5 App Store Connect でアプリ登録 → 提出
1. App Store Connect → マイApp → 「+」→ 新規App: 名前「ソラ先生 - AIボーカルトレーナー」/ プライマリ言語 日本語 / バンドルID `com.vocalcoach.sora` / SKU `sora-vocal-001`
2. GitHub → Actions → **Native iOS** → Run workflow（main）。成功すると TestFlight にビルドが届く（処理に15〜30分）
3. TestFlight で自分の iPhone に配信して実機テスト（docs/80 TC-27）
4. App情報・スクリーンショット（6.7型 1290×2796 ほか）・§5 と同じ説明文・プライバシーURL（/legal/privacy）を入力
5. App プライバシー: 収集データ=メール（アカウント）/ 音声（App機能）。トラッキング=なし
6. 価格 無料 → 「審査へ提出」

### 7.6 iOS 固有の注意
- **審査 4.2（最小機能性）リスク**: WebView 主体のため「Webサイトと同等」と指摘される可能性がある。リジェクトされた場合の打ち手（順に検討）: ①審査メモに録音→AI添削がアプリの中核体験である旨を明記 ②ネイティブプッシュ通知（FCM/APNs）追加 ③録音のネイティブ実装。①は初回提出時から審査メモに書いておく
- iOS の WebView は Web Push が動かない（通知は将来のネイティブ実装まで無し）
- 課金導線はアプリ内に無いため IAP 審査（3.1.1）は「リーダー型」該当。審査で問われたら「購読はWebで契約、アプリは利用のみ」と回答

## 8. Later: 独自ドメイン移行の注意（重要）
- 現在の接続先は duckdns（無料DNS）。**ドメインが失効するとアプリが全滅**する（Web と違い、ユーザーの手元に古い接続先が残り続ける）
- 独自ドメイン移行時は: `CAP_SERVER_URL` を新ドメインにして再ビルド → versionCode +1 でストア更新 → 旧ドメインは最低6ヶ月リダイレクト維持
- ストア公開の前に独自ドメイン取得を済ませるのが理想（年1,500円程度）。オーナーに推奨する
