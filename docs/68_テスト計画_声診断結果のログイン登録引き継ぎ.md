# 声診断結果のログイン/登録後引き継ぎ テスト計画

対象: `docs/67_仕様変更_声診断結果のログイン登録引き継ぎ.md`
実装: `frontend/src/app/voice-type/page.tsx`（worktree: `.claude/worktrees/voice-type-login-bridge`）

## 1. スコープ
- 未登録で声診断した結果を、ログイン/登録の画面遷移をまたいで sessionStorage で引き継ぐ機能。
- フロントエンドのみの変更。バックエンドAPI（`/api/v1/voice-type/analyze`, `/api/v1/auth/*`）は変更なし。

## 2. 対象機能要件 / 受け入れ基準
FR-01〜04、AC-01〜05（`docs/67`）。

## 3. 実施環境と制約（更新: SRE対応後）
- worktree内で `npm install` 後、`next dev` を手動起動（`.claude/launch.json` のプレビューはmainのcwdに解決されworktreeの変更を拾わないため、絶対パス手動起動が必要 — 既知の罠）。
- 当初、本番同等のbackend dockerイメージのビルドが `praat-parselmouth` のwheelビルド失敗（Apple Silicon = linux/arm64向けpre-builtホイールが配布されておらずソースビルドに落ち、`python:3.12-slim` にビルドツールが無いため失敗）で止まっていたが、SREが `backend/Dockerfile`（ローカル開発用。`Dockerfile.prod` はx86_64本番のため対象外）に `build-essential`/`cmake`/`libsndfile1` を追加し解消。worktree内で `docker build` により単体イメージをビルドし、既存の `claude-md-db`（ローカルMySQL）内に検証専用DB `voicetype_qa_test` を作成した上でコンテナを起動、実バックエンド＋実DBでのE2Eを実施できた。
- 未ログイン診断用の音声は、マイク入力の代わりに `say`コマンド（macOS標準TTS）で生成した実音声（母音の連続発話、22050Hz/8.3秒）を使用。`voiced_ratio≈0.85`で `_looks_like_singing` ゲートを通過することを確認済み（`tools/voice_synth.py` の合成波形はpyinでf0検出できず`NO_VOICE`になったため不採用）。

## 5. 合格基準
- TC-01, TC-02, TC-03, TC-05, TC-06, TC-07, TC-08: 実施済みで全てPASS。
- TC-04: 未実施だがTC-03と同一分岐のため合否判定には影響しないと判断（任意でリリース前に確認）。

## 6. 総合判定
**合格（Pass）**。sessionStorageブリッジ方式によるFR-01〜04は、フロントエンド単体の境界値確認に加え、実バックエンド・実DB・実際の新規登録フローによるE2E（TC-03/TC-05）でも要件通りに動作することを確認した。既存の未登録トライアル動線（docs/11 FR-06）や「もう一度診断」系ボタンにも回帰は無い。

## 7. 検出・対応した別課題
- `docker compose build backend`（`docker/docker-compose.yml`、main配下）が `praat-parselmouth` のwheelビルドで失敗し、Apple Silicon等のarm64ホストでローカルのbackend dockerイメージを再ビルドできない問題があった。SREが本セッションで原因を特定し、`backend/Dockerfile`（ローカル開発用のみ）に`build-essential`/`cmake`/`libsndfile1`を追加して解消（worktree内で確認、本番用`Dockerfile.prod`はx86_64のため無変更）。**mainブランチ側にはまだ未反映**（本チケットのスコープ外の別修正のため、別途コミット/PRが必要）。
