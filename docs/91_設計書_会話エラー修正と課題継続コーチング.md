# 91. 設計書 — 会話エラー修正（Gemini thinking_budget）と課題継続コーチング

- 作成日: 2026-08-02
- 担当: バックエンドエンジニア
- 関連: docs/42（FB品質基準・単一ソース）, docs/66（対話モデル）, docs/39（会話型FB）
- 対象コード: `backend/app/core/config.py`, `backend/app/coaching/llm.py`, `backend/app/coaching/rule_engine.py`, `backend/app/coaching/feedback_builder.py`

## 背景（ユーザー報告の2障害）

1. **原因1（会話エラー）**: テキスト会話のモデル既定が `gemini-flash-lite-latest`（浮動エイリアス）
   だったため、Google 側で新世代 Gemini（3.5 系）へ切り替わった際に
   `thinking_config=ThinkingConfig(thinking_budget=0)` が INVALID_ARGUMENT で拒否され、
   テキスト返答がすべて失敗 → 正直フォールバック文しか返らなくなった。
2. **原因2（毎回違うダメ出し）**: 歌い直し判定（`_audio_recheck`）が
   `diagnose_task(..., exclude=[current_task])` で**前回の課題を除外**して次の課題を探す仕様
   だったため、録音を送るたびに毎回別のダメ出しが返り、ユーザーのモチベーションを削いでいた。

## 方針

### 修正1: thinking 無効化はモデル世代を見て適用（＋モデルのバージョン固定）

- `llm_model` / `llm_chat_model` の既定を `gemini-2.5-flash-lite` に**固定**する
  （`-latest` エイリアスは今後使わない。エイリアスの世代切替で挙動が壊れるため）。
- `llm.py` に `_thinking_off(model)` ヘルパーを追加。**モデル名に "2.5" を含む時だけ**
  `ThinkingConfig(thinking_budget=0)` を返し、それ以外（Gemini 3 系以降・不明なエイリアス）は
  `None`（＝モデル既定に任せる）。thinking を切るのは「思考トークンが出力枠を食い潰して
  本文が途切れる」2.5 系固有の対策なので、対応世代だけに限定する。
- 適用箇所: `_complete` / `_complete_with_tools` / `classify_register_audio` /
  `analyze_pronunciation`。分析ターン（`generate_feedback` の thinking_budget=512）も
  同じガード（2.5 系のみ指定）。
- 効果: env でどのモデルに上書きしても thinking_config 起因の INVALID_ARGUMENT は発生しない。

### 修正2: 課題継続コーチング（exclude 廃止 → クリアまで伴走＋微改善の励まし）

`_audio_recheck`（歌い直し判定）を次のロジックに変更する。

1. **課題の除外をやめる**: `exclude=[current_task]` による自動乗り換えを廃止。
2. **フォーカス継続**: 課題は「解析で検知されなくなる＝クリア」まで同じものを見続ける。
   - `cleared = （前回は検知されていた）かつ（今回は検知されない）`
   - 検知判定は taxonomy の `diagnose` と発声診断（voice_coach）→課題マッピングの両方を見る。
3. **クリア時**: 一緒に大きく喜び、その時点の解析で**自然に**検知される次の課題があれば
   練習を1つ紹介（人工的な除外はしない）。無ければ気持ちよく締める。
4. **未クリア時（ここが本丸）**: ダメ出しに乗り換えず、**前回の音響指標と今回を比較**して
   「わずかでも改善している点・方向性が合っている点」を実測で拾い、
   「少しずつ良くなっていますよ」「その感覚です！」と具体的に励ましながら
   同じ課題・同じ練習をステップバイステップで続けるよう導く。
   - 微改善の検知は `feedback_builder.build_micro_progress(baseline, current)`（新設）。
     指標ごとにノイズ床（この幅未満は測定ゆらぎとして拾わない）を持ち、
     **床を超えた実測の良化だけ**を励ましの根拠にする（嘘の励ましをしない＝docs/42 §5）。
     H1-H2 は増減でなく「flow phonation の目標帯（≈4.5dB）へ近づいたか」で判定する。
   - 改善が1つも無い時は、ダメ出しを並べず取り組み自体を認め、
     チェックポイントを1つだけ添えて再挑戦を促す（正直・前向き）。
   - 比較基準（`baseline_analysis`）は毎回今回の解析で更新する＝常に「前回 vs 今回」。
5. **主訴（focus_task）最優先**: ユーザーがテキストで「ここを直したい」と伝えた主訴は、
   解析で検知できるか否かに関わらず**最優先で課題に採用**する（`_audio_diagnose` /
   `_audio_recheck` の両方）。解析で強く検知されない場合はその旨を facts に添え、
   感覚を否定せず寄り添う（docs/42 §5 の声区尊重と同じ思想）。
6. **「別の課題に変える」チップ（avoid_task）は存続**: ユーザーが明示的に乗り換えを
   求めた時の除外は本来の用途なので残す。廃止するのは**自動の**除外だけ。

### プロンプト追加

- `rule_engine._ENCOURAGE_INSTR`（新設）: 未クリア継続時の励まし指示。
  「良くなった点が facts にあれば必ず1つ具体的に挙げて『少しずつ良くなっていますよ』
  『その感覚です！』と褒める／無ければダメ出しをせず取り組みを認める／課題と練習は変えない」。
- FB方針の正本 docs/42 §6（練習継続の原則）に「課題はクリアまで変えない・微改善を励ます・
  主訴最優先」を追記し、skill 版（vocal-trainer）の Phase E 記述も揃える。

## 影響範囲・互換性

- `chat_sessions` のスキーマ変更なし（`focus_task` / `avoid_task` / `baseline_analysis` は既存カラム）。
- `build_progress_payload` は `_audio_recheck` から参照されなくなるが、後方互換のため残す。
- LLM 不可時のフォールバック文も新ロジックに合わせて確定的に生成（hermetic テスト可能）。

## テスト

`backend/tests/test_task_continuity.py`（新設・hermetic / LLMスタブ）:

- 未クリアの歌い直し → 課題を乗り換えない（current_task 維持）・励まし文に微改善の実測が載る
- 改善ゼロの歌い直し → 嘘の励ましをしない（「まだ大きく動いていない」系の正直な文）
- クリアした歌い直し → クリアを喜ぶ・自然検知の次課題 or 締め
- `build_micro_progress` の微改善検知（ノイズ床・H1-H2 の目標帯接近）
- focus_task が診断で最優先になる
- `_thinking_off` の適用判定（2.5 系のみ）・モデル既定が固定バージョンであること

実行: `cd backend && python -m unittest tests.test_task_continuity tests.test_conversational_fb -v`
