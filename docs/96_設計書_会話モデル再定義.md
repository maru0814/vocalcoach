## 1. なぜ再定義するのか

これまでの「最適なモデル」は、暗黙に **「安くて速いモデルの中で、いちばんマシなもの」** だった。
その結果が flash-lite（最安クラス）で、ChatGPT級との会話比較で **18戦0勝** の会話力しか出せなかった。

会話レイヤー刷新（PR #303）で前提が2つ変わった。

1. **モデルの仕事が増えた。** 意図の理解（承諾・訂正・雑談・依頼の判別）、ツールを呼ぶかの判断
   （録音を聴き直すか、主訴を記録するか）まで、全部モデルの責任になった。
   最安クラスでは務まらない仕事である。
2. **過去の測定は前提ごと無効になった。** docs/66 の「格上げしたら多ターンが悪化した」という
   2026-07-12 の測定は、正規表現ゲートが会話に割り込んでいた時代のもの。
   ゲートを撤去した今のアーキテクチャでは、あの結果を根拠に格上げを止められない。

## 2. 「最適」の新しい定義

> **会話の噛み合いで ChatGPT 級に到達できるモデルのうち、応答が最も速く、
> かつ運用上安全に固定・監視・載せ替えできるもの。**

選定基準を優先順に並べ直す（旧定義からの変更点: コストを基準から削除、①②を新設）。

| 優先 | 基準 | 測り方 |
| --- | --- | --- |
| 1 | 多ターンの噛み合い・雑談・共感 | soar_eval（multiturn / naturalness / ChatGPT級との blind head-to-head） |
| 2 | ツール判断の正しさ | 聴くべき時に聴く・呼ぶべきでない時に呼ばない（PR #303 のスモーク相当を eval 化） |
| 3 | 応答の速さ | 中央値 3秒以下・最悪でも `llm_timeout_sec=20` を割らないこと。**thinking（思考モード）を切れること（tb=0 受理）が実質の足切り条件** |
| 4 | 事実忠実性 | 橋渡しなし否定率・捏造検知（soar_eval の決定論指標） |
| 5 | 運用安全性 | バージョン固定できる・日次ヘルスチェックに載る・env 1行で載せ替えられる |
| — | ~~コスト~~ | 基準から除外（運用者決定）。月次実測の監視のみ継続 |

## 3. 候補の評価（docs/92 の実測に基づく）

| 候補 | 会話力の見込み | thinking を切れるか | 速さ | 評価 |
| --- | --- | --- | --- | --- |
| gemini-3.5-flash-lite（旧既定） | ✗ 18戦0勝の当事者ティア | ✅ | ◎ 1.1s | 会話の主役には不適。**緊急時の速度優先の載せ替え先** |
| **gemini-3.5-flash（PR #303 採用）** | ○ flash ティア・3.5世代（声の聞き分けで唯一まともだった地力） | ✅ 実測済（docs/92 §2-2） | ○ thinking を切れるので尾の重さを回避できる | **承認。現時点の最適解** |
| gemini-3.6-flash | ○ 未測 | ❌ 400 拒否 → 思考が強制され遅延 | △ 音声系で中央値 7.5s | 次点候補。採るならタイムアウト・ローディング UX の手当てとセット |
| gemini-3.1-flash-lite | ✗ lite ティア | ✅ | ◎ 2.6s | ヘルスチェック検知時の速度優先の載せ替え先 |
| 上位ティア（3.5-pro 等）・他社（Claude） | ◎ 期待値最大 | — | 未測 | §5 のエスカレーション条件を満たした時に検討。他社導入はキー管理・ヘルスチェック・世代ガード相当の運用整備が追加で必要になる点を判断材料に含める |

**結論: PR #303 の `gemini-3.5-flash`（バージョン固定）をアーキテクトとして承認する。**
ただしこれは「暫定王者」であり、確定は §4 の測定ゲートを通ってから。

補足（docs/92 §5.10 の「3.5-flash は尾が重い（最大49秒）」との整合）:
あの実測は音声入力＋thinking 有効の分析タスク。チャット経路は thinking を切れる（tb=0 受理）ため
同じ尾は出ない見込みだが、**チャット実測はまだ無い**。§4 のゲートでレイテンシ分布も必ず測る。

## 4. 確定のための測定ゲート（PR #303 マージ後に実施）

新アーキテクチャ＋gemini-3.5-flash で soar_eval を回し、以下で合否を判定する。

| 指標 | 合格ライン | 根拠 |
| --- | --- | --- |
| ChatGPT級との head-to-head | 勝率 40% 以上（18-0 → 拮抗圏） | 「ChatGPT級に到達」の定義 |
| 萎え率（holistic） | 27% → 15% 以下 | 過剰拒否の解消確認 |
| 多ターンの噛み合い | docs/66 時代の 6.5 を下回らない | 格上げで多ターンが悪化しないことの確認 |
| チャット応答レイテンシ | 中央値 ≤3s・p95 ≤10s・20s 超なし | 体感とタイムアウト保護 |

- **合格** → 3.5-flash を確定。本書に実測を追記して閉じる。

### 4.1 実測結果（2026-08-09 ベースライン。詳細: `scripts/soar_eval/reports/REPORT_baseline_35flash_20260809.md`）

| 指標 | 実測 | 判定 |
| --- | --- | --- |
| h2h（18会話・2審合議） | 2勝16敗（噛み合い 5.6 vs 8.1） | ✗ |
| 萎え率 | 12.5%（前回27%） | ✓ |
| dodged | 0%（前回10.5%） | ✓ |
| レイテンシ | 中央値1.49s / p95 3.07s / 20s超なし | ✓ |

**判定: 3.5-flash は未確定のまま維持。** 敗因分析では h2h 敗着の大半が「長さ・テンポ」と
「曲名検索ツールの誤爆」で、モデルの地力より先に削るべき層がある。docs/94 憲法の順序
（ツール改善 → プロンプト改善 → モデル）に従い、ツール宣言の改善＋docs/97 第1弾の実施後に
再測して、それでも勝率40%未満なら §3 の次候補（3.6-flash）試験へ進む。
- **不合格（会話力不足）** → gemini-3.6-flash（レイテンシ手当てとセット）→ それでも未達なら
  上位ティア・他社モデルの検討を CEO 判断に上げる。
- **不合格（レイテンシ）** → thinking 設定・max_tokens の調整で再測 → 改善しなければ 3.6 系と同じ扱い。

## 5. 障害時の載せ替え順序（ヘルスチェック検知時）

日次ヘルスチェック（`scripts/ops/gemini_model_healthcheck.py`）は `llm_chat_model` を監視対象に
含んでいることを確認済み。3.5-flash が死んだ場合の env 載せ替え第一候補:

1. 品質優先: `gemini-3.6-flash`（世代ガードが thinking を自動で最小予算に引き上げるため壊れない）
2. 速度優先: `gemini-3.5-flash-lite`（会話力は落ちるが確実に速い）

## 6. やらないこと

- エイリアス（`-latest`）の使用（docs/92 で実証済みの禁じ手）
- 正規表現ゲートの復活によるモデル負荷の軽減（docs/94 憲法違反）
- コストを理由にした候補の足切り（運用者決定に反する）
