# 声タイプ診断 ローンチ＆SNS自動運用設計

> マーケター作成。土台は `docs/23_ゼロ円集客プラン.md`。本書はその上に、
> 新しい目玉「声タイプ診断（8キャラのシェア型診断）」を集客エンジンに据える具体策と、
> SNSを“自動運用”する設計をまとめる。**誇大表現はしない。実際にできることだけ書く。**

## 0. 結論（先に要点）
1. **集客の心臓 = 声タイプ診断のシェアループ**。診断結果カード（キャラ＋総合スコア＋似た声質アーティスト）が、ユーザー自身の手で拡散される“勝手に広がる広告”。広告費ゼロ。
2. **入口は2つに整理済み**: ①LPに診断セクション（未登録者の好奇心フック）②`/coach` 一覧に導線（既存ユーザーの再訪・シェア）。
3. **SNSは半分まで自動化できる**。X（旧Twitter）は公式APIで日次自動投稿が可能（雛形スクリプト同梱）。Instagram/TikTokは規約上「半自動（下書き生成→手動投稿）」が現実解。
4. **狙うのは“診断 → シェア → 流入 → また診断”の輪を回し続けること**。1人運用でも回るよう、投稿を自動化して手を空ける。

---

## 1. ターゲット（再掲・1人に絞る）
- **独学で歌を練習している20〜30代**。カラオケで高音が苦しい/音痴か不安/教室は気後れ。
- 診断フックで効くのは「自分の声を“言葉で”知りたい」欲求。**MBTI診断が刺さる層と同じ**＝シェアで友達と比べたい。

## 2. コアメッセージ
- **一言**: 「あなたの声、どのタイプ？15秒歌うだけで分かる（無料）」
- 補足3つ:
  - 8タイプのキャラで、自分の声に“顔”がつく
  - 似た声質のアーティスト（男女2人ずつ）が分かる
  - 結果はワンタップでシェア → 友達も診断したくなる

## 3. なぜ“診断”が集客に効くか（仕組み）
```
ユーザーが診断 → 結果カードが嬉しい/面白い → Xや友達にシェア
   → 見た人が「自分もやりたい」→ LP/診断ページに流入 → 登録 → また診断
```
- **獲得単価ゼロ**: 1人の診断が、平均 k 人の新規流入を呼べば（k>0.2 でも）複利で増える。
- **MBTI/性格診断がバズる理由と同じ**: ①自分のことが分かる ②キャラで可愛い/シェアしやすい ③友達と比べたい。
- 既に実装済みで効くポイント: キャラ8種・スコア・近いアーティスト・Xシェア文/画像保存ボタン。

## 4. SNS自動運用 設計（ここが本題）

### 4-1. 自動化レベルの現実
| チャネル | 自動投稿 | 実態 | 推奨運用 |
| --- | --- | --- | --- |
| **X（旧Twitter）** | ◎ 可能（※有料） | 公式API v2。2026/2〜従量課金 約$0.01/投稿（月¥100前後） | **日次自動投稿**（同梱スクリプト＋cron）。初期は手動推奨 |
| note | △ 半自動 | 公式投稿APIなし | Geminiで**記事下書き生成**→手動公開（週1） |
| Instagram | △ 半自動 | 個人運用の自動投稿は制限が厳しい | Buffer等で**予約投稿**、or 下書き→手動 |
| TikTok / Shorts | △ 半自動 | アップロードAPIは審査・制約あり | 台本/字幕をAI生成→撮影・投稿は手動 |

> 結論: **「文面の生成」と「Xへの投稿」は完全自動化、他は“生成は自動・投稿は人”** が、規約に反せず1人で続く落としどころ。

### 4-2. 同梱した自動投稿ツール（X）
場所: `scripts/sns_autopost/`（README参照）
- 仕組み: **曜日で投稿の柱をローテ** → Geminiで文面生成（無ければテンプレ）→ X API v2 に投稿。
- 投稿の3本柱:
  1. **診断誘導**（月・金）: 「あなたの声どのタイプ？」→ `/voice-type`
  2. **発声Tips**（火・木・日）: 1日1つの実践メモ → 本体へ
  3. **声タイプ図鑑**（水・土）: 8タイプを1種ずつ紹介 → `/voice-type`
- 安全装置: 既定 `DRY_RUN=1`（うっかり投稿しない）／盛った文・URL欠落は自動でテンプレ差し替え／キーは `.env`（Git除外）。
- 動作確認済み（ドライランで3柱とも生成OK）。

#### 起動手順（要約）
```bash
cd scripts/sns_autopost
python -m venv .venv && . .venv/bin/activate && pip install -r requirements.txt
cp .env.example .env   # GEMINI_API_KEY と X の4キーを入れ、DRY_RUN=0
python generate_and_post.py        # 本投稿
# VPSで毎朝9時:  0 9 * * * cd .../sns_autopost && .venv/bin/python generate_and_post.py
```
> **必要な準備（ユーザー側）**: X開発者アカウント（無料）でアプリ作成し「Read and write」権限のキーを発行。キーは `.env` に入れる（チャットに貼らない）。

## 5. 最初の14日（診断ローンチの動き方）
- **D0**: 自分でX/note/友達に「声タイプ診断つくった」と告知。自分の診断結果カードを実例として投稿。
- **D0–D14**: 自動投稿ON（X）。毎晩、自分の手で1件だけ“人格のある”反応・引用（自動投稿に頼り切らない）。
- **D3**: 診断を受けた知人5人に「シェアして友達と比べて」と依頼（最初の輪を人力で点火）。
- **D7**: 反応が良かった投稿フォーマットを `themes.py` に反映（テンプレを勝ち筋に寄せる）。
- **D14**: 数字を見て、診断ページの文言/シェア文をA/B修正。

## 6. KPI（14〜30日・盛らない現実値）
| 指標 | 目安 | 取り方 |
| --- | --- | --- |
| 診断実行数 | 100/月 | サーバーログ（`/api/v1/voice-type/analyze` の件数） |
| 診断→シェア率 | 10%以上 | シェアボタン押下を計測（要1行の計測埋め込み・任意） |
| 診断→登録率 | 既存登録フローで観測 | 登録数の伸び |
| X経由の流入 | 投稿ごとに観測 | UTM or 専用導線。無料のCloudflare Web Analyticsを1行 |
| 自動投稿の継続 | 30日連続投稿 | cronログ |

> ※ シェア率やk値は“やってみないと分からない”。**まず計測を1行入れて、回しながら直す**のが正攻法。

## 7. 正直なリスク・前提
- **X APIは2026/2より従量課金**（無料枠廃止）。低額だが課金設定が要る。初期は**手動投稿（ゼロ円）**で始め、手応えが出たら自動化（課金）に移行が無難。
- **診断のバズは確約できない**: フックは強いが、最初の点火（知人の協力・自分の発信）は人力が要る。
- **キャラ/診断の精度は“傾向の推定”**: プロダクト同様、盛らずに「傾向」と明記済み。誇大広告にしない。
- **計測なしでは改善できない**: KPIの「シェア計測」「アクセス解析」の1行埋め込みを早めに。

## 8. 次の一手（おすすめ着手順）
1. **計測を1行**（Cloudflare Web Analytics）＋ シェアボタン押下イベント計測。
2. **X自動投稿をON**（開発者キー発行 → `.env` → cron）。← 同梱スクリプトで即運用可。
3. **OGP画像**をタイプ別に（Xでの見栄え＝クリック率。効果大）。
4. 反応を見て `themes.py` の勝ちパターン反映 → note週1の下書き自動生成へ拡張。
