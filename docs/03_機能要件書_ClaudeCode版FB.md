# Claude Code版 ボーカルFB機能 機能要件書

> PdM作成。`docs/01_要件定義.md`（Web版MVP）の補完ドキュメント。
> 本書は **Claude Code skill として動く** ボーカルトレーナーFB機能を定義する。

## 1. 概要
- ユーザーが Claude Code 上で `vocal-trainer` スキルを呼び出し、ローカルの音声ファイル（または歌唱の説明テキスト）を渡すと、即座にボーカルFBが返ってくる機能。
- 解決する課題: Web版はアカウント作成・サーバー起動が必要で、ちょっと録ったものを今すぐ聴いて欲しい場面に向かない。ローカルで動く Claude Code skill なら、思いついた瞬間にFBを得られる。

## 2. 想定ユーザー / ユースケース
### 2.1 ペルソナ
- 独学で歌を練習している人（初心者〜中級者）
- Claude Code を普段から使っている人（このプロダクトの初期ユーザー像）
- スマホやDAWで録音した音源をPCに置いている

### 2.2 主要ユースケース
- **UC-01: 録ったばかりの音源にFBが欲しい**
  - 練習で気になったフレーズを録音 → そのまま Claude Code でFB依頼 → 改善ポイントを次の練習に反映
- **UC-02: 過去録音と比べたい**
  - 1ヶ月前の録音と今の録音を順に渡して比較してもらう
- **UC-03: 自己評価とトレーナー評価のズレを知る**
  - 「サビが弱かった気がする」と自己評価を添えて渡し、客観評価と一致するか確認する

## 3. スコープ
### 3.1 対象（MVPでやること）
- ローカル音声ファイル（wav / mp3 / m4a）のパス受け取り
- **カバー曲の場合の原曲参照（ファイル / URL / アーティスト+曲名）の必須取得**
- **`tools/audio_analyzer.py` による音声直接解析**（f0・テンポ・キー・ビブラート・ロングトーン安定度・動的レンジ等）
- 解析結果を主材料とした4軸（音程・リズム・表現・総合）でのスコア提示
- ユーザーへのヒアリング（自己評価など、解析データの補強情報として）
- 良かった点・改善ポイント・次の練習メニューを含むFBテキスト生成
- **原曲との4軸比較（発声・リズム・音感・表現）と「原曲歌手っぽく歌うアプローチ」の提示**
- 過去FBとの差分コメント（同じ会話セッション内で複数渡された場合）

### 3.2 対象外（やらない）
- 完全な楽譜採点（音符の正誤マッチング）。本MVPはf0傾向ベースのフィードバックに留める
- FB履歴の永続保存（履歴はWeb版に委譲。Claude Code版はセッション限り）
- 楽曲データベースとの照合（カラオケ採点のような正解照合はしない）
- リアルタイム録音
- 課金 / アカウント機能

## 4. ユーザーストーリー
- **US-01**: 歌の練習者として、録ったばかりの音源パスを Claude Code に渡すだけで、5分以内にFBを受け取りたい。なぜなら、感覚が新鮮なうちに改善点を試したいから。
- **US-02**: 歌の練習者として、自分の自己評価とトレーナー評価のズレを知りたい。なぜなら、自分の耳がどこまで信頼できるか分かれば独学の精度が上がるから。
- **US-03**: 歌の練習者として、過去録音と比べてどこが伸びたか言語化されたい。なぜなら、見えない成長を可視化できればモチベーションが続くから。
- **US-04**: 歌の練習者として、FBに具体的な練習メニューが含まれていてほしい。なぜなら、「もっと練習」のような抽象的助言では明日何をすればいいか分からないから。

## 5. 機能要件

### FR-01: 入力受付（ユーザー録音）
- スキル起動時、以下のいずれかを入力として受け付けること
  - (a) ローカル音声ファイルの絶対パス（拡張子 wav / mp3 / m4a）
  - (b) 歌唱の状況・感想を記したテキスト
- (a)の場合、ファイル存在チェックを行い、存在しなければユーザーに通知して中断すること
- 拡張子が対象外の場合は警告を出し、ユーザー確認のうえ続行可否を決めること

### FR-01b: 原曲参照の必須取得（カバー曲時）
- カバー曲のFBを行う場合、**原曲参照を必ずユーザーに提出させてからFBに進む** こと
- 受理する原曲参照の形式（いずれか1つ以上、優先順位順）:
  1. 原曲音源のローカルパス
  2. 原曲の YouTube / 配信サービス URL
  3. 原曲のアーティスト名 + 曲名（両方必須）
- 「曲名だけ」「アーティスト名だけ」「うろ覚え」の場合は受理せず、再提出を求めること
- 原曲が確定しない場合、FB の比較セクション（FR-04b）は作成せず、その旨をユーザーに明示すること

### FR-Analyze: 音声直接解析（パスが両方そろった時の必須処理）
- ユーザー録音と原曲音源の wav（必要に応じ ffmpeg/yt-dlp で取得）が手元にそろったら、`tools/audio_analyzer.py` を Bash 経由で起動して解析 JSON を取得すること
- 取得する指標:
  - 発声: `f0_median_hz`, `f0_jitter_cents`, `voiced_ratio`, `spectral_centroid_hz`, `vibrato_rate_hz`, `vibrato_depth_cents`, `long_tone_stability`
  - リズム: `tempo_bpm`, `onset_rate_per_sec`
  - 音感: `estimated_key`
  - 表現: `rms_mean`, `rms_db_range`, `rms_crest_db`
  - 比較: `compare` セクション（差分一式）
- **同一音源検出**: 主要指標が小数点まで一致し RMS包絡相関が >0.95 の場合は、ユーザー録音と原曲が同一音源と判定し、ユーザーに本人歌唱の再提出を求めること（FBは中断）
- 解析失敗・テキスト入力のみで wav が無い場合は、自己申告ベースのFBに切り替えてその旨を明示すること

### FR-02: ヒアリング
- 解析データを補強する材料として取得する。以下を順に尋ねること（既に提供されていればスキップ）
  1. 曲名・原曲アーティスト（FR-01b と兼ねて確認）
  2. キー・テンポ（分かる範囲）
  3. 自己評価：うまく行った点・難しかった点
  4. 苦手意識のあるフレーズや音域
  5. 原曲のどこを真似ようとしたか／自分なりに変えた点（任意）
- ユーザーが「分からない」「省略」と答えた項目は欠損扱いで先へ進めること
- 全項目を尋ねきる前にFBを始めない（最低でも原曲参照〔カバー時〕と自己評価が埋まってから）

### FR-03: スコア算出
- 以下の4軸を 0-100 のスコアで提示すること
  - **pitch_score**: 音程の安定性
  - **rhythm_score**: リズムの正確さ
  - **expression_score**: 表現（抑揚・ダイナミクス・伝達）
  - **total_score**: 総合（上記の重み付き）
- スコアの根拠（ユーザーの自己申告 or 推定）を必ず添えること
- 推定根拠が薄い場合は「推定値」と明示すること

### FR-04: フィードバック生成
- 以下の順序・要素を含むFBを生成すること
  1. 参照原曲の確認（カバー時、FR-01bで提出されたもの）
  2. **解析データ（FR-Analyzeで取得した実測値の表）**
  3. スコア（FR-03、解析データを主材料に算出）
  4. 良かった点 2-3個（具体的に）
  5. 改善ポイント 2-3個（優先順位順、具体的に）
  6. **原曲との比較（FR-04b）**
  7. **原曲歌手っぽく歌うためのアプローチ（FR-04c）**
  8. 次の練習メニュー（声トレ軸 / 歌唱トレ軸の2軸、今日できる / 今週中の2粒度）
  9. 一言（励まし）
- 「音程が不安定」のような曖昧表現を使わず、「サビ頭の高音Aで半音下がる傾向」のように具体化すること
- 改善より肯定が先（良かった点を必ず2つ以上）

### FR-04b: 原曲との4軸比較（カバー時必須）
- FR-01b で原曲が確定している場合、以下の4軸でユーザー録音と原曲を比較すること
  - **発声**: 声種（地声/裏声/ミックス）、声質、ビブラート、息漏れ
  - **リズム**: グルーヴ位置（前ノリ/ジャスト/後ノリ）、タメ、フレーズ終わりの処理、子音の置き方
  - **音感**: スケール選択、フェイク・しゃくり・こぶし、ハモリパート
  - **表現**: ダイナミクス設計、歌詞解釈、感情の乗せ所
- 各軸で「原曲の特徴」「ユーザーの推定再現度」「差分の正体」を表で提示すること
- 原曲が確定しない場合、本セクションは作成せずスキップを明示する

### FR-04c: 「原曲歌手っぽく歌う」アプローチ
- FR-04b の比較結果から、4軸それぞれで最大の差分を1つ特定すること（全部直そうとしない）
- 各差分について、以下のいずれかでアプローチを提示すること
  - 声を寄せるための解剖学的アプローチ（呼吸支持・喉の開き・舌位置など）
  - 歌い方を寄せるための聴き取り課題（特定区間の反復聴き取り＋部分模倣）
- **原曲歌手の「らしさ」の核** を以下4分類で推定し、明示すること
  - 声質そのもの／発声テクニック／リズム感覚／歌詞解釈・感情
- 核が「声質そのもの」の場合は完全コピーを目指さず、ユーザーの声で別角度の魅力を出す方針を提案する
- 核が「テクニック・リズム・解釈」の場合は、寄せる方向への具体練習を提示する

### FR-05: 過去FBとの比較（同セッション内）
- 同じ会話セッション内で2回目以降の音源が渡された場合、前回FBとの差分を述べること
- 比較観点：4軸スコアの変化、改善ポイントとして指摘した項目の改善状況

### FR-06: 限界の明示
- 解析パイプラインを通した場合は、その旨と推定モデルの限界を FB 末尾に1行で明示すること
- 例（解析あり）: `※ 解析は librosa の f0/chroma/onset 推定に基づく。アカペラやハモリ・楽器混在で誤推定が起こりうる。`
- 例（解析なし）: `※ 本FBは音声を直接解析せず、お申告いただいた内容を元にしています。`

## 6. 非機能要件

### NFR-01: 応答時間
- 入力受け付けから初回応答（ヒアリング開始）まで 3秒以内
- ヒアリング完了から最終FB提示まで 30秒以内（Claude API応答時間に依存）

### NFR-02: 利用容易性
- スキル呼び出しは音声ファイルパスを渡すだけ、または「歌のFBちょうだい」のような自然言語で起動できること
- 解析パイプラインの初回セットアップとして `backend/.venv` に `librosa, numpy, scipy, soundfile, yt-dlp, imageio-ffmpeg` を導入済みであること（初期構築の `requirements.txt` で再現可）
- 解析ライブラリ未導入の環境では、自動的に自己申告ベースFBにフォールバックすること

### NFR-03: プライバシー
- 音声ファイルは Claude Code のローカル環境にとどまる
- FB結果も会話セッション内のみ。永続化は行わない

### NFR-04: 品質一貫性
- Web版（`backend/app/services/evaluation_service.py`）と同じ4軸・同じスコア基準を用いること
- FB文のトーン（温かいが妥協なし）は両チャネルで統一

## 7. 受け入れ基準
- **AC-01**: ユーザーが音声ファイル絶対パスを渡し、最低限のヒアリングに答えると、4軸スコア＋FB＋練習メニューを含む完全なFBが返ること
- **AC-02**: 拡張子が対象外（例: .aiff）のファイルを渡すと、警告が出てユーザー確認を求めること
- **AC-03**: 存在しないパスを渡すと、即座にエラーメッセージが出ること
- **AC-04**: FB末尾に「音声を直接解析していない」旨の注記が必ず含まれること
- **AC-05**: 同セッション内で2件目の音源を渡すと、前回との差分コメントが含まれること
- **AC-06**: 良かった点が2個以上、改善ポイントが2個以上含まれていること
- **AC-07**: 改善ポイントは「サビの高音」「ブレスの位置」など具体的な箇所・現象を指していること（抽象表現NG）
- **AC-08**: カバー曲のFB依頼時、原曲参照（音源 / URL / アーティスト+曲名）が未提出ならFB本体に進まず再提出を求めること
- **AC-09**: 原曲参照が確定したカバー曲では、原曲との4軸比較（発声・リズム・音感・表現）が表形式で含まれること
- **AC-10**: 「原曲歌手っぽく歌うアプローチ」セクションで、4軸それぞれの差分と寄せ方が具体的に示され、「らしさの核」が4分類（声質／テクニック／リズム／解釈）のどれかで明示されていること
- **AC-11**: ユーザー録音と原曲のwavが揃った場合、`tools/audio_analyzer.py` を実行して取得した実測値（f0/key/tempo/jitter/ビブラート/動的レンジ等）がFB本体に表形式で含まれること
- **AC-12**: ユーザー録音と原曲の主要解析指標が一致し RMS包絡相関 >0.95 の場合、同一音源と判定して再提出を求めること（FB中断）
- **AC-13**: 解析が失敗または不可（テキスト入力のみ）の場合、自己申告ベースに自動フォールバックし、FB末尾の限界注記がその旨に変わること

## 8. 前提・制約
- 動作環境: Claude Code（CLI / Desktop / Web 問わず）
- スキル定義: `.claude/skills/vocal-trainer/SKILL.md`
- 音声直接解析は本MVPでは行わない。将来 Web版バックエンドを Claude Code から呼び出す形での解析連携は別途検討（未決事項参照）
- FB品質基準は `docs/01_要件定義.md` の FR-03（自動評価）と整合させる
