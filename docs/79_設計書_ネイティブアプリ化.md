## 1. システム構成
```
[Android/iOS アプリ (Capacitor シェル)]
   └─ ローカル起動シェル www/index.html（接続確認・リトライ画面 = FR-03）
        └─ 接続OKなら https://<DOMAIN>/coach?source=app へ遷移
             └─ 以降は既存 Web版そのまま（録音・FB・ログイン・履歴）
[GitHub Actions] native/ 変更を検知 → APK(debug) / AAB+APK(release署名) を Artifacts 出力
```
- backend / DB / docker 本番構成への変更は**なし**。
- frontend への変更は FR-05（課金導線非表示）の条件分岐のみ。

## 2. アーキテクチャ判断
| 論点 | 決定 | 理由 / 代替案 |
| --- | --- | --- |
| リモート読み込み方式 | `server.url` は使わず、**同梱の起動シェル `www/index.html` から本番URLへ遷移** | `server.errorPath` のリモートURL時挙動は環境差があり実機なしで保証できない。ローカルシェルなら起動失敗UI（FR-03）を決定論的に実装できる。トレードオフ: 起動時に一瞬シェルが見える（背景色を本番と同じ `#0b1020` にして目立たなくする） |
| アプリ判定（FR-05） | `appendUserAgent: "VocalCoachApp"` を主、起動クエリ `?source=app` + localStorage を従 | UA はどの画面・どのタイミングでも判定でき、ログアウトや直リンクでも壊れない。クエリは計測用に残す |
| ドメイン差し替え | `capacitor.config.ts` と `www/index.html` 生成スクリプトが env `CAP_SERVER_URL`（既定 `https://sora-vocal-ai.duckdns.org`）を読む | ステージング検証・将来の独自ドメイン移行をコード変更なしで可能に |
| Android/iOS プロジェクト | `native/android/` `native/ios/` を**リポジトリにコミット**（Capacitor 標準） | 権限宣言・署名設定・versionCode がコードレビュー対象になる |
| 署名 | CI で GitHub Secrets から keystore を復元し、`keystore.properties` 経由で Gradle に注入。Secrets 未設定なら release は unsigned スキップ、debug APK は常に出す | 鍵をリポジトリに置かない（AC-08）。オーナーが Secrets を入れた瞬間から署名ビルドが出る |

## 5. モジュール構成
```
native/
  package.json           # @capacitor/core, cli, android, ios。scripts: gen, sync, など
  capacitor.config.ts    # appId=com.vocalcoach.sora, appName=ソラ先生,
                         # webDir=www, appendUserAgent=VocalCoachApp,
                         # allowNavigation=[<DOMAIN>], backgroundColor=#0b1020
  scripts/gen-www.mjs    # www/index.html を APP_URL 埋め込みで生成（テンプレは templates/）
  templates/index.html.tmpl  # 起動シェル: 接続確認 → 自動遷移 / 失敗時「再試行」UI（日本語）
  www/                   # 生成物（コミットする。CIでも再生成）
  assets/                # アイコン・スプラッシュ元画像（frontend/public/icons から複製）
  android/               # cap add android の生成物 + 権限/署名設定
  ios/                   # cap add ios の生成物 + Info.plist 権限文言
frontend/src/lib/appMode.ts        # isNativeApp() 判定ヘルパ（新規）
frontend/src/components/UpgradeModal.tsx   # FR-05: アプリ時は購入CTAを出さない
frontend/src/components/PremiumWidget.tsx  # FR-05: アプリ時は残回数バッジのみ
frontend/src/app/settings/page.tsx         # FR-05: アプリ時は「プレミアムをはじめる」節を非表示
.github/workflows/native-android.yml       # FR-06: APK/AAB ビルド
```

### 5.1 起動シェル（FR-03）の責務
1. 表示: 本番と同じ背景色・ソラ先生ブランドの最小ロード画面（外部フォント等は読まない・完全自己完結）
2. `fetch(APP_URL, {method:"HEAD", mode:"no-cors"})` で到達確認（タイムアウト 6s）
3. 成功 → `window.location.replace(APP_URL + "/coach?source=app")`
4. 失敗 → 「インターネットに接続できません」＋[再試行]ボタン（押下で 2 に戻る）
- Capacitor の `allowNavigation` に APP_URL のホストを入れ、遷移後も WebView 内に留める。それ以外のホストへのリンクはシステムブラウザで開く（Capacitor 既定挙動 = FR-01 例外/AC-05）

### 5.2 アプリ判定ヘルパ（FR-05）
```ts
// frontend/src/lib/appMode.ts
export function isNativeApp(): boolean {
  if (typeof window === "undefined") return false;
  try {
    if (navigator.userAgent.includes("VocalCoachApp")) return true;
    const q = new URLSearchParams(window.location.search);
    if (q.get("source") === "app") { localStorage.setItem("vc_app_mode", "1"); return true; }
    return localStorage.getItem("vc_app_mode") === "1";
  } catch { return false; }
}
```
- **UpgradeModal**: `isNativeApp()` のとき、価格・購入ボタン（`startCheckout`）を出さず、機能比較表＋「プレミアムの登録は Web サイトで承っています」の説明文のみ表示（リンクは置かない = Play 規約の外部誘導回避）。`logPaywallEvent("paywall_view")` は従来どおり送る（計測継続）。
- **PremiumWidget**: アプリ時は残回数バッジのみ表示し、アップグレードボタンとモーダル起動を無効化。プレミアムの「✓ プレミアム」バッジは従来どおり。
- **settings**: アプリ時は `startCheckout` を含む無料ユーザー向け勧誘ブロックを非表示。プレミアムユーザーの `openPortal`（解約・支払い管理）は残す — ポータルは Stripe ドメインのため自動的にシステムブラウザで開く（規約上も解約導線の提供は問題ない）。

### 5.3 Android 設定（FR-02, FR-07）
- `AndroidManifest.xml`: `RECORD_AUDIO`, `MODIFY_AUDIO_SETTINGS`, `INTERNET`。WebView の getUserMedia → ネイティブ権限ブリッジは Capacitor Bridge 標準（追加コード不要）。
- `android/app/build.gradle`: `versionCode 1` / `versionName "1.0.0"`。`keystore.properties` が存在する場合のみ release signingConfig を有効化。
- アイコン: `icon-512.png` / `maskable-512.png` から mipmap 各解像度を生成して配置。スプラッシュは背景 `#0b1020` 単色＋中央アイコン。

### 5.4 iOS 設定（FR-02, AC-07）
- `Info.plist`: `NSMicrophoneUsageDescription` = 「歌声を録音してAIが添削するために使用します」。
- ビルド・提出は Apple Developer 契約後（docs/81 ランブック参照）。CI での ipa ビルドはスコープ外。

## 6. CI 設計（FR-06: .github/workflows/native-android.yml）
```yaml
trigger: push(main, native/** or workflow変更) + workflow_dispatch
jobs.build:
  - setup-java 21 (temurin) / setup-node 20
  - cd native && npm ci && npm run gen && npx cap sync android
  - ./gradlew assembleDebug → upload artifact: app-debug.apk（常に）
  - if secrets.ANDROID_KEYSTORE_BASE64 != '':
      base64 -d → android/app/release.keystore
      keystore.properties 生成（storeFile/storePassword/keyAlias/keyPassword）
      ./gradlew bundleRelease assembleRelease → upload: app-release.aab / .apk
```
- 必要 Secrets: `ANDROID_KEYSTORE_BASE64` / `ANDROID_KEYSTORE_PASSWORD` / `ANDROID_KEY_ALIAS` / `ANDROID_KEY_PASSWORD`（設定手順は docs/81）。
- fork PR では secrets が渡らないため、署名ステップは `if: github.event_name != 'pull_request'` でも保護する。

## 7. エラーハンドリング方針
- 起動時オフライン: 起動シェルの再試行UI（5.1）。
- セッション中のオフライン: 既存 PWA の Service Worker（offline.html）が Android WebView で機能。
- マイク権限拒否: 既存 Web の getUserMedia エラー表示に委譲（FR-02 例外）。

## 8. 性能・可用性考慮
- 起動シェルは外部リソースゼロ（インラインCSSのみ）→ 描画即時。到達確認は HEAD 相当で軽量。
- 本番停止＝アプリ全滅はリモート方式の宿命。ランブックに「アプリ障害の一次切り分けは Web 本番の死活確認」と明記。

## 9. セキュリティ考慮
- `android:usesCleartextTraffic` は付与しない（https のみ）。
- 署名鍵・パスワードは GitHub Secrets / オーナーのパスワードマネージャのみ（AC-08）。keystore.properties / *.keystore は .gitignore。
- WebView は `allowNavigation` のホスト以外を内部表示しない（フィッシング面の限定）。

## 10. テスト方針（QAと連携）
- CI 成果物の debug APK による実機/エミュレータ手動テスト（AC-01〜05）。
- frontend の FR-05 分岐は `npm run build` の型チェック＋ブラウザで `?source=app` を付けた手動確認が可能（アプリ実機なしで検証できる設計にしている）。
- 詳細は docs/80_テスト計画_ネイティブアプリ化.md（qa-engineer）。

## 11. 移行 / 後方互換性
- 既存 Web/PWA ユーザーへの影響: `isNativeApp()` が false の経路では表示・挙動とも変更なし。
- `?source=app` は既存の `?source=pwa` と同じ計測パラメータ体系。
- 将来の独自ドメイン移行時は `CAP_SERVER_URL` を変えて再ビルド＋ストア更新（docs/81 Later 節）。
