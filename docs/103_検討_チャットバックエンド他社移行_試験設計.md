## 0. 前提として開示すべきバイアス（初版の訂正）

**本書の初版は「Claudeが第一候補」と書いたが、GPTを一度も検証せずに順位を付けたものであり、
根拠として不十分だった。** 改訂の理由を明示しておく。

1. **これまでの h2h（対戦）評価に GPT は一度も登場していない。** 対戦相手の「ChatGPT級」は、
   同じ事実・同じ制約を与えた **Claude が生成した返答の代役**である（docs/96 §4.1〜4.3、
   `REPORT_chatgpt_h2h.md` の「Claude版コーチ(ChatGPT級の代理)」）。
   したがって既存の全スコアは **「Claude vs Gemini」の結果**であり、GPT との比較データは存在しない。
2. **審査員も Claude である。** 対戦相手も審査員も同一ベンダーのモデルという構図で、
   同族びいきを構造的に排除できない（docs/96 §4.3 に記載済み）。
3. **したがって本書は「Claude を入れるか」ではなく「Claude と GPT のどちらを入れるか（あるいは
   どちらも入れないか）」を決めるための試験設計とする。** 最終判定は §4 のとおり運用者が行う。

ベンダー選定に依存しない確定事実は1つだけ:
**現行の Gemini flash ティアが会話の弱点である**（萎え率・逃げ率・字数・冗長所見はいずれも
対戦相手に依存しない単独指標で、docs/96 §4.1〜4.3 に実測が残っている）。

## 0.5 決定 — 一旦 GPT で進める（2026-08-14 運用者）

2社同時比較（§3 の当初案）ではなく、**OpenAI 側だけを先に実装して試す**。

### 決め手: 音声入力の可否が将来の構成を固定する
| | チャット | 音声（解析・録音FB） | 将来の構成 |
| --- | --- | --- | --- |
| Claude 採用 | 可 | **不可**（入力形式にテキスト・画像・PDFのみ。音声が無い） | **ハイブリッド永久固定** |
| **GPT 採用** | 可 | 別モデル族（`gpt-audio`）で可能性あり・未測定 | **将来 1社統合の道が残る** |

会話品質は未測定でどちらが上か分からない（§0）。**分からない以上、
選択肢を狭めない方を先に試す**のが合理的、というのが決定の骨子。

### この決定が含意すること
- **Claude は却下ではなく保留。** GPT が §3 のゲートを落ちたら次に試す候補として残す。
  その際は音声非対応＝ハイブリッド固定を受け入れた上での採用になる。
- **今回替えるのはチャット経路だけ。** 音声・分析経路（`llm_audio_model` /
  `llm_analysis_model`）は Gemini 据え置き。理由は docs/92 §5.9〜5.10 のとおり
  **判定の主役がすでに DSP に移っており、モデルを替えても品質が上がる余地がない**
  （替えれば正解付き録音の検証をやり直す必要があるだけ）。一度に1変数だけ動かす。
- **解析の他社移行は将来の別議題。** GPT がチャットで採用になった場合に限り、
  `gpt-audio` で解析も置換できるか正解付き録音で別途検証する。ただし本製品が音声に
  求めるのは**書き起こしではなく音色の判断**（地声/裏声）であり、`gpt-transcribe` は
  用途が違う点に注意（本製品は「歌詞は聞き取れません」を明示するポリシー）。

## 2. 候補モデル（Claude / GPT を価格ティアで対にする）

比較を公平にするため、**同じ価格帯どうしで対戦させる**。料金は100万トークンあたり。

| ティア | Anthropic | 料金(入/出) | OpenAI | 料金(入/出) |
| --- | --- | --- | --- | --- |
| 上位 | claude-opus-5 | $5 / $25 | gpt-5.6-sol | $5 / $30 |
| **中位（本命）** | **claude-sonnet-5** | $3 / $15（2026-08-31まで$2/$10） | **gpt-5.6-terra** | $2 / $12 |
| 軽量 | claude-haiku-4-5 | $1 / $5 | gpt-5.6-luna | $0.20 / $1.20 |

- OpenAI は公式ドキュメントで **GPT-5.6 を本番API利用の推奨**としている。
  ただし **上表のOpenAI料金は第三者集計サイト由来**であり、契約前に公式価格ページで要確認。
- Anthropic 料金は公式（`claude-api` skill 同梱の一次情報）。
- **両者ともプロンプトキャッシュ対応**（キャッシュ読みは概ね定価の10%）。
  台本2,371字≈1.5千トークンはキャッシュ最小サイズを超えるため、実効コストは表より大きく下がる。

### コスト感（実務スケール）
1ターン=入力4千トークン＋出力150トークン想定で、中位ティアはどちらも **1ターンあたり1〜3円**。
月1,000ターンでも数千円で、現行のSNS予算（月5,000円）と同規模。**コストは選定基準にしない**
（運用者決定）が、青天井でないことの確認として記録する。

### 技術的な移植性（両者とも問題なし）
- **function calling**: 現行の全ツール（動画検索・原曲検索・聴取系の文脈ツール）は
  両者の tool use に1:1で移植できる。呼び出し規約が違うだけで、設計変更は不要。
- **音声入力は不要**: 聴取系ツール（声区・発音）は内部で `llm_audio_model`（Gemini 2.5-flash）が
  音声を処理してテキストを返す構造のため、**チャット用モデルに音声入力能力は要らない**。
  → 音声解析は Gemini のまま、チャットだけ他社、というハイブリッドが成立する。
- **バージョン固定**: 両者とも日付サフィックス無しの固定IDを提供。
  Gemini の「エイリアスが黙って実体を変える」事故（docs/92）と同型のリスクは小さい。

## 3. 試験設計（3段階・いつでも撤退可能）

| 段階 | 内容 | 必要なもの | ゲート |
| --- | --- | --- | --- |
| Stage 1（無効） | ~~h2h対戦相手としてのClaude品質確認~~ | — | **§0 のとおりGPT未検証のため、勝敗の根拠としては採用しない** |
| **Stage 2a（実装）** | llm.py の**チャット経路のみ**にプロバイダ抽象を追加し、OpenAI アダプタを実装 | 不要（キー無しでも実装・テストは可能） | 既存テスト全パス＋キー未設定時に従来動作が不変 |
| **Stage 2b（測定）** | **同一72会話コーパス**を gpt-5.6-terra で実行し、現行 gemini-3.5-flash の実測値と比較 | **OpenAI APIキー** | docs/96 §4 ゲート（萎え15%以下・中央値3秒以内・捏造0件） |
| **Stage 2c（最終ゲート）** | **運用者ブラインド判定**（下記） | 運用者30分 | 過半数で GPT 採用可否を決定 |
| Stage 3 | 本番切替（env切替 → カナリア → 全量） | 2c 通過 | 実ユーザー指標で最終確認 |

- Stage 2 は**本番に一切触れない**（評価ハーネスのみ）。不合格なら Gemini 3.5-flash 続投で撤退可能。
- **比較対象は「現行の Gemini 3.5-flash」**。docs/96 §4.2 に実測ベースライン
  （萎え8.3%・雑談90字・中央値1.34秒・捏造0件）が残っているため、
  新たに対戦相手を用意する必要がなく、§0 のベンダーバイアスも入らない。
- 費用: 1モデル×72会話×2ラン想定で数百円規模。

### Stage 2c: 運用者ブラインド判定（自動審査の代替）
自動審査（Claude審査員）は §0 のバイアスがあるため、**最終判定は運用者が行う。**

1. 代表10会話を選ぶ（雑談・感情の吐露・多ターン・録音FBのフォロー・偽前提への反応から各2）
2. 各会話について、**現行Gemini版とGPT版の返答を A/B 伏せてランダム順に並べた比較ページ**を生成する
3. 運用者は各会話で「**こっちのソラ先生と話したい**」を選ぶ（理由は任意）
4. 過半数を取った側を採用。割れた場合は「差が無い」＝現行 Gemini 続投（乗り換えコストを払う理由が無い）

この判定には自動審査のような同族びいきが原理的に存在せず、
**「会話が噛み合わない」と最初に気づいた本人が物差しになる**点で最も信頼できる。

## 4. 実施内容

Stage 2a（実装）は**キー無しで先行できる**ため完了済み。Stage 2b 以降がキー待ち。

### 実装方針（Stage 2a）
- **チャット経路のみ**プロバイダを差し替え可能にする。音声・分析経路は Gemini 固定のまま。
- プロバイダは**モデルIDから決定論で判別**（`gpt-` / `o` 始まり → OpenAI、他 → Gemini）。
  設定を二重に持たないため、provider と model の食い違いが原理的に起きない。
  docs/94 憲法 1.1「誤読しようがない形式の決定論パース」の範囲。
- **キー未設定なら従来どおり Gemini。** 既定値は変えないので、実装を入れただけでは本番挙動は不変。
- ツール定義（動画検索・原曲検索・聴取系）は両社で同一の JSON Schema を共有し、
  呼び出し規約の差だけをアダプタが吸収する。**ツールの中身と事後ガード
  （URL到達保証・原曲確認アンカー・秒数スクラブ）は共通コードのまま**＝FB品質の分岐を作らない。

### CEOへの依頼（Stage 2b の唯一のブロッカー）
OpenAI の APIキー発行。アカウント作成・支払い設定を伴うため代行不可。

| 発行先 | 手順 | 配置先 |
| --- | --- | --- |
| OpenAI | platform.openai.com → アカウント作成 → 課金設定 → キー発行 | 検証時は `backend/.env` に `OPENAI_API_KEY=` |

※ Stage 2b は検証のみのため、まずは手元の検証環境にだけ置けばよい（本番VPSへの配置は Stage 3 で）。
※ Anthropic のキーは今回不要（§0.5 の決定により Claude は保留）。
