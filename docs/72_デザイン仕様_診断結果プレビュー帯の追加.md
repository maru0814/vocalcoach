# 診断結果のプレビュー帯 デザイン仕様（docs/69・70 追補）

対応する既存仕様: [docs/69_機能要件書_診断結果から声タイプ詳細記事への導線.md](69_機能要件書_診断結果から声タイプ詳細記事への導線.md)（FR-05）、[docs/70_デザイン仕様_診断結果から声タイプ詳細記事への導線.md](70_デザイン仕様_診断結果から声タイプ詳細記事への導線.md)

## 1. 課題
docs/70 FR-05 で実装済みの「↓ {タイプ名}のプロフィールを読む」アンカー（`text-xs` の下線テキストリンク）は、意図どおり「レッスンを受ける」ボタンより弱いトーンにした結果、**下に詳細記事が続くこと自体に気づかれず素通りされる**。ファーストビュー（結果カード＋シェアボタン）だけを見て、ボタン列に進んでしまう。

## 2. 方針
リンクを強く（ボタン化）はしない＝docs/70の「レッスン導線の優先度を侵さない」制約は維持する。代わりに、**リンクではなく中身の一部を白カード内で先に見せる**プレビュー帯を追加し、「この下に読み応えのある記事がある」ことを情報として伝える。

## 3. 変更箇所
`frontend/src/app/voice-type/page.tsx` の結果セクション（ログイン済み、[292-314行](../frontend/src/app/voice-type/page.tsx)）。

```
<div class="rounded-2xl bg-white/90 p-4 shadow-card">
  <div ref={shareRef}><VoiceTypeBlock /></div>
  <div class="mt-3"><ShareButtons /></div>
  ── ここに追加: セクションプレビュー帯 ──
</div>
↓ アンカー文言を変更（下記）
```

### 3-1. セクションプレビュー帯（新規）
- 配置: 白カード内、`ShareButtons` の直下（`shareRef` の**外**＝シェア画像に写り込まない。docs/70 AC-07を踏襲）。
- データソース: `profile.sections`（`nav`・`icon`）。`VoiceTypeProfileArticle` の目次チップと同じデータを再利用し、二重管理しない。新規コンポーネント作成は不要（`page.tsx` 内にインライン、または`VoiceTypeProfileArticle`から目次部分だけ切り出して共有してもよい＝実装者判断）。
- 見出し: 「この診断でわかること」（`text-[11px] font-bold text-brand-700`）
- チップ: 各 `profile.sections[i].nav` をアイコン付きチップで並べる（`bg-white border border-brand-200 rounded-full text-[11px] font-bold text-brand-700`）。タップで `#${section.id}` へアンカー遷移（記事側は既存のまま、id重複なし）。
- 背景: `bg-brand-50/70 rounded-2xl p-2.5`（帯全体を軽く囲み、カード内の他要素と区別する）
- 表示条件: `profile` が読み込めている場合のみ（docs/69 FR-01の例外ケースと同じ＝準備中タイプは非表示）。

### 3-2. アンカー文言の変更
- Before: `↓ {nameJa}のプロフィールを読む`
- After: `↓ 苦手なこと・話し方・似てる有名人まで、ぜんぶわかります`
- トーン: 変更なし（`text-xs font-bold text-brand-600` 下線、ボタン化しない）。プレビュー帯の直下に配置。
- 理由: 「読み物がある」という抽象的な事実より、「何が書いてあるか」を具体的に列挙する方がスクロール動機になる（設計原則「文言は具体的に」）。

## 4. 状態
- `profile` あり: プレビュー帯＋新アンカー文言を表示。
- `profile` なし（準備中タイプ）: プレビュー帯・アンカーとも非表示（現状のFR-05表示条件を維持）。
- 未ログイン（ぼかしカード）: 変更なし（docs/69 FR-02のとおり対象外）。

## 5. アクセシビリティ
- チップは `<a href="#{id}">` のネイティブリンクとして実装し、キーボード操作・フォーカスリングは既存ボタン群と同じ表現（`focus-visible:ring-2 focus-visible:ring-brand-400`）に揃える。
- チップ内アイコンは装飾のため `aria-hidden="true"`。チップのテキスト（`nav`）自体でリンク先が推測できる。

## 6. 影響しないもの
- `ShareButtons`・`VoiceTypeBlock`・締めCTA（FR-06）・記事本体（`VoiceTypeProfileArticle`）は変更なし。
- `shareRef` の範囲は変更しない（プレビュー帯はその外）。

## 実装メモ（frontend-engineer向け）
- 変更ファイル: `frontend/src/app/voice-type/page.tsx`（1箇所）。
- `profile.sections` の型は `frontend/src/content/voiceProfiles/types.ts` の `VoiceProfile["sections"]` を参照。
- アイコン描画は既存の `IconChip` / `Icon`（`@/components/site/IconChip`）を流用可能か確認し、無ければ`s.icon` 文字列に対応する既存アイコンコンポーネントをそのまま使う。
