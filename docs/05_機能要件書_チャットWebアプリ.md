# チャット形式ボイトレWebアプリ 機能要件書

> PdM作成。`docs/03_機能要件書_ClaudeCode版FB.md` のコーチングループを **チャット形式のWebアプリ** として提供する。
> 既存Web版MVP（`docs/01`, `02`）の `frontend/` `backend/` を拡張する。

## 1. 概要
- ブラウザ上のチャットUIで、ユーザーが歌の録音を送ると、AIボイストレーナーが多段コーチング（課題発見 → 基礎練処方 → 練習確認 → 曲再録音判定）を会話形式で進めるWebアプリ。
- コーチングの頭脳は **ルールベースエンジン**（Claude API非依存・無料・高速）。`tools/audio_analyzer.py` 相当の音声解析をバックエンドで実行し、解析値を閾値ルールに通してFB文・スコア・基礎練・参考動画を生成する。
- 解決する課題: Claude Code版は開発者向け。一般ユーザーが「録音 → コーチング」を **ブラウザだけで** 完結できるようにする。

## 2. 想定ユーザー / ユースケース
### 2.1 ペルソナ
- 独学で歌を練習している初〜中級者（PC/スマホのブラウザを使う）
- アカウント登録して練習履歴を残したい人

### 2.2 主要ユースケース
- **UC-01**: 練習したい曲のURLと区間を指定し、ブラウザでその場録音 → 課題と基礎練がチャットで返る
- **UC-02**: 手持ちの音声ファイルをアップロードしてFBを受ける
- **UC-03**: 基礎練を録音して送り、達成できたか判定してもらう
- **UC-04**: 曲を再録音して、初回からの改善を数値とコメントで確認する

## 3. スコープ
### 3.1 対象（MVPでやること）
- チャットUI（メッセージ送受信、コーチ発話、ユーザー発話）
- **ブラウザ録音**（MediaRecorder API）と**ファイルアップロード**の両方
- 音声解析（f0・テンポ・キー・ビブラート・ロングトーン安定度・声種推定・時系列指標）
- ルールベースのコーチングループ（Phase A〜E）
- 課題タクソノミーに基づく基礎練処方 + 参考動画リンク提示
- 4軸スコア（音程・リズム・表現・総合）
- 認証（既存の auth を流用）とセッション履歴保存

### 3.2 対象外（やらない）
- Claude API などLLMによる自由文生成（FB文はルール+テンプレート）
- リアルタイム（歌っている最中の）採点
- 課金・複数トレーナーキャラ選択
- ネイティブアプリ（PWA含む）

## 4. ユーザーストーリー
- **US-01**: ユーザーとして、曲URLと区間を入力してブラウザでそのまま録音したい。ファイル変換の手間をなくしたいから。
- **US-02**: ユーザーとして、コーチの発話・自分の録音が時系列のチャットで残ってほしい。やり取りを見返したいから。
- **US-03**: ユーザーとして、課題に対する基礎練と参考動画をチャット内で受け取りたい。別のサイトを探す手間をなくしたいから。
- **US-04**: ユーザーとして、基礎練・再録音のたびに「達成したか」「改善したか」を判定してほしい。独学で判断できないから。
- **US-05**: ユーザーとして、改善したら褒めてほしい。モチベーションを保ちたいから。

## 5. 機能要件

### FR-01: チャットセッション
- ユーザーは新規コーチングセッションを開始できること
- セッションは Phase（A〜E）と現在の課題を内部状態として保持すること
- チャット履歴（コーチ発話・ユーザー発話・解析結果）はDBに保存され、再訪時に復元できること

### FR-02: メッセージ送受信
- ユーザーはテキストメッセージを送れること（Phase A の情報入力、質問への回答など）
- コーチ（システム）はルールエンジンが生成したメッセージを返すこと
- メッセージ種別: `text`（テキスト）/ `audio`（音声）/ `feedback`（解析つきFBカード）

### FR-03: 音声入力（録音 + アップロード）
- **録音**: ブラウザの MediaRecorder で録音し、停止後にサーバーへ送信できること
- **アップロード**: wav / mp3 / m4a / webm ファイルを選択して送信できること
- 録音/アップロードした音声はチャット内で再生できること
- サイズ上限は20MBとすること（既存の10MB制限を緩和）

### FR-04: 原曲取得
- Phase A で渡された原曲URL（YouTube等）から、サーバー側で音声を取得すること（yt-dlp）
- アーティスト名+曲名だけの場合は、URL特定をユーザーに促すこと（MVPでは自動検索しない）
- 取得した原曲はキャッシュし、同一セッションで再ダウンロードしないこと

### FR-05: 音声解析
- ユーザー録音と原曲を、指定区間で解析すること（`backend/app/audio/analyzer.py`）
- 取得指標は `docs/03` の FR-Analyze と同じ（f0/jitter/voiced_ratio/centroid/rolloff/vibrato/long_tone_stability/tempo/onset/rms + 時系列 + 声種推定）
- 同一音源検出時は本人歌唱の再提出を促すこと
- 解析失敗時はエラーメッセージを返し、フェーズを進めないこと

### FR-06: ルールベースFB生成
- 解析値を閾値ルールに通して以下を生成すること
  - 4軸スコア（0-100）
  - 良かった点・改善ポイント（テンプレート + 解析値の差し込み）
  - 秒数単位の具体指摘（時系列指標の `sustained_segments` / `per_window` を使用）
  - 裏声/地声/ミックスを区別したコメント
- FB文は「初心者にも分かる平易さ」を満たすこと（専門用語に括弧書きの言い換え）

### FR-07: コーチングループ（Phase A〜E）
- `docs/03` の Phase A〜E と同じ状態遷移をルールエンジンで実装すること
- Phase B で課題を1つ特定し、タクソノミーにマッピングすること
- Phase C で基礎練 + 参考動画リンクを提示すること
- Phase D で基礎練録音を判定（◯/△/✗）すること
- Phase E で初回録音との差分を提示し、改善時は褒めること

### FR-08: 課題タクソノミー + 参考動画
- 課題（喉締め/ビブラート未獲得/ロングトーン崩れ/ミックス未習得/音程細部揺れ/リズム/表現平板/鼻声）ごとに、基礎練メニュー・達成判定・参考動画リンクを保持すること
- 参考動画リンクは事前にキュレーションしたものをタクソノミーに格納すること（MVPでは動的検索しない）
- 基礎練は道具不要のものに限定すること

### FR-09: 認証・履歴
- 既存の auth（JWT Cookie）でログインしたユーザーのみ利用可能とすること
- セッション一覧・各セッションのチャット履歴を閲覧できること
- 他ユーザーのセッションにアクセスできないこと

## 6. 非機能要件
- **NFR-01 性能**: テキスト応答は1秒以内。音声解析は25秒区間で15秒以内。原曲DLは曲長次第（目安30秒以内）
- **NFR-02 対応ブラウザ**: 最新の Chrome / Safari / Edge。MediaRecorder 対応必須
- **NFR-03 プライバシー**: 音声はサーバー保存だが本人のみ参照可。原曲は解析目的の一時取得
- **NFR-04 品質一貫性**: スコア基準・FBトーンは Claude Code版（SKILL.md）と統一
- **NFR-05 セキュリティ**: 既存の認可チェックを踏襲。アップロードのMIME/拡張子検証

## 7. 受け入れ基準
- **AC-01**: ログイン後、新規セッションを開始し、曲URL・区間を入力するとPhase Bに進む
- **AC-02**: ブラウザ録音した音声がチャットに表示・再生でき、解析FBが返る
- **AC-03**: ファイルアップロードでも同じFBが返る
- **AC-04**: FBに4軸スコア、秒数単位の指摘、裏声/地声の区別が含まれる
- **AC-05**: Phase C で基礎練と再生可能な参考動画リンクが返る
- **AC-06**: Phase D で達成判定（◯/△/✗）が返る
- **AC-07**: Phase E で初回との差分が数値で示され、改善時に褒め言葉が出る
- **AC-08**: 同一音源を送ると再提出を促される
- **AC-09**: 解析失敗時にフェーズが進まず、再試行できる
- **AC-10**: 他ユーザーのセッションにアクセスすると403になる

## 8. 前提・制約
- 既存 `frontend/` `backend/` を拡張（新規プロジェクトは作らない）
- 解析は `backend/.venv` に導入済みの librosa / yt-dlp / imageio-ffmpeg を利用
- DBは既存（MySQL/SQLite）。新テーブルは Alembic マイグレーションで追加
- 設計書（docs/06 デザイン仕様, docs/07 設計書）作成後に実装着手

## 9. 未決事項 / 要確認
- **Q1**: 原曲のアーティスト+曲名からのURL自動特定はv1.1（MVPはURL必須）
- **Q2**: 参考動画の動的検索はv1.1（MVPは事前キュレーション固定リンク）
- **Q3**: スマホのMediaRecorder実機差異（Safari iOSのwebm非対応）は実装時に要検証 → mp4/aac fallback
