**症状**: ストロー発声をすすめると、リップロールの動画URLが付く。

→ 個別に貼り替えるのではなく、**別の練習に同じ動画を使い回せない形で構造的に塞ぐ**こと
（例: 練習名と動画タイトルの不一致を検出するテスト。同一URLの重複登録を禁止し、
妥当な共有（ハミング系）は明示的な許可リストで通す）。動画が無い練習は
`found=False` で正直に返し、`search_practice_video` の実検索に委ねるのが既存の設計思想。

## 2. 運用者提案 — ルール未実装を機械的に落とす

今回の事故は「docs/42 にルールを書いたが、プロンプトにも検査にも入れなかった」。
運用者から「数値問題に限らず、**文書にあるのに実装されていない時点で落とせないか**」という
提案があった。**完全な自動判定は不可能だが、今回の失敗クラスは機械的に塞げる。**

### できないこと
docs/42 は散文なので、「『まず気持ちに共感して受け止める』が台本に実装されているか」を
機械が意味的に判定することはできない。文字列一致では言い換えを取りこぼす。

### できること: 来歴（traceability）を必須にする
**docs/97 柱4「全ての指示行に来歴を付ける」がまさにこれで、書かれたが未実装。**
今回と同じ「書いただけ」事故なので、ここも同時に閉じる。

1. docs/42 の規範的な各ルールに **ID を振る**（例: `[FB-042-06-3]` = §6 の3番目）
2. 実装側に紐づけを書く。3つのどれかがあればよい:
   - `SYSTEM_PROMPT` / `SKILL.md` のコメントに ID
   - `backend/tests/` のテスト docstring に ID
   - `scripts/soar_eval/checkers.py` の `RULES[...]` に ID（既に docs 参照を持つ仕組みがある）
3. **テストで「IDの集合 ⊇ docs/42 の全ID」を検証**する。紐づけの無いIDがあれば落ちる
4. 逆方向も見る: 実装にあって docs/42 に無い記述は SSOT 逸脱の候補として警告

これで拾えるのは「書いたが一度も実装しなかった」＝**今回の事故そのもの**。
意味の正しさは担保できないが、**担当者が「どこに実装したか」を一度は宣言する**ことを強制でき、
宣言し忘れをテストが落とす。

### 併せて: 機械で測れるルールは検査に落とす
意味判定が要らないものは soar_eval のチェッカに実装し、**数で追えるようにする**。
既存: N4（冗長）、H1〜H8（捏造系）、**N5（生の数値。2026-08-14 追加）**。
候補: Markdown混入、1ターン1問、動画オファーの重複、練習の乗り換え。

## 3. 再現用メモ

```bash
# 評価コーパス生成（backend/ を cwd に）
python -m scripts.soar_eval.cases_naturalness > /tmp/bank_nat.json
python -m scripts.soar_eval.cases_multiturn   > /tmp/bank_mt.json

# 実行（キーは backend/.env。worktree 側に置くこと。メインの checkout は古い場合がある）
bash scripts/soar_eval/run.sh --batch-file /tmp/bank_nat.json --out /tmp/out.json
LLM_CHAT_MODEL=gpt-5.6-terra bash scripts/soar_eval/run.sh --batch-file /tmp/bank_nat.json --out /tmp/gpt.json
```

- **ブラインド判定ページ**: 2社の transcript を読み、ケースごとに左右をランダム入替して
  HTML を吐き、答えを別ファイルに保存する。運用者は「こっちと話したい」を選ぶだけ。
- **OpenAI は Responses API を使う**（chat.completions では gpt-5.6 系が関数ツールを 400 拒否し、
  ツールが丸ごと無効になる）。tools は平坦形 `{"type":"function", **decl}`。
- キーは検証後に削除する（`backend/.env`）。本番VPSには未配置。
