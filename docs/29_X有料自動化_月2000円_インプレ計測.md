# X 有料自動化（月2,000円以内）＋インプレ計測＋直近バズ型分析

> マーケター×アーキテクト作成。X集客を有料APIで自動化しつつ**月2,000円以内**に収める設計。
> 直近（2026）の伸びるフォーマット分析と、インプレッションで改善を回す仕組みも定義。
> 価格は変動するので必ず公式（[console.x.com](https://console.x.com)）で再確認すること。

## 0. 結論（先に要点）
1. **本文にURLを入れない**（=リーチが落ちる＋**URL投稿は$0.20/件**と高い）。リンクは**プロフィール／固定ポスト／（必要時のみ）リプ**に。これでAPI費が激減。
2. **X Premium に入る**（Web版が安い）。研究上、**インプレ約6倍**。これが最大の費用対効果。
3. **自動＝種まき（テキスト投稿）／計測＝毎日インプレ取得 → 週次で勝ち型に寄せる**。
4. 月コスト目安：**Premium ¥980（Web ~¥628）＋ API ~¥300 ≒ 月¥1,000〜1,300**（2,000円以内）。

## 2. 月2,000円に収める設計（コスト試算）
前提：1日2投稿（昼+夜、URLなしテキスト）＋毎日インプレ計測。
| 用途 | 計算 | 月額(目安) |
| --- | --- | --- |
| 投稿（URLなし）2/日 | 60 × $0.015 | $0.90（≒¥140） |
| インプレ計測（owned read） | 約40件/日 × 30 × $0.001 | $1.20（≒¥190） |
| URL投稿（任意・厳選） | 例 月4件 × $0.20 | $0.80（≒¥125） |
| **API小計** | | **≒ $2.90（¥455）** |
| **X Premium**（Web推奨） | Basic ~¥262 / Premium ~¥628 | ¥262〜980 |
| **合計** | | **≒ ¥720〜1,450/月** |

> 2投稿化してもAPIは月¥455前後で、`MONTHLY_COST_CAP_USD=12（≒¥1,900）` の範囲内。合計も2,000円以内を維持。

- **超過防止ガード**：スクリプトに「1日の投稿上限」「月間の概算コスト上限（既定 $12≒¥1,900）」を実装。上限超で投稿停止＋ログ。
- 一番の節約：**URL投稿をしない**（$0.20を避ける）。リンクはプロフィール固定で回収。

## 3. 直近（2026）の“伸びる型” 分析（マーケター）
出典の要旨（§末）。**質>量・会話・滞在時間**が軸。
1. **リプ至上主義（会話/質問型）**：リプがインプレ最大ドライバー。投稿は「会話の入口」。「みんなはどう？」で議論の余白を残す。**出した後30分のリプ返しが必須**。
2. **質 > 量**：1日5投稿より、**質の高い1〜2投稿**。本運用は昼=情報/診断導線・夜=会話/リプ型の**1日2本**に限定し、各本を作り込む（数打ちはしない）。
3. **記事(Articles)機能**：Premium長文。滞在時間で**インプレ激伸び**（直近の伸び筋）。→ Premium加入で解放。
4. **動画/Shorts**：dwell time。10〜30秒で最後まで見せる。
5. **言葉はシンプル**：専門用語は例え話に。スクロールでスッと入る。
6. **時間帯**：**夜20〜22時**が最良。
7. **リンクは本文に入れない**：reach減＋$0.20。プロフィール/固定/リプで。

→ ソラ先生の運用方針：**昼に“情報/診断導線”を1本、夜（20–22時）に“会話/共感/問いかけ”を1本（いずれもURLなし）→ 各投稿後30分のリプ返し**。診断導線は固定ポスト＆プロフィール。週1で Premium の Articles で「声タイプ図鑑」長文＝滞在時間狙い。

## 4. インプレで改善を回す仕組み（impression-driven）
- **毎日**：自分の直近投稿の **impressions / リプ / リポスト / いいね / ブックマーク** を取得（owned read $0.001）。
  - 取得：`GET /2/tweets?ids=...&tweet.fields=public_metrics,non_public_metrics`（非公開メトリクス=impression_countは本人投稿のみ取得可）。取得不可な場合は public_metrics（エンゲージ）で代替し、インプレはX標準アナリティクスで補完。
- **記録**：`metrics_log.jsonl`（tweet_id, pillar, impressions, eng, eng_rate, ts）。
- **週次レポ**：型(pillar)別に「平均インプレ／エンゲージ率」を集計し、**勝ち型を増やし負け型を削る**（`themes.py` の `PILLARS` 配分を寄せる）。
- 判断指標：**エンゲージ率 = (リプ+リポスト+いいね+ブックマーク) / インプレ**。リプ比率を特に重視（アルゴリズム的に効く）。

## 5. アーキテクチャ / モジュール
`scripts/sns_autopost/`（既存を拡張）
- `generate_and_post.py`：**URL自己リプを既定OFF**（`POST_LINK=1` の時だけ）。投稿後 `posts_log.jsonl` に {tweet_id, pillar, ts} を記録。**予算ガード**（`MAX_POSTS_PER_DAY`, 月間概算コスト上限）。
- `fetch_metrics.py`（新規）：`posts_log.jsonl` の直近N件のメトリクスを取得→`metrics_log.jsonl` に追記→**型別サマリを表示**。
- cron：昼(slot1)＋夜(slot2)に投稿各1本＝1日2本＋（別枠で）毎日メトリクス取得。
- 鍵は `.env`（X_* / DRY_RUN）。すべて従量。Premiumは別契約（コンシューマ側）。

## 6. 運用フロー（まとめ）
1. **X Premium 加入（Web）** → リーチ6倍の土台。
2. **API 従量**：開発者登録→支払い設定→キー発行（`docs/26`手順）。
3. `.env` に鍵＋`DRY_RUN=0`、`POST_LINK=0`（URL投稿しない）。
4. cron：昼12時 `--slot 1`＋夜21時 `--slot 2` の投稿2本（テキスト）＋ 毎日 `fetch_metrics.py`。`.env` は `MAX_POSTS_PER_DAY=2`。
5. 週1で型別インプレを見て `PILLARS` を勝ち型へ。リンク導線は固定ポスト/プロフィール。
6. **週次レポート**：分析→企画→報告を `docs/weekly/YYYY-MM-DD.md` に保存（[テンプレ](weekly/_template.md)）。毎週自動実行（`/schedule` クラウドルーティン）。

## 7. 正直なリスク・前提
- 価格は変わる。**URL投稿$0.20**が地雷 → 自動では原則しない（ガードでも抑止）。
- 非公開メトリクス（impressions）のAPI取得が制限される場合あり → public_metrics＋標準アナリティクスで代替。
- Premiumのリーチ倍率は調査値（保証ではない）。が、費用対効果は高い。
