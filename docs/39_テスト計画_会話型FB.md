# 会話型FB テスト計画

対象: [36_機能要件書_会話型FBリニューアル.md](36_機能要件書_会話型FBリニューアル.md) / [38_設計書_会話型FB.md](38_設計書_会話型FB.md)

## 1. スコープ
録音FBリニューアル（スコア・採点カード撤廃→会話チャット化）の品質保証。Web版（`backend/app/coaching`・`frontend`）と Claude Code版（`SKILL.md`）の双方。
対象外: 音声解析エンジン（`analyzer`/`voice_lab`）の精度、声タイプ診断（`/voice-type`）、課金。

## 2. 対象機能要件
FR-01 録音FBの会話文化 / FR-02 苦手検知時の練習1つ提案 / FR-03 参考動画の会話内リンク化 / FR-04 スコア・カード撤廃 / FR-05 Web版・skill版のトーン統一。

## 3. テスト観点
正常系 / 異常系（無音・非歌唱・同一音源・原曲取得失敗）/ 境界値（課題ありなしの分岐、ファイルサイズ）/ 状態遷移（初回診断→基礎練確認→歌い直し）/ 後方互換（過去カードを含む既存セッション）/ 性能（応答時間）。

## 4. テスト環境
- 自動: `backend/tests/test_conversational_fb.py`（DB/LLM不要・`_complete`無効化でテンプレ確定化）。実行: `cd backend && ./.venv/bin/python -m unittest tests.test_conversational_fb -v`。
- 手動（実機）: FastAPI + MySQL + Next dev + 認証済セッション。旧カードを含む既存セッションと新規セッションの両方を用意。

## 7. 合格基準
- 自動テスト 6/6 PASS（CI/手元）。
- 手動 TC-01〜TC-14 が期待結果どおり。特に TC-08（後方互換）と TC-09〜TC-12（異常系・事実忠実性）で破綻しないこと。
- 全経路で点数（NN/100, NN点）・◎○△×・指標の表が出力に現れない。

## 8. 既知の制限 / 申し送り
- 自動テストは `_complete` 無効化のテンプレ文ベース。実LLM応答の文量（2〜4文遵守）はプロンプト制約に依存し、TC-01/13 の手動確認で担保する（スポット検証では実LLMで2吹き出し・点数なしを確認済み）。
- TC-08〜TC-14 は実機（DB+認証）が必要なため自動化対象外。
