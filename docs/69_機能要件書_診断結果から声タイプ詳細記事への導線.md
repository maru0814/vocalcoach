# 診断結果カードから声タイプ詳細記事への導線 機能要件書

> **改訂 (2026-07-16)**: 経営者判断により要件を格上げ。当初の「詳細記事へのテキストリンク1本」から、
> **「診断完了後、結果カードの下に詳細プロフィール記事の全文をインライン表示する」**（MBTI/16personalities と同じ体験）に変更。
> FR-01 を全文表示に置き換え、リンク案は FR-03（補助導線）に降格。

## 1. 概要
- 声タイプ診断（`/voice-type`）の結果表示直後に、その声タイプの詳細プロフィール記事（`/voice-type/{typeId}` と同一コンテンツ、全8タイプ実装済み・PR#159）を**その場で全文表示**する。
- 現状、診断完了時は要約カード（スコア・似たアーティスト）のみで、タイプの性格・話し声などの読み物は別ページに行かないと読めない。MBTI診断のように「診断が終わった瞬間に自分の全プロフィールが読める」体験にし、診断直後の最も関心が高い瞬間を滞在時間・レッスン誘導につなげる。

## 2. 想定ユーザー / ユースケース
- ペルソナ: 診断を完走し、結果カードを見ているユーザー（ログイン済み・未ログイン両方）。
- US-01: ユーザーとして、診断結果を見た直後に「自分のタイプについてもっと知りたい」と思ったら、その場で詳細記事に飛びたい。なぜなら結果カードは要約（スコア・似たアーティスト）のみで、タイプの性格・話し声の傾向などは載っていないから。
- US-02: 検索エンジンとして、診断結果ページ（`/voice-type`、集客のハブ）から各詳細記事へのクロール経路を辿りたい。なぜなら詳細記事はSEOコンテンツ資産であり、内部リンクが被リンク評価・クロール発見性に寄与するから。

## 3. スコープ
### 3.1 対象（やること）
- ログイン済みユーザーの結果カード（`VoiceTypeBlock`表示部分、[frontend/src/app/voice-type/page.tsx:204-232](../frontend/src/app/voice-type/page.tsx)）に、詳細記事へのテキストリンクを1本追加する。
- 未ログイン（ぼかし表示）状態では追加しない（3.2参照）。

### 3.2 対象外（やらないこと）
- 未ログイン時のぼかしカードへのリンク追加（登録前に記事へ離脱されると「無料登録して結果を見る」の主導線が弱まるため対象外）。
- 「レッスンを受ける」ボタンの位置・優先順位の変更（プロダクト本体機能への導線を弱めない。詳細記事リンクは必ず二次導線）。
- `/voice-type/share/{id}`（Xシェア用OGPページ）側の変更。
- 詳細記事の中身の追記・修正（別要件）。

## 5. 機能要件

### FR-01: 診断完了後に詳細プロフィール記事を全文インライン表示
- 概要: ログイン済みユーザーの診断結果表示に、そのタイプの詳細プロフィール記事（導入・本文全セクション・有名人ラインナップ）を結果カードの下に全文表示する。
- 詳細仕様:
  - コンテンツソース: `frontend/src/content/voiceProfiles`（`VOICE_PROFILES[typeId]`）。詳細記事ページ `/voice-type/[typeId]` と**同一コンポーネントを共有**し、二重管理しない。
  - 表示位置: 結果カード（`VoiceTypeBlock`＋`ShareButtons`）とアクションボタン列（「もう一度診断」「レッスンを受ける」）の**下**。診断のコア動作（結果確認・シェア・レッスン誘導）を先に見せ、その下に読み物が続く。
  - 表示範囲: 記事の導入（lede）・目次・本文セクション・有名人ラインナップ。詳細ページ側のヒーロー画像・診断CTA・他タイプグリッドは重複するため表示しない（結果カードがヒーロー相当のため）。
- 入出力: `result.voice_type.id` を使用。プロフィール本文は約300KB（有名人SVG含む）のため、初期バンドルに含めず**診断結果表示後に動的import**する。
  - 読み込みは `result` を起点とする（`runAnalyze` 内ではない）。docs/67 のブリッジ復元（未登録→登録→フル結果）でも `result` が入るため、そこでも記事が出る必要があるため。
- 例外ケース:
  - `VOICE_PROFILES[typeId]` が未定義（準備中タイプ）→ 記事部分は非表示（結果カードのみ。エラーは出さない）。
  - 動的importの読み込み失敗 → 記事部分は非表示（診断結果自体は影響を受けない）。

### FR-02: 未ログイン時は対象外のまま
- 概要: 未ログイン（ぼかしカード表示、[frontend/src/app/voice-type/page.tsx:237-259](../frontend/src/app/voice-type/page.tsx)）には記事を表示しない。
- 詳細仕様: 既存の「無料登録して結果を見る」CTAのみを維持。記事全文は登録後のリワードとして温存する。

### FR-03: 詳細記事単独ページへの補助リンク
- 概要: インライン記事の末尾に、単独ページ `/voice-type/{typeId}` へのテキストリンクを置く（あとで読み返す・URLを共有する用途）。
- 詳細仕様: 「レッスンを受ける」より視覚的に弱いテキストリンクとする。

### FR-04: 診断完了時に結果カードへ自動スクロール
- 概要: 診断が完了して結果が表示された瞬間、結果カードが画面上部に来るよう自動スクロールする。
- 背景: 現状は自動スクロールが無く（`scrollIntoView`/`scrollTo` ともにコード内に存在しない）、記事見出しはスマホ幅で Y=1218px＝1画面（812px）の外。ユーザーが結果と記事に気づかないまま離脱しうる。
- 詳細仕様:
  - 発火条件: `result` がセットされ、かつ `auth === "in"` になったとき。
  - 対象: 結果セクションの先頭（結果カードの上端）。
  - `prefers-reduced-motion: reduce` の場合はスムーススクロールを使わず即時移動する。
- 例外ケース: 未ログイン（ぼかし表示）の場合もスクロールする（結果が出たこと自体は伝えるべきため）。

### FR-05: 記事へ誘導するアンカー
- 概要: 結果カードの直下に「↓ {タイプ名}のプロフィールを読む」というアンカーを置き、記事の存在を明示してその位置までスクロールさせる。
- 詳細仕様:
  - 表示条件: 記事（`profile`）が読み込めたログイン済みユーザーのみ。
  - 動作: クリックで記事見出しまでスクロール（ページ内アンカー）。
  - トーン: 「レッスンを受ける」より弱いテキストリンク。ただし下向き矢印で「下に続きがある」ことを示す。

### FR-06: 読了後にレッスンへ誘導する締めCTA
- 概要: インライン記事の末尾（有名人ラインナップの後）に、レッスン（`/coach`）へ誘導するCTAブロックを置く。記事を読み終えて自分の声への理解が最高潮にある瞬間を、レッスン開始につなげる。
- 詳細仕様:
  - 表示条件: ログイン済み・記事が表示されている場合のみ。
  - 内容: タイプ名を織り込んだ見出し＋本文＋`/coach` への主要ボタン。
  - **コピーの誠実性（制約）**: レッスンの実体は「曲を選んで歌う → ソラ先生がフィードバックを返す」（`/coach` の既存コピー準拠）。それを超える約束（上達保証・具体的な期間など）を書かない。料金の主張もしない（課金仕様は docs/32・52 の管轄で、ここでは触れない）。
  - 単独記事ページ（`/voice-type/{typeId}`）側の既存「診断CTA」は変更しない（あちらは未診断の検索流入向けで、診断CTAが正しいため）。
- 例外ケース: 記事が無い（準備中タイプ）場合は締めCTAも出さない（既存の「レッスンを受ける」ボタンが残るため導線は途切れない）。

## 6. 非機能要件
- 性能: プロフィール本文（約300KB）は動的importで遅延読み込みし、診断ページの初期表示を悪化させない。
- 保守性: 記事描画は詳細ページと共有コンポーネント化し、本文の修正が両方に自動反映される構造にする。
- SEO: 詳細ページ `/voice-type/[typeId]` の静的生成（`generateStaticParams`）・メタデータは本変更で壊さない。

## 7. 受け入れ基準
- AC-01: ログイン済みユーザーが診断を完走すると、結果カード・アクションボタンの下に、診断されたタイプの詳細記事（導入・全セクション・有名人）が全文表示される。
- AC-02: インライン表示される記事の内容が `/voice-type/{診断結果のtypeId}` 単独ページの本文と一致する（同一コンポーネント）。
- AC-03: 未ログイン状態のぼかしカードには記事が表示されない（既存の登録導線のみ）。
- AC-04: 「レッスンを受ける」「もう一度診断」ボタンの視覚的優先度（サイズ・色）が本変更前後で変わらない。
- AC-05: 8タイプすべて（rock/groovy/pop/mysterious/crystal/dramatic/whisper/moody）で診断結果に対応する正しい記事が表示される。
- AC-06: 詳細ページ `/voice-type/{typeId}` 全8件が本変更後もビルド・表示できる（共有コンポーネント化のリグレッションなし）。
- AC-07: 結果カードのXシェア画像（html2canvas）に記事部分・アンカー・締めCTAが写り込まない。
- AC-08: 診断完了時、ユーザーの操作なしに結果カードが画面内（上部）に入る（FR-04）。
- AC-09: 結果カード直下のアンカーをクリックすると記事見出しまでスクロールする（FR-05）。
- AC-10: 記事の末尾（有名人の後）にレッスンへのCTAが表示され、`/coach` に遷移する（FR-06）。
- AC-11: 締めCTAの本文が、レッスンの実体（歌う→ソラ先生がFB）を超える約束・料金の主張を含まない（FR-06 コピー制約）。

## 8. 前提・制約
- 詳細記事ページ（`/voice-type/{typeId}`）は全8タイプ実装済み（PR#159、本番稼働確認済み）。
- 診断結果オブジェクト（`VoiceTypeResult`型）に`voice_type.id`が含まれていることは`frontend/src/lib/api.ts`で既存確認済み。

## 9. 未決事項 / 要確認
- リンクの正確な文言・配置・視覚トーン → **designerに依頼**。
- 結果カードのスクリーンショット（Xシェア画像化・`html2canvas`）に、追加するリンクが写り込むかどうか → デザイナー仕様で「シェア画像には含めない（`shareRef`のDOM範囲外に置く）」ことを明記してもらう必要あり。
